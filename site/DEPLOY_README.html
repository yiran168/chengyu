CHAPTER 01

澄屿 Chengyu 0.19.0

独立 PHP 内容、社区与数字资源平台，包含前台和可管理的后台。不需要 WordPress、运行期 Composer、Node、Redis 或常驻队列。PHP 7.4–8.5 使用同一套业务代码，支持原生 PDO MySQL / SQLite。

本版新增资源多版本与私有镜像、失效反馈闭环、组合筛选、22 种可视化区块、响应式轮播与按钮组，以及原创二次元站标和海岛插画。修复 Windows 安装 Cookie 路径、长文本分片上传类型识别、SKU 标价排序和布局布尔值校验问题。

保留文章/社区/圈子/问答/投票、会员、积分与余额、SKU 与卡密、实物订单、访客结算、售后退款、作者收益、课程、工单、私信、搜索、分片上传、快照恢复及后台动效实验室。功能的具体边界见 功能矩阵，没有把未实现的第三方接口标成可用。

新站安装

  1. 解压完整包或 upload.zip，在自己的电脑打开 DEPLOY_PREPARE.html，生成本站独立口令，保存 key.php 和私密 INSTALL_KEY.txt。
  2. 上传 site/ 内的全部文件，或直接解压 upload.zip 到网站根目录；保留隐藏的 .htaccess 和 web.config。
  3. 将生成的 key.php 上传，覆盖网站的 install/key.php。私密 INSTALL_KEY.txt 留在本地，绝不上传。
  4. 准备空 MySQL 数据库，打开 /install/，填写数据库、口令与自己的管理员账号。SQLite 数据库必须在网站公开目录外。
  5. 安装成功后访问 /admin/，核对站点配置并删除服务器 install 目录。

公开包不含通用安装密码或默认管理员。无面板新 VPS 也可使用 部署脚本，脚本会生成该站点的独立安装口令；已有面板使用面板创建 PHP 站点。

已有 0.18 站点按 升级说明 保留 config.php、原 secret、数据库和 storage，升级至结构 v11，不重新安装。

部署与验证

最低环境：64 位 PHP 7.4–8.5、PDO MySQL 或 SQLite、OpenSSL、Fileinfo、可写存储。MySQL 需要 InnoDB、utf8mb4 和建表/索引权限；网上收款与外部服务需要 HTTPS 及主机允许的出站网络。

PHP 七版本本地原生 SQLite 测试、Linux 原生 MySQL/SQLite 的 14 组 CI 和真实 HTTP 测试分别保存证据，详见 测试报告。免费主机的具体实例和 VPS 装机尚未实测，不能将语言兼容测试等同于服务商所有套餐均可用。

CHAPTER 02

安装与部署

核查日期：2026-09-08。项目版本：0.19.0。本文描述部署步骤，不代表已登录蓝队云、萌哒云或在真实 VPS 执行过部署。

一、免费虚拟主机：推荐 MySQL 安装

1. 在面板准备

绑定自己的域名，选 PHP 而不是 ASP。建立一个空数据库并记录数据库主机地址、端口、名称、用户名、密码。数据库名称前缀以主机面板实际值为准，不是自行填写一个不存在的名称。 启用 HTTPS，并确认浏览器能正常访问，不出现证书警告。本站的支付网关回调必须能从公网访问。

程序面向 64 位 PHP 7.4–8.5，所有版本使用相同功能；检查 pdo_mysql、OpenSSL、Fileinfo。上线仍建议使用获得安全维护的运行时，而不是把兼容旧语法等同于旧运行时安全。安装器会检测运行时、PDO 驱动和基本写权限，但不等于完整安全审计，也不能提前验证真实支付回调。 蓝队云官方免费主机说明为 Windows 环境、FTP 上传 wwwroot、无 SSH 和单独环境更换；未明确本套餐 PHP 小版本和 PDO 扩展。萌哒云“免费1”本轮未取得可独立确认的当前官方配置页，不能继续把 PHP 8.2 写成已确认。两者均须以实际面板、安装检测和工单为准；代码不能替主机安装扩展或解除磁盘/网络限额。见 HOSTS_AND_SOURCES.md。

2. 上传

推荐使用单独的上传 ZIP，在网站根目录解压。或者在本地解压完整包，仅上传 site/ 内全部内容，含隐藏文件。根目录应当直接看到：

index.php
action.php
notify.php
notify-direct.php
jobs.php
oauth.php
media.php
admin/index.php
install/index.php
app/
assets/
storage/
.htaccess
web.config

不能公开完整交付 ZIP、INSTALL_KEY.txt、数据库导出、备份、tests、docs、deploy。 不要覆盖原网站；先备份旧站，使用空站点目录和空数据库。此安装器不会迁移 WordPress 数据，也不提供一键导入旧主题。

Apache / LiteSpeed 需要正确处理随包 .htaccess。Nginx 不读取 .htaccess，须在面板添加 deploy/nginx.conf.example 中的目录保护规则。IIS 附带 web.config，但未实测；由主机确认配置功能允许、目录浏览关闭且敏感目录不可访问。不要删除防护文件来绕过错误。

3. 运行向导

打开 /install/，例如：

https://example.com/install/

填写站点名称、规范网址、安装口令、MySQL 信息和管理员账号。先在电脑打开包内 DEPLOY_PREPARE.html，生成本站独立口令；上传生成的 key.php 覆盖服务器 install/key.php。口令保存在刚生成的私密 INSTALL_KEY.txt 中，公开包本身不含通用口令。它用于避免未安装站点被抢先初始化，不是管理员密码。 管理员用户名为 3–32 位小写英文字母、数字、下划线，字母开头。密码为 12–72 字节、必须含字母和数字。 可选择安装原创示例内容和套餐；公开运营前必须检查价格和内容。

安装器创建数据表和配置文件，但不创建 MySQL 数据库或数据库用户。站点网址必须与当前安装目录一致，不能填带查询参数、片段或其他路径的网址。 向导成功后登录 /admin。实体目录入口不依赖 WordPress 伪静态。

4. 权限与收尾

app/ 安装期间要能由 PHP 写入，以创建 app/config.php；安装后除配置变更或升级外不应继续允许 PHP 修改应用代码。 storage/ 要允许 PHP 创建媒体文件和日志。不要用全站 777 解决权限问题。共享主机文件所有者模型不同，使用主机提供的权限管理。 app/config.php 自动设置为仅所属用户可读写；不要改为可公开下载的扩展名。 安装完成且确认能登录后，删除 install/。

用未登录浏览器实际请求下面的路径，必须被拒绝或返回无敏感内容的 404，不能显示目录、源码或 JSON 种子数据：

/app/seed.json
/app/config.php
/storage/
/uploads/
/.htaccess

测试安装器的 PDO 检测与这些 HTTP 路径保护是两个不同的事项，都需要验证。

5. 首次后台设置

站点身份与联系方式、服务条款、隐私与退款说明 → 外观与布局 → 用户与评论审核 → 内容 / 会员套餐 → 交易与支付 → SMTP。 蓝队云用户在「站点设置」中设置「主机鸣谢文字」和「主机鸣谢链接」，遵守该套餐页面的页脚链接规则。不要自行删掉主机要求的标识。 后台系统页能查看 PHP、数据库类型、上传限制、存储写入状态和 HTTPS 网址配置；不能控制主机面板或安装证书。

二、已有面板的 VPS

用现有面板创建 PHP 站点、绑定域名和证书、建立数据库，再按上述安装。不要运行新 VPS 脚本覆盖面板服务。 Nginx 的私有路径拒绝规则优先于 PHP 匹配，参见模板；PHP-FPM socket 按面板实际值修改。本站无需通用 try_files ... /index.php 前端控制器重写。 面板开启强制 HTTPS 后再把安装网址设为 HTTPS。已经安装的站点换域名或 HTTP 切 HTTPS，备份后修改 app/config.php 的 url，保留 secret 与数据库信息，不要重新安装。 反向代理必须只信任自己控制的代理，并正确传递 HTTPS 状态。不要为了消除登录问题全局信任任意客户端伪造的代理头。

三、全新、无面板 VPS

deploy/install-vps.sh 面向全新 Debian 12+ / Ubuntu 24.04+、root 权限和 systemd 主机。本次只检查了 Bash 语法，没有实际安装系统包或取得证书。 先阅读脚本。它会安装发行版 Caddy、PHP-FPM、PDO 驱动，创建 /var/www/chengyu，写入 Caddy 配置；会拒绝目标目录已存在、常见面板或已运行 Web 服务的环境。它不修改云防火墙、不为你设置 DNS、不卸载现有服务。

把完整包上传到非 Web 公开目录解压后：

cd chengyu
sudo bash deploy/install-vps.sh example.com

将 example.com 换成自己的域名；按提示输入 INSTALL。先使域名 A/AAAA 指向该 VPS，允许公网 TCP 80/443，保证 Caddy 能绑定端口并持续保存证书数据。删除指向错误服务器的 AAAA 记录，而不是反复申请证书。 完成后浏览器进入 /install/，选 SQLite，填 /var/www/chengyu/private/chengyu.sqlite。私有口令保留在 /var/www/chengyu/INSTALL_KEY.txt，可用 root 读取。也可自行配置 MySQL，脚本没有安装 MySQL 服务器。 Caddy 的公开域名 HTTPS 申请和续期由 Caddy 管理；不是 PHP 后台调用 ACME。网关服务、DNS 和防火墙必须正常，否则不会凭空获得可用证书。

验证后，在该脚本部署的特定路径下执行：

sudo rm -r /var/www/chengyu/site/install
sudo chown root:www-data /var/www/chengyu/site/app
sudo chmod 0750 /var/www/chengyu/site/app

这些命令只适用于本脚本创建的路径。不要照搬到不确定的生产路径，不要删除私有数据库或存储。config.php 仍需 PHP 用户能读，媒体存储仍需可写。 运行日志使用 journalctl -u caddy、journalctl -u php8.3-fpm 等，PHP 服务名按实际安装版本替换。

四、IP、端口、子目录

根目录部署时 /admin 和 /admin/ 都由 Web 服务器的实体目录入口处理；带端口可以使用 http://IP:端口/admin/ 进行隔离环境初测。正式登录与充值应使用有效 HTTPS，HTTP 模式无法创建本站在线充值单。 不能保证主机共享 IP 能直接访问你的虚拟站点，这由面板的站点绑定决定。

子目录部署时后台是 /子目录/admin/，而不是域名根目录 /admin。要严格满足根目录加 /admin，就把网站放在该域名的文档根目录。Nginx 私有目录规则也要加子目录前缀。本次自动化测试以根目录部署为主，没有完整覆盖所有子目录 / 代理组合。

五、常见问题

现象 排查方向

六、升级与迁移

0.14.0 按序提供从 0.9.0–0.13.0 到结构 v6 的增量、可重试迁移，详见 UPGRADE.md。没有在线热更新或自动降级回滚，不支持 WordPress 数据库直接导入。 迁移需要数据库、app/config.php（尤其 secret）、整个 storage 一致备份。域名或绝对存储路径变化后修改配置对应项，检查回调地址和邮件链接，并再次做验收。完整备份不能用用户 / 订单 CSV 导出来代替。

七、新增模块上线顺序

升级或安装后先检查「模块」中的问答/投票开关，在测试版块发布试帖并用两个普通账号验证权限与结果隐私。后台「动效工作台」可先在本地预览，保存后用另一个浏览器检查默认效果；页面不会因关闭动画而失去付款或下载功能。

SMTP 先配置、实际收发成功，再开启必填邮箱验证，避免把真实访客挡在注册入口。详见 EMAIL_COMMUNITY.md。需要普通不验证注册时保持该可选开关关闭，所有 PHP 版本遵循同一设置，不是低版本精简模块。

部署完成不要求开放 SSH、FFI、Python、Node 或测试端口。测试目录仅留本地。安装器只检查基础运行环境，不表示服务器的网络、数据库性能与所有业务已验收。

八、安全、定价与主机自检

首次上线先到“系统”运行部署自检，确认真实环境的原生 PDO、回滚、加密与写权限。下载报告便于维护，但报告不含公网敏感路径访问检查，不得跳过真实 URL 验收。

准备好离线恢复码再给管理员启用身份验证器，确认服务器时钟正确。SMTP 密码找回不会移除身份验证器；没有命令权限的免费主机尤其需要事前保管恢复码。完整包的本地恢复脚本不得公开上传。

先用测试账户/测试商品设置会员价和活动，核对 0/8000/10000 比例含义、单件最高确认额和按成交价退款，再开放促销。详情见 SECURITY_PRICING.md。旧站没有价格规则时不会因升级自动出现优惠。

CHAPTER 03

从 0.18.0 升级到 0.19.0

本轮基线是用户提供的 0.18.0 完整代码，数据库结构从 v10 到 v11。config.php 中的 schema_version: 1 是配置格式，保留为 1。此程序不导入 WordPress 数据。

  1. 暂停写入、收款和任务调度，备份同一时点的数据库、旧代码、app/config.php、原 secret、全部 storage 与服务器规则。先在隔离环境验证备份可恢复。
  2. 覆盖上传包中的应用文件与 assets，保留原 config.php 和 storage。旧站不上传 install，不使用新站口令生成器重新安装。
  3. 清理 OPcache、CDN 和浏览器缓存。首次请求按顺序迁移至 v11，需要数据库建表和索引权限；不要手动修改版本号跳过失败。
  4. 检查文章、登录、订单、媒体与后台。按 PLATFORM_019.md 设置外观和资源版本，再恢复写入和受认证的调度。

新增 cy_resource_files、cy_resource_reports、cy_resource_downloads 三张表。资源版本保存来源、加密镜像/提取码与修订号，反馈与下载记录分别保存；原内容 resource_id、订单和媒体数据不搬迁、不重算余额。三张新表纳入加密快照。

布局文档仍使用 version:1；旧文档缺少的新字段会在验证时填入兼容默认值。旧发布历史保留。外观默认采用新排版与二次元站标，可在外观设置切换经典排版、抽象封面和文字站标；已有自定义内容与封面保留。

0.18 的加密备份先使用匹配的 0.18 工具恢复，再升级；0.19 备份使用匹配的 0.19 代码与相同数据库引擎恢复。不要把新版恢复工具当作任意版本转换器。

回滚需要停写并恢复同一时点的旧代码、配置、数据库与存储，不能仅覆盖旧 PHP 文件。回滚数据库不会撤销真实商户付款、退款、邮件或已发包裹。更早版本有顺序迁移代码，但不代表所有历史生产库都已演练。

CHAPTER 08

PHP 与部署兼容性

0.19.0 使用同一套 64 位 PHP 7.4–8.5 代码，功能不按小版本裁剪。需要原生 PDO MySQL 或 SQLite、OpenSSL、Fileinfo，以及可写的私有存储。默认不依赖 curl、mbstring、FFI、Composer、Node、Redis 或常驻服务。

本地实际执行 PHP 7.4.33 / 8.0.30 / 8.1.34 / 8.2.33 / 8.3.33 / 8.4.25 / 8.5.10，全部使用原生 pdo_sqlite。Linux CI 为七个 PHP 小版本各运行原生 MySQL 8.0 与 SQLite 两组，共 14 组；准确提交、数量与状态见 TEST_REPORT.md，不把旧报告计入最新改动的通过数。

Windows 安装网址路径已改用专用 WebPath，避免 dirname() 产生反斜杠 Cookie 路径；媒体签名探测有固定字节边界，避免 Windows Fileinfo 将大重复文本误判为二进制。兼容 7.4 不代表旧 PHP 运行时本身仍有官方安全维护。

CHAPTER 30

加密数据库、本地媒体与离线恢复

**先在隔离环境完成一次恢复演练，再依赖备份。**这是0.19小站的手动一致性快照，不是跨机灾备、热备、高可用或自动覆盖正在运行的网站。

备份包含什么

归档包含当前支持的80张数据表的记录、应用/数据库版本、原站点URL和用于解密旧数据的原始站点 secret。账户、密码哈希、订单、余额、付费权限、卡密、设置中的加密凭据等都属于敏感数据。可选包含已经完成的本地媒体封装文件。

排除备份目录本身、限流、密码重置/邮箱挑战、未完成上传任务与分片。也不包含程序源码、数据库连接密码、服务器配置、TLS证书、PHP会话文件、S3/R2远程对象实际字节。远程对象仅有数据库指向信息；云桶需要独立备份。数据库专用触发器、视图或用户另装插件表不在这个固定应用格式内。

请同时保存匹配版本源码、服务器规则和目标数据库配置。数据库类型必须匹配：MySQL归档恢复到MySQL，SQLite恢复到SQLite，不作跨引擎转换。

后台创建与下载

进入后台“恢复副本”，输入单独的16–256字节备份密码、再次输入确认，选择是否含本地媒体，再提供当前管理员密码与已启用的TOTP/恢复码。确认归档包含敏感数据后创建。下载和删除也要求当前凭据复验，不能仅凭登录Cookie执行。

归档使用PBKDF2-SHA256派生独立密钥和逐记录AES-256-GCM认证加密；每条记录绑定序号、前一记录认证标记与头部，末尾清单用于检测截断、乱序或追加。解析只接受已知表名和严格的本地文件键，不执行归档里的SQL、PHP或序列化对象。

服务器文件使用随机名称、PHP停止执行封装与私有目录权限；下载移除封装，扩展名为 .cybackup。下载前检查目录记录的SHA-256。将归档移出服务器，密码放在另一安全位置。文件和密码同时丢失无法恢复；不得放进源码仓库或普通邮件。

默认归档上限64MiB、保留最近3份成功副本；可在安全设置调到8–512MiB、1–10份。创建请求有最多约20秒的安全预算，并提前考虑主机执行时间；大站、慢主机或大媒体请用主机/数据库备份工具，不反复提高超时硬撑。只读一致性事务会持有快照，操作时尽量停写。

失败不生成成功目录记录，并清理正常异常路径的临时文件；进程被强杀可能留下保护封装文件，需要管理员核对目录后清理。损坏副本下载校验失败时不要删除最后一份其他完好副本。当前界面删除同样要求文件可验证，严重损坏的孤立文件通过主机文件管理核对后移除。

离线检查

将完整包解压到本地可信环境或隔离VPS。工具只接受CLI，不能通过浏览器运行，tools/ 不放到网站公开目录。下例应用目录为 /srv/chengyu/site，没有连接生产站点：

php /srv/chengyu/tools/recover-backup.php inspect /srv/chengyu/site /private/copy.cybackup

工具从标准输入读取备份密码，不把密码写进命令参数或历史记录。普通终端可能回显输入；类Unix终端可使用关闭回显的方法：

old=$(stty -g) || exit 1
trap 'stty "$old"' EXIT HUP INT TERM
stty -echo
php /srv/chengyu/tools/recover-backup.php inspect /srv/chengyu/site /private/copy.cybackup
stty "$old"
trap - EXIT HUP INT TERM

随后输入备份密码并回车。不要把密码作为工具第三/第四参数。自动化输入只能来自权限严格的私有文件或秘密管理器，完成后按你的密钥制度销毁。Windows终端可使用私有标准输入文件；不要套用 stty。

检查输出只包含版本、数据库类型、记录/文件数等摘要，不输出原密钥和私密记录。错误密码、认证标签变化、路径穿越或不完整末尾会直接拒绝。

恢复到空目标

准备同类型空数据库，创建一个仅在本地可信目录的PHP连接文件，例如 /private/target-database.php：

<?php
return [
    'driver' => 'mysql',
    'host' => '127.0.0.1',
    'port' => 3306,
    'name' => 'chengyu_rehearsal',
    'user' => 'rehearsal_user',
    'password' => 'REPLACE_WITH_TARGET_DATABASE_PASSWORD',
];

SQLite用 ['driver'=>'sqlite','path'=>'/private/new-site.sqlite']。该PHP文件由你本地编写，不来自陌生上传，因为工具会读取执行它。恢复存储目录与输出配置文件必须尚不存在，而它们的父目录必须存在。

php /srv/chengyu/tools/recover-backup.php restore /srv/chengyu/site /private/copy.cybackup /private/target-database.php /srv/restored-storage /private/recovered-config.php CONFIRM-EMPTY-TARGET

使用上节相同的标准输入方式输入密码。工具先完整验证归档，再检测空库，从当前可信代码建立结构、事务写入数据、逐片恢复并核对媒体，最后生成新的私有配置。已有任何数据表会拒绝。MySQL DDL不能全部回滚；失败可能留下空表或未发布目标数据，重新演练应换一个干净目标，不能把半恢复站点直接上线。

工具输出配置保留旧 secret，使用你指定的新数据库与存储。将恢复代码、配置与目录放到隔离站点后确认路径，谨慎把配置移为 app/config.php。恢复后的维护模式/任务暂停及远端开关必须保持，直到核对完成。

恢复后必须核对

旧账户/TOTP、余额与流水、订单和待退款/代付状态、卡密可解密、原付费权限、本地媒体校验、S3桶访问和原站点URL都要检查。所有旧会话已撤销，需重新登录。数据库只恢复到快照时刻，不会撤销快照之后真实发生的商户退款、提现、发货、邮件或下载。

外部支付/邮件/身份连接等开关会关闭，计划任务被 recovery_hold 拦截，调度密钥清空。手工重配真实服务前，在商户侧核对待处理单；检查结束后才重新生成调度凭据、恢复服务、关闭维护与任务暂停。不要盲目重试所有历史任务。

仅数据库归档不会还原本地媒体字节，需另行恢复原始 storage/blobs。完整媒体归档在缺少已登记本地文件时会失败，而不是静默漏文件。远程存储不在归档内，仍需原桶或独立恢复。

免费主机没有SSH怎么办

创建和下载小型归档在后台完成，不要求SSH、Composer或ZipArchive。本版恢复工具没有网页执行入口，不能宣传为免费主机一键整站在线恢复。

可在本地/隔离VPS的相同数据库环境验证归档并恢复，然后用该环境的数据库管理工具导出，再通过主机数据库面板导入；通过FTP传回恢复媒体与配置。蓝队云官方说明数据库只支持面板管理、不支持外部远程连接，不能假设本地CLI可直连它的数据库。真实数据迁移前仍优先采用主机的原生整站备份与还原。

程序从不为PHP7.4关闭备份或为8.5另开一套功能；实际能力取决于扩展、数据库权限、内存、执行时间和磁盘。原生MySQL/PDO与真实主机恢复尚待你按验收清单演练。

CHAPTER 31

0.19 · 资源版本、模块编排与二次元界面

本版是独立 PHP 程序，数据库结构 v11。旧功能继续沿用同一套账户、权限、账目、媒体、备份和通知服务。

资源版本与镜像

后台「内容创作 → 资源版本」选择文章或数字商品，填写版本名称、版本号、更新说明。每条版本选择一个私有文件或一个 HTTPS 网盘地址，可以填写提取码、排序、启用状态。每篇内容最多 40 条。

上传私有附件后使用媒体 ID；网盘地址和提取码加密保存。已解锁内容的用户看到版本列表，点击后才进入下载或镜像中转页。访客购买沿用订单通行证；退款、内容到期、停用版本会在下一次请求重新核对权限。文件仍走统一受保护媒体出口，不公开存储路径。

会员下载额度同时统计私有文件和镜像，每个资源每天重复访问只计一次，HEAD 请求不消耗额度。共享的文件通过其他合法内容获得权限时，仍能按原权限访问。

登录会员可以报告链接不可用、版本过旧或文件不符。后台处理时填写说明，用户收到站内通知。重复提交不会重复新建待处理单，处理使用修订号，防止多人覆盖；平台无法自动确认所有第三方网盘的内容真实性。

可组合页面

布局工作台目前有 22 个插入位置、22 种区块：标题、文字、内容列表、专题、行动按钮、真实统计、友情链接、间距、横幅、FAQ、媒体、亮点卡片、标签页、图片画廊、时间线、分类卡片、会员卡片、标题列表、公告、创作者卡片、响应式轮播、按钮组。

新条目类区块支持最多 12 个条目，编辑文字、图标、链接、图片 ID、顺序；卡片可选 1–4 列。背景和站标只允许公开图片，私有附件不会因为被填入装饰字段而泄漏。标签页支持键盘左右键、Home/End，无 JavaScript 时全部内容按顺序显示。

轮播支持桌面/手机两张公开图片、3–20 秒间隔、上/下一张与暂停；自动播放默认关闭，开启后在悬停、焦点、隐藏页、移出视口或减少动画时暂停。无 JavaScript 仍可横向滚动。

工作台提供内容型、资源型、社区型、创作者型、产品型模板；可保存草稿、发布、导入导出和恢复最近 20 次发布。所有导入内容在服务器再次校验，不执行用户填写的 PHP、JS 或任意模板。

检索与排版

文章和资源页可组合权限、标签、时间、交付方式、币种、标价、库存筛选。标价排序使用实际可售 SKU 的最低标价，排序链接保留筛选条件，空价格与零价格区分。积分等整数资产不能填小数；不跨币种比较数字大小。会员优惠与促销另按结算规则计算。

前台支持网格和列表视图，偏好保存在本机。外观设置提供均衡/宽屏/阅读宽度、澄屿新刊/经典布局、原创二次元/抽象默认封面。编辑文章时可以使用自己上传的封面。

原创猫耳海岛信使站标用于导航栏、页脚、后台；可切换文字标或填写公开站标图片 ID。浏览器图标随包本地加载。站标、海边书房、蓝调海港插画来自本轮生成，出处见 ARTWORK.md。

动效沿用统一贝塞尔曲线与弹簧引擎；新增卡片抬升、封面缩放、标签页切换、站标轻摆，遵守系统减少动态效果、全站开关和零时长设置。装饰不是交易成功的依据，提交仍以服务器响应为准。

安装与升级

公开包不再共享可用安装口令。新站先用包内 DEPLOY_PREPARE.html 在浏览器本地生成密钥，将 key.php 上传到 install/key.php。无面板 VPS 脚本自动调用 CLI 为该站点生成独立口令。旧站升级保留配置、密钥、数据库和存储，无需重装。
