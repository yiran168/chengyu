新站安装

  1. 解压完整包或 upload.zip，在自己的电脑打开 DEPLOY_PREPARE.html，生成本站独立口令，保存 key.php 和私密 INSTALL_KEY.txt。
  2. 上传 site/ 内的全部文件，或直接解压 upload.zip 到网站根目录；保留隐藏的 .htaccess 和 web.config。
  3. 将生成的 key.php 上传，覆盖网站的 install/key.php。私密 INSTALL_KEY.txt 留在本地，绝不上传。
  4. 准备空 MySQL 数据库，打开 /install/，填写数据库、口令与自己的管理员账号。SQLite 数据库必须在网站公开目录外。
  5. 安装成功后访问 /admin/，核对站点配置并删除服务器 install 目录。

公开包不含通用安装密码或默认管理员。无面板新 VPS 也可使用 部署脚本，脚本会生成该站点的独立安装口令；已有面板使用面板创建 PHP 站点。

已有 0.18 / 0.19 站点按 升级说明 保留 config.php、原 secret、数据库和 storage，升级至结构 v12，不重新安装。

安装与部署

核查日期：2026-09-08。项目版本：0.19.0。本文描述部署步骤，不代表已登录蓝队云、萌哒云或在真实 VPS 执行过部署。

一、免费虚拟主机：推荐 MySQL 安装

1. 在面板准备

绑定自己的域名，选 PHP 而不是 ASP。建立一个空数据库并记录数据库主机地址、端口、名称、用户名、密码。数据库名称前缀以主机面板实际值为准，不是自行填写一个不存在的名称。 启用 HTTPS，并确认浏览器能正常访问，不出现证书警告。本站的支付网关回调必须能从公网访问。

程序面向 64 位 PHP 7.4–8.5，所有版本使用相同功能；检查 pdo_mysql、OpenSSL、Fileinfo。上线仍建议使用获得安全维护的运行时，而不是把兼容旧语法等同于旧运行时安全。安装器会检测运行时、PDO 驱动和基本写权限，但不等于完整安全审计，也不能提前验证真实支付回调。 蓝队云官方免费主机说明为 Windows 环境、FTP 上传 wwwroot、无 SSH 和单独环境更换；未明确本套餐 PHP 小版本和 PDO 扩展。萌哒云“免费1”本轮未取得可独立确认的当前官方配置页，不能继续把 PHP 8.2 写成已确认。两者均须以实际面板、安装检测和工单为准；代码不能替主机安装扩展或解除磁盘/网络限额。见 HOSTS_AND_SOURCES.md。

2. 上传

推荐使用单独的上传 ZIP，在网站根目录解压。或者在本地解压完整包，仅上传 site/ 内全部内容，含隐藏文件。根目录应当直接看到：

index.php
action.php
notify.php
notify-direct.php
jobs.php
oauth.php
media.php
admin/index.php
install/index.php
app/
assets/
storage/
.htaccess
web.config

不能公开完整交付 ZIP、INSTALL_KEY.txt、数据库导出、备份、tests、docs、deploy。 不要覆盖原网站；先备份旧站，使用空站点目录和空数据库。此安装器不会迁移 WordPress 数据，也不提供一键导入旧主题。

Apache / LiteSpeed 需要正确处理随包 .htaccess。Nginx 不读取 .htaccess，须在面板添加 deploy/nginx.conf.example 中的目录保护规则。IIS 附带 web.config，但未实测；由主机确认配置功能允许、目录浏览关闭且敏感目录不可访问。不要删除防护文件来绕过错误。

3. 运行向导

打开 /install/，例如：

https://example.com/install/

填写站点名称、规范网址、安装口令、MySQL 信息和管理员账号。先在电脑打开包内 DEPLOY_PREPARE.html，生成本站独立口令；上传生成的 key.php 覆盖服务器 install/key.php。口令保存在刚生成的私密 INSTALL_KEY.txt 中，公开包本身不含通用口令。它用于避免未安装站点被抢先初始化，不是管理员密码。 管理员用户名为 3–32 位小写英文字母、数字、下划线，字母开头。密码为 12–72 字节、必须含字母和数字。 可选择安装原创示例内容和套餐；公开运营前必须检查价格和内容。

安装器创建数据表和配置文件，但不创建 MySQL 数据库或数据库用户。站点网址必须与当前安装目录一致，不能填带查询参数、片段或其他路径的网址。 向导成功后登录 /admin。实体目录入口不依赖 WordPress 伪静态。

4. 权限与收尾

app/ 安装期间要能由 PHP 写入，以创建 app/config.php；安装后除配置变更或升级外不应继续允许 PHP 修改应用代码。 storage/ 要允许 PHP 创建媒体文件和日志。不要用全站 777 解决权限问题。共享主机文件所有者模型不同，使用主机提供的权限管理。 app/config.php 自动设置为仅所属用户可读写；不要改为可公开下载的扩展名。 安装完成且确认能登录后，删除 install/。

用未登录浏览器实际请求下面的路径，必须被拒绝或返回无敏感内容的 404，不能显示目录、源码或 JSON 种子数据：

/app/seed.json
/app/config.php
/storage/
/uploads/
/.htaccess

测试安装器的 PDO 检测与这些 HTTP 路径保护是两个不同的事项，都需要验证。

5. 首次后台设置

站点身份与联系方式、服务条款、隐私与退款说明 → 外观与布局 → 用户与评论审核 → 内容 / 会员套餐 → 交易与支付 → SMTP。 蓝队云用户在「站点设置」中设置「主机鸣谢文字」和「主机鸣谢链接」，遵守该套餐页面的页脚链接规则。不要自行删掉主机要求的标识。 后台系统页能查看 PHP、数据库类型、上传限制、存储写入状态和 HTTPS 网址配置；不能控制主机面板或安装证书。

二、已有面板的 VPS

用现有面板创建 PHP 站点、绑定域名和证书、建立数据库，再按上述安装。不要运行新 VPS 脚本覆盖面板服务。 Nginx 的私有路径拒绝规则优先于 PHP 匹配，参见模板；PHP-FPM socket 按面板实际值修改。本站无需通用 try_files ... /index.php 前端控制器重写。 面板开启强制 HTTPS 后再把安装网址设为 HTTPS。已经安装的站点换域名或 HTTP 切 HTTPS，备份后修改 app/config.php 的 url，保留 secret 与数据库信息，不要重新安装。 反向代理必须只信任自己控制的代理，并正确传递 HTTPS 状态。不要为了消除登录问题全局信任任意客户端伪造的代理头。

三、全新、无面板 VPS

deploy/install-vps.sh 面向全新 Debian 12+ / Ubuntu 24.04+、root 权限和 systemd 主机。本次只检查了 Bash 语法，没有实际安装系统包或取得证书。 先阅读脚本。它会安装发行版 Caddy、PHP-FPM、PDO 驱动，创建 /var/www/chengyu，写入 Caddy 配置；会拒绝目标目录已存在、常见面板或已运行 Web 服务的环境。它不修改云防火墙、不为你设置 DNS、不卸载现有服务。

把完整包上传到非 Web 公开目录解压后：

cd chengyu
sudo bash deploy/install-vps.sh example.com

将 example.com 换成自己的域名；按提示输入 INSTALL。先使域名 A/AAAA 指向该 VPS，允许公网 TCP 80/443，保证 Caddy 能绑定端口并持续保存证书数据。删除指向错误服务器的 AAAA 记录，而不是反复申请证书。 完成后浏览器进入 /install/，选 SQLite，填 /var/www/chengyu/private/chengyu.sqlite。私有口令保留在 /var/www/chengyu/INSTALL_KEY.txt，可用 root 读取。也可自行配置 MySQL，脚本没有安装 MySQL 服务器。 Caddy 的公开域名 HTTPS 申请和续期由 Caddy 管理；不是 PHP 后台调用 ACME。网关服务、DNS 和防火墙必须正常，否则不会凭空获得可用证书。

验证后，在该脚本部署的特定路径下执行：

sudo rm -r /var/www/chengyu/site/install
sudo chown root:www-data /var/www/chengyu/site/app
sudo chmod 0750 /var/www/chengyu/site/app

这些命令只适用于本脚本创建的路径。不要照搬到不确定的生产路径，不要删除私有数据库或存储。config.php 仍需 PHP 用户能读，媒体存储仍需可写。 运行日志使用 journalctl -u caddy、journalctl -u php8.3-fpm 等，PHP 服务名按实际安装版本替换。

四、IP、端口、子目录

根目录部署时 /admin 和 /admin/ 都由 Web 服务器的实体目录入口处理；带端口可以使用 http://IP:端口/admin/ 进行隔离环境初测。正式登录与充值应使用有效 HTTPS，HTTP 模式无法创建本站在线充值单。 不能保证主机共享 IP 能直接访问你的虚拟站点，这由面板的站点绑定决定。

子目录部署时后台是 /子目录/admin/，而不是域名根目录 /admin。要严格满足根目录加 /admin，就把网站放在该域名的文档根目录。Nginx 私有目录规则也要加子目录前缀。本次自动化测试以根目录部署为主，没有完整覆盖所有子目录 / 代理组合。

六、升级与迁移

0.14.0 按序提供从 0.9.0–0.13.0 到结构 v6 的增量、可重试迁移，详见 UPGRADE.md。没有在线热更新或自动降级回滚，不支持 WordPress 数据库直接导入。 迁移需要数据库、app/config.php（尤其 secret）、整个 storage 一致备份。域名或绝对存储路径变化后修改配置对应项，检查回调地址和邮件链接，并再次做验收。完整备份不能用用户 / 订单 CSV 导出来代替。

七、新增模块上线顺序

升级或安装后先检查「模块」中的问答/投票开关，在测试版块发布试帖并用两个普通账号验证权限与结果隐私。后台「动效工作台」可先在本地预览，保存后用另一个浏览器检查默认效果；页面不会因关闭动画而失去付款或下载功能。

SMTP 先配置、实际收发成功，再开启必填邮箱验证，避免把真实访客挡在注册入口。详见 EMAIL_COMMUNITY.md。需要普通不验证注册时保持该可选开关关闭，所有 PHP 版本遵循同一设置，不是低版本精简模块。

部署完成不要求开放 SSH、FFI、Python、Node 或测试端口。测试目录仅留本地。安装器只检查基础运行环境，不表示服务器的网络、数据库性能与所有业务已验收。

八、安全、定价与主机自检

首次上线先到“系统”运行部署自检，确认真实环境的原生 PDO、回滚、加密与写权限。下载报告便于维护，但报告不含公网敏感路径访问检查，不得跳过真实 URL 验收。

准备好离线恢复码再给管理员启用身份验证器，确认服务器时钟正确。SMTP 密码找回不会移除身份验证器；没有命令权限的免费主机尤其需要事前保管恢复码。完整包的本地恢复脚本不得公开上传。

先用测试账户/测试商品设置会员价和活动，核对 0/8000/10000 比例含义、单件最高确认额和按成交价退款，再开放促销。详情见 SECURITY_PRICING.md。旧站没有价格规则时不会因升级自动出现优惠。

动效、曲线与视觉工作台

适用 0.17.0（保留早期动效模块说明）。入口：后台导航「动效实验室」，或 /admin/index.php?tab=motion。只有具备设置权限的管理员能够保存。所有动效不参与权限、库存、付款或内容可见性的判断。

一、先选择基调，再微调

页面顶部有「安静专注」「自然流动」「光感表达」三套预设。点击只改变当前浏览器的预览和表单；按下保存才写入数据库。离开页面而不保存不会更改网站默认值；预览也不是另一套演示动画，而是调用网站相同的 CYMotion 引擎。

安静预设使用 280ms 和较小位移，关闭卡片透视、磁吸、持续装饰等；自然流动预设为 480ms，保留柔和入场、光点与轻透视；光感预设为 650ms，使用弹性曲线并启用更明显的层次。预设只覆盖它列出的相关项，玻璃、主题、纹理及其余配置继续保留，避免意外重置整组外观设置。

五套配色和玻璃仍在「外观」页面选择。玻璃档位为关闭、磨砂、棱镜、流体；名称是本项目视觉风格，不保证所有浏览器都有真实折射或相同合成效果。颜色模式是明亮、深色、跟随系统；允许访客自选时，本地选择可覆盖站点默认主题，不影响后端业务。

二、曲线到底控制什么

预置曲线由服务端 Core/Motion.php 唯一定义，并输出给前端与工作台读取，避免两处数值不一致。

曲线 参数 cubic-bezier(x1,y1,x2,y2) 表现
gentle 0.22,1,0.36,1 较快响应、柔和落定
snappy 0.2,0.8,0.2,1 轻快、直接
elastic 0.34,1.56,0.64,1 轻微超出终点再回落
cinematic 0.76,0,0.24,1 起落更明显的缓入缓出
linear 0,0,1,1 匀速
custom 自定义四个控制值 以工作台曲线图与实物预览确认

自定义值以百分数填写：X1/X2 为 0–100，Y1/Y2 为 -100–200。横轴是时间，纵轴是进度；Y 大于 100 可以产生超调。字段经后端白名单和数值范围校验，不接收任意 CSS。工作台 SVG 实时显示控制点、曲线与 CSS 参数，也可点击重播比较持续时间。

全局时间动画时长 0–1200ms；卡片悬浮位移 0–12px，显现位移 0–40px，交错间隔 0–120ms。同一批入场的累计延迟封顶 360ms，避免下方内容要等很久才显示。弹层关闭会采用更短的离场时间，按钮反馈也不刻意等待整个页面动画结束。

「页面过渡」现在同时提供页面进入反馈与同源跨文档 View Transition 的条件开启。参与页面都需启用、浏览器需支持；不支持时按正常多页导航。已移除旧的 130ms 链接等待和 160ms 提交后跳转等待，点击不为装饰而人为延迟。它不是 SPA，也不缓存或伪造订单响应。本环境未完成真实浏览器 URL 导航验收，因此跨文档转场不能标为实机通过。

四、无障碍与性能优先级

系统 prefers-reduced-motion: reduce 优先于后台预设，装饰运动关闭，但购买、下载、表单、权限和全部模块保留。工作台此时仍可编辑保存数值，只是不强制播放预览动画。

低资源收敛使用浏览器可报告的节流/硬件提示，关闭部分昂贵玻璃与指针效果。不是服务器根据 PHP 版本减少功能，也不是能准确测量所有设备性能的基准测试。无法报告硬件信息时仍按常规配置运行。

弹簧模式由指针事件激活统一 requestAnimationFrame 调度；只有正在移动或回到静止的元素参与，收敛后自动停止，不留下空闲全局循环。隐藏页面、失焦或减少动态效果会清除待动元素。曲线模式保留原有渐变路径，视觉设置集中在 CSS 自定义属性。内容默认可见，仅在引擎初始化成功后标记等待显现；禁用 JavaScript 不会把正文永久藏起来。减少动态效果与页面隐藏也会取消或暂停相应动画。

五、排查

保存后效果没变化：确认提示成功，清浏览器/站点静态缓存；查看访客本地主题选择、系统减少动态效果、低资源模式、页面是否在后台，以及设备是否支持精细指针。旧浏览器直接主题切换是预期增强回退，不表示 PHP 缺失该模块。

感觉晃动：选安静预设，降低透视与悬浮，关闭粒子、持续装饰和磁吸；保留短时按钮反馈。光感预设并非适合所有内容站。

布局边缘空白：先用真实浏览器检查是否能横向滚动；某些全页截图会包含已经被根元素裁剪的离屏装饰，截图宽度不等于页面实际可滚动宽度。随包截图按真实视口宽度截取，布局测试另行检查 DOM 滚动宽度。

首次上线用键盘 Tab、Escape 和手机触摸验证导航、表单与弹层，再逐项启用昂贵效果。没有用截图保证“比某个产品更好看”；预设、参数与业务体验需要结合实际内容选择。

六、物理弹簧：保留速度，而不是重播一次 easing

选择「指针响应 → 弹簧」，调节刚度 40–480、阻尼 8–60、质量 0.40–2.50（表单按百分之一填写 40–250）。自然流动预设为 180/24/1.00；光感表达为 160/17/1.10；安静预设使用曲线路径。

spring.js 解析求解欠阻尼、临界阻尼、过阻尼三种状态。指针目标改变时携带上一次位置和速度，反向移动不会忽然把速度清零；相同真实时间下的结果不依赖简单“每帧乘固定百分比”的帧率近似。运动幅度有视觉限制，并非让卡片任意越界。

工作台显示阻尼比、响应曲线和采样收敛时间，点击重播时演示使用同一个求解器。刚度大通常跟手更快，阻尼低容易超调，质量增大会改变回落；先选择预设再微调。全局毫秒时长控制入场/弹层等时间动画，不决定弹簧的自然收敛时间。

卡片倾斜、悬浮与按钮磁吸共用求解器，正在物理更新的元素不会再叠加 CSS transform 过渡导致“双重拖延”。触屏不强造鼠标悬停；减少动态效果时显示静态可用界面。42 项算法测试验证三类阻尼、分步时间一致性、速度保留、非法输入与参数角点；它不等于所有设备上固定 60/120 帧性能保证。

七、折叠、导航与媒体

折叠面板使用原生 details 语义，增强模式动画高度可被下一次点击反向打断；完成后取消残留填充效果并清理内联高度，避免打开两次后内容被旧高度裁剪。禁用动效时直接开关，禁用 JavaScript 时仍可用原生控件。

移动后台导航支持遮罩关闭、Escape、Tab 焦点范围与关闭后恢复触发按钮焦点；打开时后台主内容 inert。桌面不显示只用于手机的菜单按钮。无 JavaScript 时保留可访问侧栏，不把管理导航永久隐藏。

「布局」中的图片灯箱只从页面已经授权输出的封面/正文图片构建，支持前后切换、计数、键盘、双倍缩放和失败状态；不会从未解锁正文偷偷提取图片。现有 Markdown 并不等价于全功能图库编辑器，主要可对封面及已经渲染的图片增强。部分原生能力缺失时保留原图阅读。

分享先尝试系统原生分享；不支持时尝试复制，复制也不可用时显示可选择的真实规范链接。用户取消系统分享不会被当成错误反复弹窗。没有加载第三方分享 SDK 或追踪脚本，没有生成海报/二维码的完整功能。

资料参考：MDN View Transition API，https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API （2026-09-06 核查）。不同浏览器的能力与授权规则需要在实际站点验收。

0.13：状态与导航微交互

「动效实验室 → 状态与导航」新增三个独立开关：motion_navigation（导航指示线）、motion_feedback（表单/通知反馈）、motion_images（已加载图片显现）。它们仍服从总动效开关、减少动态效果和低资源模式；所有新动画使用 CYMotion.animate 及统一曲线/时长，不维护另一套私有曲线。

导航指示线根据当前条目、指针和键盘焦点测量位置。用户快速反向切换时从当前可见位置续接，不先闪回原点；关闭该装饰不影响实际链接。动效实验室内有三个状态按钮与通知预览，可立即操作，不需要保存到正式站点。

表单提交立即防重并设置 aria-busy，真正请求超过 180ms 才出现装饰旋转指示，短请求不闪一下。按钮在失败/完成后恢复原来的禁用状态；失败同时提供文字提示，不能仅靠颜色或摇晃。保存和跳转不等待动画播放完毕。

通知最多同时 4 条，有明确关闭按钮，文字按文本处理而非 HTML。成功提示约 5 秒、错误约 9 秒后关闭，鼠标停留或键盘焦点进入时暂停；键盘关闭后尽力恢复触发元素焦点。减少动态效果时通知仍可用，仅不播放进出移动。

搜索结果到达采用轻微显现；图片只在成功加载后装饰，不把 opacity=0 当正文前置条件。失败图片、无 JS、旧浏览器或动画被关闭，不应造成权限已授予内容永久看不见。

这几项是原生 DOM/WAAPI 渐进增强，不依赖动画框架。后端业务不因不同 PHP 小版本而减少功能；动画支持与具体浏览器能力有关。实际导航转场尚未在当前环境完成真实浏览器 URL 验收，离线截图不证明跨文档转场已通过。

0.14：连续布局、专注阅读与报价反馈

新增 motion_layout，当前实验室统一管理 36 项参数。布局工作台按组件稳定编号记录正在显示的位置，更新 JSON/DOM 后只做位置变换；再次操作时从当前视觉位置重新测量，避免先跳回旧终点。动画完成、被取消、页面隐藏或减少动态效果时清理，不留 transform 或无意义常驻循环。

排序保留展开状态和编辑焦点，Alt+上/下键与原来的拖动/按钮并存。屏幕阅读器会听到位置变更；动画关闭后结构修改仍即时完成。它不依赖 PHP 小版本或安装动画框架。

修复折叠面板把 0ms 当空值并回退到 280ms 的错误。现在后台允许保存 0–1200ms，0ms 下入场直接可见、不保留交错等待。物理弹簧和连续背景有独立参数/开关；希望全部静止时关闭动效总开关或启用系统减少动态效果。

reading_focus 在布局设置控制专注阅读按钮：隐藏侧栏、优化文本宽度，保留正文和购买控件；不做缩放文字的重排动画，只在合适时给轻微透明度反馈。无脚本则保持正常布局。

报价由服务端生成，再按实际请求状态更新。新请求会取消旧请求，迟到响应不能替换最新金额；失败留下文字反馈并清除忙碌状态。刷新价格不收费，提交不等待动画，安全文本插入不接受接口返回 HTML。

邮箱验证、问答与投票

适用 0.11–0.14；本章所述模块最初加入结构 v3，当前数据库已升级 v6。所有管理入口仍在同一个 /admin，无 WordPress 或额外插件依赖。

一、邮箱验证码注册

后台「设置 → 邮件」填 SMTP 主机、端口、TLS 模式、发件地址、用户名与授权凭据，启用 SMTP。使用邮件服务商给出的参数和授权码；不要使用其他网站的密钥。先用自己的测试邮箱确认实际送达，再启用「注册时要求已验证邮箱」。

必填邮箱验证不能在 SMTP 未启用时保存。服务端检查发件地址/主机格式，但不能预先保证服务商账户权限、DNS、TLS 证书、出站端口或发件信誉都正常。免费主机阻止 SMTP 连接时，需由主机开放或调整到其支持的合规邮件服务，代码无法越过网络权限。

启用后，用户在注册页填写邮箱并请求验证码，填写收到的 6 位数字及其余注册信息。证明与注册账号、奖励、邀请码消耗同属业务事务；用户名冲突或邀请码失败不应出现半个账号和已扣邀请次数。没有 JavaScript 时可使用备用发码页，返回注册页继续，必须仍是同一浏览器会话。

验证码有效 10 分钟；绑定收件人、用途、浏览器会话和适用用户。数据库存带密钥摘要，不存明文验证码与收件邮箱；用户表自然仍需存账户邮箱。5 次错误后该次证明不可再用；验证码检查还有限流。邮件已发送不代表已完成验证；SMTP 接受 DATA 后即以发送完成处理，不会因随后 QUIT 断开让已送达的码失效。

二、发送限额与维护

注册、改绑和找回密码共用发送额度，不能用不同入口绕过： 同 IP 10 分钟最多 3 次，单收件人每分钟 1 次；收件人每小时上限取后台邮件发送限制（默认 3），每天上限为其 3 倍。失败尝试也可能消耗发送额度，避免对坏地址或被攻击目标无限重试。前端倒计时只为提示，真正限制在服务器。

验证码失败次数先独立提交，再返回错误，不会因后续注册事务回滚而清零。成功消费用数据库条件更新确保只消费一次。未使用记录过期后不可验证；管理员维护清理可以移除过期一天以上记录，不清空财务流水。

邮件会话绑定意味着另一台设备打开注册页后直接输入原码不会通过；退出登录也会清理该会话证明。操作日志不写验证码，第三方 SMTP 日志和邮件箱仍由运营者保护。演示测试 SMTP 仅在本地夹具中使用，不随站点启动。

三、修改邮箱及账号安全

用户中心资料页：输入新邮箱、当前密码，先向新邮箱发送验证码，再提交修改。服务端重验密码及账号状态，确认邮箱唯一，原子消费证明，记录新邮箱验证时间，并递增会话版本；当前会话刷新，其他旧会话失效。旧找回密码令牌同时作废。

管理员修改邮箱视为人工变更，邮箱验证时间清零，不伪造用户已经证明拥有邮箱。管理员改密码、改邮箱、封禁或改角色也会吊销未用找回链接。仅修改昵称不会不必要地吊销链接。用户自己修改密码同样吊销旧链接，退出登录清理购物车临时状态、口令内容授权与一次性显示内容。

「认证用户」是原有人工认证标记，与「邮箱验证时间」不是同一个字段；验证邮箱不意味着法定实名、支付资质或授予管理员权限。当前仍没有短信注册；TOTP/恢复码、第三方OAuth和账号连接已分别在0.14/0.15加入，见SECURITY_PRICING.md及CONNECTIONS_AND_OPERATIONS.md。

四、创建问答

后台「问答与投票」可查看、筛选并编辑帖子；从发布帖子或前台投稿选择类型「问答」。问答沿用现有正文、版块、内容访问权限、审核和评论机制，不生成另一套绕开权限的内容表。

用户正常评论作为回答。问题作者或有内容编辑权限的管理员/编辑可以采纳本帖、审核通过、顶级回答；不能采纳别的帖子的回答、待审回复或回复中的嵌套回复。重复采纳同一条不会反复通知。采纳回答显示高亮与跳转链接，并排到显示列表前部；审核拒绝已采纳回答时，采纳状态与审核变更在同一事务内清除。

问答需要开放评论且允许相应用户评论。此版是基础「回答＋采纳」流程，不包含付费悬赏、自动分账、专家服务、付费圈子或答案投票评分。已有采纳回答的帖子不可直接改成其他类型。

五、创建投票

帖子类型选择「投票」，输入问题、每行一个选项，共 2–10 个互不相同的选项。可设截止时间，支持永不到期；结果可选公开、投票后、结束后。截止值是站点时区下的时间。

用户需登录、账户可用，帖子已发布且到展示时间，并有该内容及分类的访问权限，才能投票。它是单选、一账号一票，不等于能阻止一个自然人注册多个账号。重复提交相同选择幂等成功；改选请求被拒绝，不改变已经记下的选择。

第一票产生后，问题、选项、截止时间和结果隐私锁定，避免中途篡改。正文、摘要等仍按正常编辑版本保护修改；不能以清空截止时间绕过锁定。没有投票时，可以正常修改选项和截止设置。启用截止时间后，在首次投票前清空字段可恢复永不到期。

「投票后可见」不会把票数先输出到 HTML 再用 CSS 遮盖；未有权看结果的响应不含总票数与选项计数。「结束后可见」即使已投也要等截止，保存此规则必须填写截止时间；不能创建永远不公布结果的无截止投票。帖子权限同样保护投票问题与结果。

已投票记录不会因关闭模块删除。模块开关在后台「模块」中控制，服务端写入口也会拒绝，不能靠手工构造请求继续投票。简单采纳/投票不是子比付费圈子全套功能。

六、阅读目录与受限评论

后台布局开关可控制阅读目录。正文有 Markdown 标题时，前端从已经渲染、已经授权的标题生成锚点；没有标题则不生成空目录。代码不会解析尚未授权的隐藏正文来泄露标题。

受限文章/帖子的评论列表仅在相应内容权限满足时输出。回复后可见规则需要先允许回复，保留对应评论入口；这是规则自身语义，不是所有会员/密码内容都对访客开放评论。后台评论显示条件仍可叠加限制。

一、布局工作台

后台进入「布局工作台」，选择首页、文章、社区或商城。布局放在该页面的标准列表区域之前，不替换登录、支付、用户中心等系统页面。

支持 8 类组件：标题、文本、内容卡片、专题卡片、行动按钮、站点统计、友情链接、间距。可设置标题/安全 Markdown、内容或专题 ID、内部跳转、对齐、普通/玻璃/强调表面、显示设备和入场效果。组件可新增、复制、删除、箭头调序或拖动调序；修改后点击发布保存。内置三套起始组合，可进一步修改。

每个位置最多 24 个组件。导出文件是 chengyu-layout v1 JSON，服务端限制为 100,000 字节并重新验证所有字段。导入会替换编辑器当前未保存布局，导入前先导出备份。跨站导入必须重新核对内容/专题 ID。布局 JSON 不带支付密钥、数据库密码、HTML 脚本或可执行 PHP；这不是安全运行任意模板代码的沙盒。

两位管理员同时编辑同一位置时，旧版本保存会收到冲突，不会静默覆盖新修改。无 JavaScript 时仍提供受校验的 JSON 编辑入口。此模块是结构化组件编排器，不是古腾堡、任意拖拽整站或完整所见即所得设计器。

二、多规格商品与卡密库存

在后台创建商品后进入对应「规格」管理。实物和卡密商品可建立最多 100 个 SKU，设置唯一编码、名称、价格、库存、启用与排序；每个规格有自己的库存。页面和购物车会携带明确的规格 ID，不能只传一个随意价格。

卡密商品从库存页选择对应规格，再按行导入，每批最多 500 行。代码加密保存，重复码全局检查，字面字符串 0 也是有效卡密。卡密库存从未售代码记录同步计算，不把人工库存数字当作可发放卡密。已有未分配规格的未售码时，先处理原库存再切换规格结构，不能让两类库存并行失真。

前台同一商品的不同规格作为不同购物车条目。购物车最多 20 个条目、总计 100 件；单条卡密/实物数量 1–10，数字授权通常为 1。整车结算使用一个事务，任何商品无权限、售罄或余额不足都会整体回滚，不会只扣钱而留下半张购物车。请求标识与内容指纹用于重复提交保护。

未发货实物退款回到原规格库存。已发出的卡密即使退款也不重新出售。已有有效数字权益不会重复购买；过期的限时权益可以重新购买。更改商品类型可能破坏历史订单，所以存在销量、库存或规格后受限制。

三、VIP 1–3 与有效期

后台会员套餐增加等级字段：VIP 1、VIP 2、VIP 3。高等级可访问要求较低等级的会员内容。每个等级独立累计期限，同等级续期从现有到期时间与当前时间的较晚者开始；低等级续费不会顺便延长高级会员。

内容可配置最低 VIP 等级。后台编辑普通资料不会重置或延长会员；需要管理员明确勾选替换期限才进行对应变更。会员未到期并不自动表示可看一切付费资源，仍按内容自身的访问级别和 VIP 免费规则判定。

0.9.0 的单层会员升级时保留为 VIP 1。兑换码赠送的原基础 VIP 仍按其既有语义处理，不是任意指定高级套餐的销售系统。

四、付费时限、密码、修订与下载

内容可设置购买权益天数，0 为永久，非零范围为 1–3650 天。订单保存购买当时的到期时间，后续商品改价/改时长不重写旧订单。到期后的正文与私有附件同样重新检查权限。只有真正付费的内容可通过购买解锁，不能对 VIP、回复或密码内容构造零元订单绕过限制。

密码内容使用哈希保存密码，错误输入有限流。授权保存在会话，修改密码会让旧授权失效；此功能不是对共享密码防转发的数字版权保护。

内容编辑使用版本号避免覆盖另一位编辑的更新，并保留最近 20 个文本修订。还原以文本内容为范围，不回退价格、已付款订单、库存或资产账本，不能用于撤销交易。

私有文件经 media.php 检查权限再输出，支持单段 HTTP Range：固定段、末尾段、开放尾段，合法返回 206，非法或多段返回 416；HEAD 不发送文件正文。私有存储保护前缀不包含在下载内容与长度中。

后台可以配置每日下载额度及查看下载记录。配额按已登录用户、当天、不同私有文件计数；同一天重复获取同一文件及其分段不会重复占用次数，HEAD 不扣次数，管理人员豁免。通过密码获得访问的匿名访客没有稳定用户身份，不能把此额度宣传为对匿名人的可靠日限制。需要身份级配额时使用登录/VIP/购买权限。

五、任务中心

后台可建立一次性或每日任务，目标来自实际数据：当天签到、通过审核的评论、已发布且到展示时间的文章/帖子、完善个人简介与显示名。积分与经验奖励独立配置。资料完善仅允许一次性任务，避免同一份资料每天无限领奖。

用户在前台「任务」查看进度并领取，进度未达标不会发放。领取记录、积分账本和经验写入在同一事务内，重复提交不重复发奖。领取过的任务不允许改变目标/周期/奖励规则；停止旧任务后新建规则，防止已发奖励语义变化。此系统没有人工审查任务、外部平台打卡或定时后台自动领奖。

六、邀请制注册

后台用户设置可启用注册邀请码要求；邀请码在专门管理页生成，单批 1–100 个，每码最多使用 1–1000 次，并配置到期时间。原始邀请码只在生成后的页面展示一次，应立即保存到安全位置。数据库保存带站点密钥的摘要，不能在后台反查明文。

注册成功和消费邀请码次数处于同一事务，注册失败不会浪费次数；并发使用遵守次数上限。管理员可以停用代码。此模块是邀请注册，不是商城购买后自动生成邀请码的商品类型；后者仍未实现。

七、专题、友情链接和公告

后台通过专属管理页建立专题，关联最多 200 条内容 ID；前台输出前重新检查内容状态和权限，不把未发布正文拼进专题。不同文章、帖子或商品可根据可见性组合。

友情链接支持名称、描述、分组、顺序和启用，链接只接受安全 HTTP/HTTPS 协议。它不是自动审核站点或检测死链的工具。

公告支持开始/结束时间、展示人群与内部跳转，按请求时刻判断展示，无需定时任务。到期消失不是服务器已经执行过一个后台定时作业。任务、专题、友情链接等有模块开关；其他运营参数由各管理表单配置。

八、发货、确认收货与退款逆向

实物订单由后台人工发货，可更正运输信息；所属用户确认收货，重复确认不会重复处理。这里只保存人工填写的数据，不调用物流轨迹 API。

退款仍是本项目支持的站内购买退款，退回原站内资产，撤销该笔订单权益并保留其他有效订单权益。不是支付宝、微信或银行卡原路退款。

推荐佣金的退款冲销允许形成内部负债记录，以免推荐人已提现导致买家永远不能退款；负数佣金不等于普通余额可以透支，也不是自动向推荐人的银行卡追回。运营者应审核此情况并人工对账。提现仍为人工审核/人工打款后确认，不是自动代付。

0.17 支付、退款与代付

本软件提供协议实现，不提供商户账户、免签资金通道、经营资质或平台批准。新外部通道默认关闭；本次未做真实商户联调/实付。本地签名和响应夹具不是平台认证。

两种交易路径

原易支付/CodePay：外部充值 → 校验通知/查询 → 站内余额 → 站内资产购买。新 Checkout：复核商品/运费/优惠 → 原子预留库存 → 创建支付总单与单位订单 → 站内余额或官方支付 → 服务器核实后履约。会员补差目前仅走站内资产。

金额为整数最小单位；不接受科学计数法、浮动尾数或未绑定订单的金额。站点单一法币由 store_currency 决定，发生金融活动后不能改标签充当换汇。无自动汇率转换。支付宝/微信仅 CNY；PayPal 适配 USD/EUR/GBP/HKD/SGD/CAD/AUD，存量人民币站不可为接 PayPal 随意改币种。

官方直连接入

售后与原路退款

用户从订单申请，管理员以密码及已启用的第二因素审核。支持单位订单退款（含已分摊运费）、退货退款、同 SKU 换货、回寄物流、收货验货后可选恢复库存。已经交付的卡密不回到可销售库存。

审核后入队：站内资产购买退原资产；官方直连购买调用原通道，不能再额外给钱包加余额。稳定退款号、租约、未知结果先查后重试，验证外部成功后才完成本地回滚。超时保持待核实，不用新的退款号重试。旧充值不会通过商品售后自动退回。

未实现任意金额部分退款、跨 SKU 补差换货、拒付争议自动仲裁、收费换汇或删除用户已经下载的内容。作者/推荐收益按原单冲回，已转出收益可能形成债务，软件不能自动追回外部现金。

主动核付、调度与代付

收据页/后台可主动查单；Jobs 在待处理付款、退款与代付中选 1–10 个任务，支持后台、CLI、HMAC POST 及重放拒绝。它是订单级主动核付，不是平台日账单下载、手续费核算或银行结算。0.17另有标准CSV账单差异报告，但不自动下载平台原始账单，也不据CSV操作资金。免费主机无人值守需要可信外部调度，不存在自动运行的隐藏常驻进程。

自动代付只实现 PayPal Payouts，需平台批准权限、原申请接收邮箱与相同币种，管理员审款后排队；固定批次键，未知结果继续冻结。支付宝转账、微信商家转账、银行代付未实现。保留人工打款确认，禁止同笔提现同时人工付款和自动执行。

安全、数据与运维说明

没有“无漏洞”或通过独立渗透审计的承诺。自动化测试不能代替真实环境配置、安全复核与持续维护。当前版本适合先做隔离验收，再决定开放哪些模块。

已实现的主要边界

密码使用 PHP password_hash / password_verify。会话开启严格模式，Cookie 使用 HttpOnly、SameSite；规范网址为 HTTPS 时使用 Secure。登录、退出或凭据更改涉及会话防护；服务端用户 session_version 支持使既有会话失效。 写入请求要求 CSRF，只有支付通知走独立的签名验证流程。业务权限在服务端判断，不能靠隐藏菜单防护。普通用户不能访问管理员页面、读其他用户的订单或私信、拿到未购买的私有附件。 所有动态数据库参数绑定；表 / 字段标识来自程序控制并验证。输入使用类型 / 长度约束。Markdown 不执行用户 HTML，输出进行转义，外链限制协议。不能据此宣称覆盖全部 XSS 场景或浏览器兼容情况。 敏感操作包括管理员财务操作及用户转账的相应身份 / 密码校验，日志记录操作而不是把所有密码与完整密钥写入日志。 登录、注册、发帖、私信、找回邮件等使用频率限制。共享代理、NAT 用户和反向代理部署仍需要人工调整，避免误伤。

资产一致性

站内资产用整数，不用浮点数表示货币。钱包调整、账本、订单状态、库存与权益在数据库事务中更新；账本唯一幂等键与平台交易号唯一约束防重复结算。 SQLite 用 BEGIN IMMEDIATE，MySQL 用事务与需要的行锁；MySQL 死锁重试有次数上限。嵌套操作共享外层事务，没有实现嵌套保存点。 schema 使用索引与唯一约束，但没有声明完整数据库外键；关联一致性由服务层维护。不要直接手工删金融记录或绕过服务层写表。 8 进程 SQLite 竞争扣款验证过余额不会扣成负数；这不是 MySQL 并发压测、财务审计、分布式部署保证或资金保险。

文件与秘密

商户密钥、SMTP 密码、订单支付配置快照、卡密及部分支付信息使用应用 secret 加密；secret 位于 app/config.php，丢失后无法恢复原密文内容。管理员账号被控制后仍可能修改配置与执行管理员功能，加密不等于免于账号失陷。 用户地址簿、正文、普通资料和媒体文件并非全部加密存储。订单地址快照有加密，但不能把整个数据库称作“全量加密”。备份必须按敏感数据保护。

上传限制 MIME 和大小；普通成员只允许合规图片，不允许 SVG / PHP 等可执行文件。管理员可上传规定的资源类型，应用通过受控下载端点输出。 实际文件写成随机命名并带 PHP 阻断前缀的存储封套，直连执行会先退出；合法下载由应用去掉封套后输出原始字节。该机制不等于文件内容加密，不替代 Web 服务器拒绝访问 storage。PHP 解析失效时必须立即处理服务器配置。 Apache .htaccess、Nginx 私有目录规则、Caddy handle 与 IIS web.config 的实际生效情况必须在部署主机检查。本次 HTTP 测试中的私有目录拒绝由测试路由器提供，不能作为这些生产服务器配置已经验证的证据。 不要把完整交付目录、备份、SQL、INSTALL_KEY、测试适配器或 debug 页面上传到 Web 根目录。

安全上线顺序

先完成 HTTPS、规范网址、目录访问阻断、文件权限和主机账户安全；删除 install；测试普通用户权限隔离；恢复备份；再测试商户支付，最后开放用户注册与交易。 现有Google/GitHub/Microsoft OAuth适配、TOTP/恢复码和邮件验证注册；仍没有短信验证或真正实名核验。本版的人工认证标记不是第三方身份认证服务。后台管理员应使用唯一强密码并优先配合主机侧访问控制。 前端出现余额或价格不能作为授权事实；管理员收款、提现人工流程也必须留外部凭据。金融模块默认关闭的部分不应仅为“功能多”而全部打开。 不要在支付回调路径加人机验证页面，也不要为了回调方便全局关闭 CSRF、金额校验或 HTTPS。

可恢复的备份

必须把数据库、app/config.php 的原 secret、整个 storage 作为同一备份集。CSV 导出不是完整备份，没有密码哈希、加密配置和媒体等完整恢复要素。 MySQL 使用面板的一致性导出，或专业备份工具的事务一致性模式；同时避免备份过程中新增上传造成数据库与媒体不一致。 SQLite 使用 SQLite 在线备份 API / sqlite3 .backup 或停止写入后正确处理 WAL。不能在活跃写入期间只复制主 .sqlite 文件并忽略 WAL。

恢复演练：在非公开的新目录 / 数据库准备备份 → 保留相同 secret → 修正绝对路径与规范网址 → 恢复 storage → 验证密码登录、会员权限、购买权益、卡密解密、订单与账本合计、文件下载 → 关闭测试站的真实支付或使用单独测试商户。 演练成功才可认定备份“可恢复”。演练未在本次真实主机执行。 不要直接用安装向导重新生成密钥覆盖已有数据库。安装器看到已有用户会拒绝新装；应恢复原 config，而不是删除用户数据绕过它。

日志、清理与事件处置

异常日志受保护且有大小限制。管理员系统清理处理过期令牌、过期限流项、超时待支付单和按留存期轮转审计；不会清空金融流水。 收到泄露或异常付款报告：暂停对应入口，保留订单 / 账本 / 主机与网关日志，核对真实商户账单，撤销泄露凭据、使会话失效，复核受影响账户与金额。不要直接删除证据。 对应用 secret 的更换需要重新加密方案，不可只换一串随机值；商户密钥修改也需要考虑旧订单快照。恢复与升级前都应备份。

0.11 新安全约束

0.14：第二因素、恢复与金额确认

密码登录的服务入口也拒绝超过 72 字节的密码，避免 bcrypt 静默截断。停用账户在兑换前由资产服务重新锁定并检查，不能只依赖路由或隐藏按钮。

第二因素密钥加密保存，恢复码存带站点密钥的摘要；登录时与账户行锁/会话版本共同验证。重复时间步或恢复码拒绝，事务回滚恢复消费。管理操作要求当前密码和相应第二因素；暂停新绑定/重置密码不会移除已启用保护。

备份必须包含原加密密钥，并妥善保护备份和用户恢复码。恢复旧数据库可能重放旧状态，需要撤销旧会话并重新核对安全与资金。本地恢复脚本只有站点所有者在 Web 根目录外执行，不是 HTTP 后门；脚本完整生产命令路径没有原生 PDO 实机验收，本地服务方法和语法已测。

报价返回纯文本和整数，前端不插入返回 HTML。结算复算并核验单件最高金额，拒绝时回滚券额度/扣款。预览不保证永久价格或库存，不能把显示“已核对”当“已支付”。

部署自检需管理员与 CSRF，输出不含商户/数据库密钥或服务器绝对路径。版本信息仍只给可信维护人员；自检通过不替代外部安全审计、真实目录保护和支付验收。

0.18.0 搜索与加密副本

恢复副本采用 PBKDF2-SHA256（600000 次）与分块 AES-256-GCM，含顺序/前块标签关联和终止记录，拒绝截断或篡改。密码 16–256 字节；应用不保存备份密码。格式是本项目有限记录协议，不接受 PHP 序列化对象、SQL 语句或任意路径。密码和归档需要分开保存；归档中包含原站 secret、用户哈希、订单、余额等敏感信息，不能公开分享。

加密不等于可恢复保证，须另存并定期演练。当前只支持同版本、同结构、同数据库类型的独立空目标。MySQL DDL 无法完全事务回滚；失败后丢弃隔离目标再排错，不在运行中的生产数据库重试。恢复后维护模式与 recovery_hold 阻止任务继续，原会话失效；外部资金与旧数据库之间的差异需人工核对。具体命令及限制见 BACKUP_RECOVERY.md。

全局设置统一由 settings.php 和版本增量定义组成，默认值与字段数记录在RELEASE.json；本轮另加 settings018.php，保留 settings017.php。默认值、类型范围、后台表单、保存验证与前台读取复用同一键。任务、专题、SKU、套餐、布局等是业务对象，不硬塞成数百个彼此关联的全局配置项。

5 种主题共用业务服务和组件，只改变变量与小范围排版。支付验证、库存扣减、账本写入、内容授权不复制到每个主题。SVG 几何封面与图标属于本项目原创代码素材，不依赖 CDN、在线字体或图片服务。

新版 DRY 边界

Inventory 是规格选择、库存消费/恢复、卡密同步和导入的共用入口；Cart 复用 Commerce 的购买规则，不再维护另一套可分叉的扣款代码。Membership 管理独立等级期限，内容与媒体复用同一访问判定。

Catalog 对专题、链接、公告使用受限实体定义和共用管理路径，不开放客户端传入任意 SQL 表名。Layout 只接受固定 JSON 格式和字段白名单。Tasks 从实际数据取得完成证明，领取和资产调整共用事务。Invitations 只保存摘要，次数消耗在注册事务中。

控制器做输入解析、权限和路由，服务层维护业务不变量，视图输出已授权数据；不能在模板中直接修改账本。基础数据库和活动日志统一复用，但不把语义不同的余额、邀请码和库存强行做成同一个抽象。

金融与并发

余额、推荐佣金与作者收益以整数分保存，积分/站内代币为整数。所有资产通过 Wallet::adjust 和业务事务，带与业务记录绑定的幂等键。请求指纹阻止将同一个结算标识复用于不同购物车。付款、库存、卡密、权益与退款一起设计。

MySQL 用 InnoDB 行锁，SQLite 用事务和忙等；嵌套调用共享外层事务，任一嵌套调用抛错都会标记 rollback-only，外层捕获异常也不能提交部分变更。金额和数量验证在写入前完成，事务内避免不可回滚的网络发信。唯一约束不是错误处理的替代品：正常重试返回已有结果，冲突数据应报错。

推荐佣金逆向可能形成内部欠账，以保证已经提现的推荐收益不阻塞买家退款；普通用户资产仍不能超支。免费主机上没有分布式事务或多节点锁的保证。

数据库结构升级

schema.php 创建基础表，Core/Migrations.php 增量升级到结构v9（v8交易表、v9运营表另见本篇补充）；v2 新增 13 张表，v3 新增 4 张表；v4 新增 4 张表及分类/投票/邀请码字段；v5 新增收益与历史两张表、作者/隐私/提现来源字段及媒体关联索引；v6 新增身份验证器与价格规则表、券范围字段；v7 新增身份连接、查询记录、配置快照、徽章与授予五张表。新装和升级共用迁移，不把升级逻辑仅写进安装器。数据库 cy_settings._schema_version 在全部迁移完成后才更新。

用私有文件锁串行化单站迁移；新增表/列先判定存在，可重试。MySQL DDL 不能被应用事务整体回滚，因此失败恢复需要备份和重试设计。配置文件的 schema_version 是安装格式标记，不是当前数据库迁移版本。

生产使用 PDO；本环境的 FFI SQLite 是测试工具，不能替代原生 PDO/MySQL 验收。开发者应运行随包 CI 矩阵并保留原生数据库测试结果，再扩展 SQL 或调整锁顺序。

扩展方法

新增设置：字段定义、中文标签、读取点和非法值测试一起提交。新增主题：扩展允许值与样式变量，验证移动端、深色、减少动态效果和文字对比度。新增业务：先定义权限/事务/逆向流程，再接前后台。

新增支付网关需核对其真实官方协议、签名、金额单位、交易状态和重试语义，再加入固定样例和真实商户联调。不能因名称中有“易支付”或“码支付”就复用另一个平台的参数。

新增订单类型必须同时处理履约、下载、库存、取消、退款和推荐佣金逆向。新增数据库版本先有一致性备份与迁移测试。修改公共组件应同时跑旧测试与新增边界用例，而不是删除不通过的旧测试。

运行边界

定时发布和公告通过读取时判断时间，不是可靠后台调度平台。没有自动主动支付对账、消息队列、全文检索集群或多节点共享会话实现。需要高并发或大型媒体时应独立设计基础设施，不能从源码体积推断免费主机容量。

浏览器动效遵循减少动态效果；低资源模式只收敛视觉负载，不限制购买或后台业务。客户端偏好存在 localStorage，管理员默认存在数据库，互不冒充。示例内容可编辑，不代表真实访客数据。

0.11 服务与浏览器边界

Verification 统一验证码哈希、发送限额、用途/会话绑定、失败次数与证明消费；注册、改绑和找回密码共用发送配额。失败尝试在独立验证事务提交之后才抛错；成功证明在账户业务事务消费，避免失败注册把证明永久扣掉。SMTP 网络发送在数据库事务之外，发送失败不留下可消费证明。密码修改和管理员凭据变更同步吊销旧找回链接。

Threads 管理讨论类型、投票选项、结果隐私与采纳，保存复用 Content 的版本/事务；读写复用 Content 的访问检查。投票同时依赖账户/内容锁与唯一约束，重复提交不产生多票。采纳和审核均先锁同一内容再锁评论，减少相反锁序；审核否决同步清理采纳标志。

Core/Motion.php 是预置曲线与预设的单一来源，settings.php 管理字段范围，视图将允许的公开数值输出为转义 JSON；前端不再维护第二张曲线表。Settings::savePartial 复用整组验证并保留未修改字段，不由动效页重置其他外观。

motion.js 管理显现、指针反馈、原生弹层与主题转场；motion-studio.js 只负责编辑器参数、曲线显示和重播，调用同一引擎。features.js 邮箱请求复用 app.js 的 CYUI 请求和反馈层，不复制 CSRF/错误转换流程。样式变量共用，主题不复制业务模板。

浏览器的增强是渐进式：内容本来可见，JS 成功初始化后才加入等待显现状态；动画开关从不决定业务授权。减少动态效果优先，指针仅在事件后调度帧，无全局常驻指针渲染循环。后台保存始终经过服务端输入校验、CSRF、权限和审计。

0.12 的新增边界

Categories 负责树结构校验、继承阅读/发布条件与成员有效期；Content::access 再检查分类，避免调用方只传入原始内容行时漏掉父级门禁。前台是否显示按钮不是授权来源。

圈子加入和自动邀请码是 Commerce 的订单分支，不各自建立第二份扣款系统；Invitations 继续以摘要验证，交付码通过既有加密服务保存。Reviews 锁定购买订单并通过关联有效订单计算公开评分；Bounties 使用已有 Wallet 幂等键托管/发奖/退回，采纳与发奖同事务。

旧单选的 cy_poll_votes 表保留一账号一票约束，选择集合位于 cy_poll_choices；迁移回填可重试。结果查询按投票人数统计而非选择行数。数据库死锁/锁等待超时在最外层事务有限重试，业务副作用不得移到事务回调内的外部网络。

动效的曲线与字段属于 Core/Motion.php，解析弹簧属于 assets/spring.js，前台与实验室共用。interactions.js 管理具体控件与焦点，不另复制后台/前台弹簧算法。CSS 按主题变量工作，避免主题各自维护 JS。

0.13 维护边界

Creator 集中管理作者收益的应计、结算、退款逆向与转换；Commerce 在订单事务内调用，Wallet 是唯一资产账本边界。前后台收益列表共用 income_rows，避免显示与统计规则分叉。锁顺序以订单 → 收益 → 作者为主，提现使用原来源资产；原生 MySQL 的并发和死锁重试仍需专门运行矩阵。

Discovery 管理本人阅读状态与检索建议，关注/历史列表重用 Content::feed 的中央可见性过滤，不复制另一套忽略分类权限的 SQL。阅读容量有明确上限，搜索建议只暴露公开字段。

新 JS 拆成 discovery.js 与 feedback.js，UI 网络状态与业务权限分离；运动仍交给 motion.js / spring.js。无构建依赖、无外部 CDN 脚本、无前端保存的支付密钥。服务器输出遵循统一转义，搜索 DOM 使用 textContent，不执行响应里的标记。

0.14 的复用边界

Pricing 只做受限整数计价/优惠券验证和规则保存，会员资格继续调用 Membership，不另造会员缓存或资产账本。预览不预留券；真正核销必须在 Commerce 交易里调用 reserve 路径。SKU、卡片、购物车和订单保存共用同一计算入口；最高确认金额不是客户端指定成交价。

SecondFactor 按账户→认证记录的锁顺序复用 Wallet 的有效账户锁、Crypto、Activity 和会话版本。TOTP 数学放在独立 Core/Totp，HTTP 入口只处理输入/证明传递；现有 Auth 登录在账户事务中调用验证，避免两个入口实现不同验证规则。恢复码只保存摘要，明文短暂放在当前用户会话且消费后清除。

Diagnostics 以管理员按需执行的检查集合输出，不借运行检查执行任意 SQL 或外部命令；回滚探针写入随机短期键并验证不存在。只报告当前被检查的基础能力，不将测试适配器冒充生产驱动。

refinement.js 复用 CYMotion 的时长、曲线、减少动态效果与清理语义。布局编号是稳定键，内容仍由原 Layout 校验；报价不创建客户端私有计价公式，服务端返回整数和安全展示文字。CSS 使用现有颜色/表面变量，新页面不复制业务代码。

这些边界便于扩展，但不构成任意插件加载平台；新增财务模块仍需事务、幂等、权限、退款和并发回归，不能只增加按钮。

0.16 新服务边界

Checkout 复用 Commerce 的单位订单、账本、库存和履约；GuestOrders 是令牌限定的购买身份，不是常规登录。Shipping/Promotions 通过 Rulebooks 验证修订号；Membership 用实际付款权益批次和签名短时报价。

0.18.0 复用与边界

HttpClient::request 统一传输校验，JSON、form、HEAD 共用重复头、请求体和响应分帧约束。Activity::rateMany 一次事务预留验证码全部配额，不在每种收件场景复制限流逻辑。

0.12 社区与交易模块使用说明

本章只描述源码已经实现的范围。后台管理路径均以根目录部署为例；部分危险或需要运营规则的功能默认关闭，启用前先设置价格、说明与审核。

一、分类层级与圈子

后台「分类/版块」设置父级。层级最多 8 级，不允许循环、跨内容类型父子关系；已有内容或子节点的分类不能直接改成另一类型。上级与本级阅读条件同时生效，不是“子级开放就绕过父级”。

阅读条件：公开、登录、指定最低 VIP、圈子成员；发布条件：登录、指定最低 VIP、成员、编辑/管理员。发布限制和阅读限制是独立设置。分类继承由共用 Categories 服务执行，文章详情、列表筛选、购买、评论、正文访问和私有下载均通过服务端判断；编辑/管理员有管理访问权。

把社区版块设为圈子，配置是否开放加入、站内资产、价格与天数。0 金额为免费加入；余额是整数分，积分/代币为整数。前台有圈子发现页、圈子详情、加入表单及成员到期提示。/admin/index.php?tab=circles 管理圈子成员，可人工给予期限或暂停成员资格，修改写审计日志。

不是定期订阅扣款：有效成员不可提前购买续期；到期后可再次加入。每笔成功订单有独立期限，退款只撤销对应订单授予的有效权益，人工期限/其他有效订单不被误删。成员暂停不自动退款，管理员要单独处理争议。不得把本圈子付款视为绕过父级权限；父级要求仍需满足。

关闭新加入不会删除历史权益；单独关闭整个圈子模块将阻止新的加入行为。取消/退款仍走订单处理，不能靠删除分类清除交易历史。

二、积分悬赏问答

后台「模块」启用积分、问答及悬赏，设置最高悬赏积分。悬赏默认关闭；本版仅站内积分，没有现金悬赏/代付/多人分配。

问题作者可为自己已发布、未采纳的问题托管 1–30 天积分。托管时即扣除可用积分并生成唯一记录；余额不足整体回滚。一个问题只保留一段悬赏历史，本版不支持追加或退款后重新悬赏。

作者/编辑采纳同帖已审核顶级回答时，同一事务把积分发给回答作者、更新采纳状态并写日志；不能奖励自己、已停用账号或过期悬赏。重复请求不会再次发奖；已发奖不能改奖另一个回答。

过期未发奖由作者在问题页点击退回；管理员可在 /admin/index.php?tab=bounties 提前人工退回并留痕。关闭新悬赏后，历史未结清积分仍可退回。不需要计划任务，也不是自动到期退款服务；运营者须处理待结清记录。

回答后来被驳回时，采纳展示撤销，但历史积分奖励不自动扣回；重新审核/再次采纳也不重复付款。争议由管理员结合日志人工处理。

三、单选与多选投票

发布帖子选择投票，填 2–10 个不同选项，设置最多可选数量 1–选项数。1 是单选，大于 1 是多选。结果可以始终可见、投票后可见、截止后可见；截止后可见必须有有效截止时间。

每账号一张不可修改的票；选项顺序不同但集合相同的重试返回原结果，不产生新票。提交重复选项、越限或别的投票的选项都会被拒绝。第一票之后锁定选项、题目、隐私规则、最大选择数与截止时间，避免投票后改规则。

分母是投票人数，不是选择总数，因此多选百分比之和可能大于 100%。未达到结果显示条件时服务端不返回票数，不是仅靠 CSS 隐藏。旧单选数据迁移后继续使用，不丢票。

四、购买后自动生成邀请码

后台「模块」启用自动邀请码商品（默认关闭）；编辑商品，将交付类型设为邀请码，配置每个码允许使用次数、购买后有效天数、价格、库存和交付说明。适用于单规格商品，本版不提供邀请码 SKU 组合。

结算在同一事务中扣款/扣库存、生成随机邀请码、保存验证摘要并加密保存交付内容。用户在自己的订单里查看，管理员按订单权限处理；每次支付通知或幂等重试不会生成第二份码。

要强制邀请码注册，必须把后台注册方式切为「仅邀请码注册」；开放注册不会要求或消耗该码。邀请码原文只在交付记录受控展示，注册验证依摘要和次数进行，多个注册竞争次数不会超用。

未使用的码支持站内退款并同步停用；已经消耗次数的码拒绝自动退款，转人工争议处理。已经生成交付的码不会回到可售库存，也不会把同一个码卖给另一位买家。退款去向仍是原站内资产，不会自动调用支付宝/微信原路退款。

五、经购买验证的商品评价

后台启用商品评价，默认需要审核。实际购买成功的用户可对该商品提交 1–5 星、最多 2000 字的文字评价；每个用户/商品最多一条，再次提交为修改。修改后按当前审核设置重新进入待审，不绕过审核。

/admin/index.php?tab=reviews 审核。公开列表只统计已批准评价、仍有效的对应购买订单和正常账号；订单退款后该评价不再进入公开评分/列表，历史记录保留供审计。不能向没有购买的用户开放“已购评价”标记。

本版没有图片追评、商家回复、评价积分奖励、虚构评价导入或虚假销量；展示的数量与平均分从数据库实时查询，不可在后台填一个假的数字。

六、页面与配置

圈子入口：/index.php?r=circles，详情 /index.php?r=circle&id=分类ID。积分悬赏与评价在对应文章/商品页面显示，不能单独绕开内容权限访问内部资料。

前台表单全部使用现有登录、CSRF、参数验证与事务；普通用户不能调用后台成员/退款/审核接口。管理员、编辑权限依接口区分，不能只根据按钮是否可见判断授权。后台集中设置与具体业务对象分开维护，不把每个圈子的价格硬编码成全局设置。

作者收益、阅读历史与关注发现

适用 0.13.0–0.14.0。新模块无 WordPress、队列、cron 或额外生产依赖；与旧模块共用数据库、权限、钱包和前后台模板。下面的默认值只适用于未被管理员修改的站点。

一、开启作者经营

先到 /admin → 系统设置 → 交易与资产分组，开启「作者收益分成」；配置默认分成比例和等待天数。对应设置键为 creator_income_enabled、creator_share_bps、creator_hold_days。比例以基点保存：8000 = 80%，不是 8000%。

二、收益如何计算

仅针对实际已支付、余额计价、金额大于零、作者当时具有资格且买家不是作者自己的内容订单。积分/代币购买、免费订单、购买会员和加入圈子，不产生本模块的内容作者收益。

公式（内部单位为分，最终向下取整）：

可分成基数 = 实付金额 - 本单实际推荐佣金
作者收益 = floor(可分成基数 × 作者比例 / 10000)

例如实付 100 元、推荐佣金 10 元、作者比例 80%，作者收益是 72 元，剩余 18 元是这两项扣除后的站内差额；这不代表扣除了网关手续费、税费、运营成本或退款损失。

订单创建时保存作者、实际基数、比例、收益、可结算时间快照。以后调整站点比例/等待期、作者资格、文章作者或价格，不追溯改写旧单。升级前订单不批量追补作者分成，也不把原推荐佣金转换成作者收入。

推荐佣金 commission 与作者收益 earnings 是两种独立账本资产；订单后分成与退款都在现有交易事务内执行，不靠仅显示前台数字完成。

三、结算与提现

付费后先显示「待结算」。到达等待期、订单仍已付且没有正在处理的退款，才可结算。实物订单还必须确认收货。作者点击「结算符合条件的收益」，每次最多 50 条，逐订单核验并记入收益资产；超过 50 条可以继续点击，不需要后台常驻队列。

重复点击、重复请求和并发结算不会重复入账。已结算收入统计是历史累计，不等于当前可用收益：提现、转换和退款会改变可用资产。

可选「收益转余额」默认关闭。开启后作者须验证当前密码，按 1:1 将可用收益转入余额，形成对应转出/转入流水；同一请求不重复处理。转换是单向的，余额不是可提现资产，不提供余额反向换收益。

提现需另外启用钱包和提现功能。申请时选择推荐佣金或作者收益作为来源，填写真实收款说明并验证密码；申请冻结所选资产，驳回退回同一种资产，不能混入其他资产。外部转账由管理员人工完成后确认，程序不会自动调用支付宝/微信代付。手续费、经营合规、实名和税务需要运营方自行处理。

四、退款和负收益

待结算订单退款，收益变为已冲回，不向作者发钱。已结算后退款，会冲回该订单的作者收益；原订单退款与冲回在同一事务中，重试不重复扣回。关闭分成功能也不能阻止历史订单退款冲回。

如果作者已转换或提现，冲回可能使 earnings 为负。程序保留这笔负债，不为了让数字好看而偷偷挪用买家退款、删除流水或回写旧订单。后续收益先弥补负债；负收益不能继续转出或申请该资产提现。

提现审核确认前会再次检查所选收益资产，若退款造成该来源余额为负，会阻止标记打款完成。管理员应先处理冻结申请、退款争议和真实转账状态。已经在外部打出的款项无法由本程序自动追回，不能把恢复数据库当成撤回真实支付。

建议在业务规则中设置合理的等待期、退款窗口、作者协议和风控核验。本模块是记账/结算实现，不是持牌支付托管服务。

五、阅读记录与隐私

站点模块开关 reading_history_enabled 默认开启；容量 reading_history_limit 默认每人 200 条，范围 20–500。记录仅在登录且页面正文已授权输出后写入，不靠访问未解锁标题创建“已读”。

前台 /index.php?r=history 只查询本人数据，提供卡片、进度、删除单条、清空和个人关闭。个人关闭同时清空历史，不影响收藏；后台没有查看任意用户阅读历史的页面。管理员/数据库运维人员仍可能从其权限读取数据库，不能把“本人页面隔离”宣传为对站点运营者端到端加密。

浏览器按阅读高度估算 0–100% 进度，首次与节流滚动时提交，最多约 45 秒一次，页面隐藏时尽力补交。进度只增不减；它不是阅读证明、任务领奖证据、课程考试记录，也不自动把滚动条恢复到精确段落。关闭页面瞬间的网络可能未送达，因此进度是尽力记录，不承诺每个像素都保存。

记录容量在后续记录时裁剪，不需要 cron。无 JavaScript 时可以查看和管理历史，但不会自动采集滚动进度。

六、关注动态与搜索

关注动态 /index.php?r=following 依照当前用户已关注作者的内容生成，继续执行原有发布、分类和权限过滤；取消关注后下一次读取即变更。它是按作者聚合的时间列表，不是 WebSocket 消息流或社交推荐算法，也不会在列表里泄露收费正文。

搜索联想默认随搜索模块开启。search_suggestions_enabled 独立控制弹框增强；至少输入 2 个字符，延迟 200ms 合并输入，最多展示 6 条。中文输入法在组词阶段不发请求；迟到的旧响应不能覆盖新结果，关闭弹框会使未完成查询失效。

联想使用原有内容检索，只取标题、公开摘要和标签等当前可展示元数据；不检索受保护正文。部分内容公开标题可以作为购买入口展示，这不代表已解锁正文。没有外部搜索服务依赖，不等于 Meilisearch 的分词、纠错、权重和大规模索引能力。

上下键选择，Enter 打开选中结果，Escape 先清空结果再关闭搜索；没有 JavaScript 仍可使用原来的页面搜索表单。请求失败不伪造结果。浏览器组件测试包含模拟乱序响应，而真实 HTTP 套件单独测试了服务端搜索权限、开关和结果字段。

七、设置与验收

新导航目标「创作中心、阅读历史、关注动态」可在后台菜单管理选择；模块关闭时入口随导航权限隐藏，直接访问仍执行服务端开关校验。

先用隔离账号验收「批准作者 → 付费投稿 → 审核 → 买家购买 → 等待/结算 → 提现驳回 → 退款冲回」，核对所有资产流水和订单状态。再测试其他作者无法结算别人的收益、其他账号看不到阅读历史、关闭记录后无新增、关闭模块后接口拒绝。真实商户付款与人工打款必须另外小额验证。

账户安全、会员定价与部署自检（0.14 基础，0.15 更新）

本章对应可实际操作的前后台模块。业务实现独立，不依赖 WordPress、短信平台、第三方二维码网站、任务队列或新增常驻进程。

一、账户安全中心

前台登录后进入“我的 → 安全中心”，实际路由为 /index.php?r=security。后台用户也使用相同账户与登录验证；可以从后台进入前台个人中心操作。全站设置在“用户”分组控制是否允许新绑定。

绑定时间型身份验证器

输入当前密码后开始绑定。页面显示密钥，在自己的身份验证器中选择“手动输入密钥/时间型”：SHA1、6 位、30 秒。本项目不生成远程二维码，也不会把密钥发给二维码网站。不要把密钥、截图或生成的验证码发送给客服或其他人。

待绑定流程 10 分钟过期，且绑定当前账户、会话版本。再次输入当前密码与验证器中的当前验证码完成启用。成功后会撤销其他会话，本浏览器继续登录，并显示 8 个恢复码。

恢复码只展示一次、每个只能使用一次；先保存在与密码分离的离线安全位置再离开。数据库中保存其带站点密钥的摘要，不保存可直接使用的明文；身份验证器密钥使用站点加密服务保存为密文。

登录与防重放

已绑定用户在正常登录表单填写密码，并在“身份验证器或恢复码”栏提供证明。没有绑定的账户仍按原密码流程登录。

采用当前时间步前后各一个窗口容忍时钟偏差。绑定时刚用过的码已经被消费，立即再做受保护操作时要等待下一个时间步，或者使用尚未消费的恢复码。已接受的时间步不能再次使用；恢复码在同一账户事务锁下只消费一次，外层事务失败会恢复消费状态。

服务器和验证器时钟需同步。不要为方便而把验证窗口无限扩大。恢复码无自动到期日，但可以轮换、解除绑定或在恢复后重新绑定；被泄露时立即处置。

管理与恢复

“替换恢复码”要求当前密码与当前第二因素，生成八个新码，旧码全部立即失效；“解除绑定”也要求两项验证。“退出其他登录”在已绑定时同样要求第二因素，撤销其他会话但保留当前浏览器。

邮箱找回密码不会移除身份验证器；关闭全站新绑定入口也不会跳过已启用的保护。 没有设置一个可从 HTTP 调用的管理员万能解除接口。

手机丢失但有恢复码：用恢复码登录，在安全中心使用另一枚恢复码完成解绑或轮换，再绑定新设备。两个操作不能重复使用同一个码。

手机与恢复码都丢失：站点所有者可在有本地命令权限的环境，备份后使用完整包中、Web 根目录之外的工具：

php tools/recover-authenticator.php /absolute/path/to/site USER_ID CONFIRM-REVOKE-ALL-SESSIONS

该命令读取已安装站点配置，移除指定用户的身份验证器、递增会话版本并写审计；不修改密码。必须由有文件/数据库管理权限的站点所有者执行，不能把此工具复制到网站公开目录。免费主机没有命令权限时，应事前妥善保存恢复码；丢失后向可信主机管理员申请本地恢复，不提供绕过面板权限的 Web 后门。

本版没有强制全员绑定、硬件通行密钥、WebAuthn、登录设备地理识别或短信；0.15 新增三家第三方登录，见 CONNECTIONS_AND_OPERATIONS.md。TOTP 不是防钓鱼硬件凭据；不要据此承诺账户绝不会失窃。安全中心显示最近 20 条本人 account.* 审计，而不是任意用户的登录设备清单。

标准与算法测试参考：RFC 6238，https://www.rfc-editor.org/rfc/rfc6238.html 。本轮验证 SHA1 标准向量、窗口、重放、恢复码并发以及实际 HTTP 登录流程，没有宣称所有外部身份验证器产品均完成实机联调。

左侧列出近期 300 条可选内容；较旧内容可直接填内容编号。右侧配置 VIP 1–3 的付款比例与限时活动。页面使用规则修订号，另一窗口先保存后，旧窗口提交会报冲突而不是静默覆盖。

金额与比例

10000 原价 1000 分
8000 付原价 80%，即八折 800 分
6000 付原价 60%，即六折 600 分

优惠券

券新增可选范围：全部、内容、会员套餐；可指定单个内容编号、开始时间和最低会员等级。原有到期、全站次数、最低金额及每账户一次限制仍保留。券仅用于余额计价，不能对积分、代币或零价订单硬套金额券。

默认不允许券叠加已经生效的会员价或限时价。开启“优惠券叠加”后，单张券在当前特别价格上扣减；不是多张券相叠、满赠或跨店活动。

券额度锁定和次数增加发生在真正购买事务中。报价接口不消耗券；购买金额超上限、余额不足或其他后续步骤失败，预留次数随事务回滚。已用券的历史使用记录不会因退款自动变成“从未使用”。

页面报价与成交快照

单件购买页面先由服务端输出实际价格，JavaScript 不是显示金额的唯一来源。选择规格或输入优惠券后可点“核对优惠”；异步请求取消、防抖与序号校验防止旧响应覆盖新确认，返回文字以文本插入。

报价只供确认，不锁定价格、不预留库存、不扣款。提交仍由服务器重新计算。支持的单件购买表单携带最高确认金额：最终应付更高时返回 409 并不扣款，要求重新核对；金额更低时正常按更低值扣款。篡改这个上限不能强迫服务器用低价成交，只能造成拒绝。

**边界：**购物车页面汇总也用同一计价器，实际整车购买在事务中重新计价，0.15 已增加按三种资产分别校验的整车最高确认金额，超限整单回滚。禁用 JavaScript 的多规格表单仍可提交真实购买，却没有在切换选项时同步最高确认金额的增强逻辑；应核对选项与最终订单，不能把单件增强说成所有入口都锁价。购物车暂不提供优惠券输入。

新订单保存基础金额、会员等级、来源、比例、规则编号/修订号与券扣减快照。退款按原订单实际支付额退回站内资产，后续调价不改变旧单；作者收益与推荐佣金也沿用实际订单金额。没有把页面临时试算写成支付已成功。

本版不提供按会员等级填写固定绝对售价、升级补差/剩余天数折算、访客购买、阶梯量价、秒杀排队/库存预占、满赠/多券叠加、复杂运费或自动支付平台退款。

自检实际执行：运行时及 64 位检查、PDO 是否原生、基础扩展、AES-GCM 加解密、密码哈希、中文/64 位整数参数绑定、临时行写入后回滚并验证不存在。MySQL 在有权限时额外检查应用表是否 InnoDB；检查存储是否可写、配置网址是否 HTTPS。

自检不会主动向外部商户发钱、发邮件、申请证书或扫描公网目录；配置写着 HTTPS 不代表证书已有效。需要另查 /app/、/storage/ 等敏感路径访问保护、TLS、上传执行限制、真实收款和邮件。测试适配器会明确显示非原生警告，不能拿它当 PDO/MySQL 认证。

这项基础自检不是对所有 PHP 小版本的全模块测试，也不会修复主机配额、扩展缺失或面板权限。生产不依赖测试 FFI，不要求为自检开通 shell、进程执行或网络下载能力。

全局时长允许 0–1200ms。0 表示这些时间动画立即完成，入场不保留交错等待；物理弹簧和持续装饰由各自开关及物理参数控制。要完全静止，请关闭动效总开关或使用系统减少动态效果，不把 0ms 与关闭所有连续装饰混为一谈。

2. Google / GitHub / Microsoft 登录

在对应平台创建 Web 应用，使用自己的 client ID 和 client secret。后台连接中心会显示按实际站点网址生成的回调地址，必须原样登记，例如：

https://your-domain.example/oauth.php?provider=google
https://your-domain.example/oauth.php?provider=github
https://your-domain.example/oauth.php?provider=microsoft

先确认安装配置中的站点 URL 是真实 HTTPS，再保存密钥并开启总开关和单个平台开关。测试应用请按平台规则添加测试账号；外部应用未发布时不等于所有访客都能授权。

Google 请求 openid profile，GitHub 请求 read:user，Microsoft 使用 common 端点和 Graph User.Read。Microsoft 应用的账户类型需允许实际登录的个人或组织账户；组织策略可能要求管理员同意。这三个驱动不是任意 OIDC、GitHub Enterprise、QQ、微信或抖音登录适配器。

**已有用户：**先用本地密码登录，到安全中心绑定；需验证当前密码，已开启双重验证时还需验证器或恢复码。**新用户：**授权后仍需完成本地用户名、邮箱、密码和条款；站点的邀请码、邮箱验证与注册限额仍然生效。

不会仅因外部账号和本地账号邮箱相同就合并。已绑定身份的登录也不会跳过本地双重验证。不持久保存访问令牌或刷新令牌；身份以平台、应用和稳定标识的摘要关联，不用显示名判断身份。授权 state 和完成凭据 10 分钟后失效，共用 PKCE S256。

解绑需当前密码与已启用的第二因素，并撤销其他旧会话。这仅删除本站关联，不代替用户在平台安全页撤销应用授权。关闭新登录开关不会删除原关联；用户仍可用本地密码登录后解绑。

主机需允许出站 TLS socket、DNS 和公网 443，配置正确 CA 信任。程序不需 cURL、Composer 或 allow_url_fopen，也不会在连接失败时关闭证书校验。不跟随跨域重定向，拒绝内网端点和非 443 端口，限制响应大小与超时。域名 DNS 当前通过 IPv4 解析；纯 IPv6 DNS 主机需另行适配与验收。

3. 易支付主动查单

适用于经典易支付余额充值订单，不是所有同名支付网关通用接口。在易支付设置中开启主动查询，填入商户提供的 API 地址，通常是 https://gateway.example/api.php。它必须与订单原收银台同 HTTPS 域名，不含查询参数。程序发送 act=order、pid、key、out_trade_no。

用户在本人订单页点击查单，管理员也可在连接中心输入订单编号检查。服务端校验商户、订单、支付通道、精确金额和已支付状态后，调用与异步通知相同的入账服务。回调与查单竞争、重复查单不重复加钱。未支付、超时和信息不匹配都不会假装成功。

使用原订单的商户与密钥快照；查询地址也随新订单保存。旧订单未保存地址时可使用当前地址，仍必须满足原网关同域约束。已过期充值单如有真实付款证据可恢复入账，不用于有稀缺库存的商品预留。

每单每分钟最多 6 次，每操作账户每小时 30 次，已入账订单直接返回当前状态。查询结果和审计不记录密钥。这是按需查单，不是定时全量对账、自动退款、代付或 CodePay 主动查询。请先用自己的商户完成真实小额与重复通知验收。

快照只包含集中设置，不包含用户、商品、订单、资产、布局数据、附件或 app/config.php。**它不是整站备份。**数据库只保留最近 30 份，重要版本请及时导出并离线保存。

先保存基线快照，再修改设置。恢复前预览差异，密钥只显示已隐藏标记，不输出原文。输入当前密码及已开启的第二因素后恢复，系统会先自动保存当前配置。如预览后有人修改设置，恢复将拒绝，需重新核对。

0.16 交易、物流、会员与任务操作手册

先在隔离测试站操作。真实支付、代付、翻译和对象存储默认关闭。开关开启并不代表外部服务已开通；不能用伪造成功回调验收收款。

一、首次启用的顺序

先在“设置 → 统一结算”确认站点结算币种。默认 CNY；订单或资金活动出现后禁止随意更换，避免把人民币余额改成美元余额。没有自动换汇。旧 CNY 站点不应为开 PayPal 直接篡改数据库币种。

确认商品使用余额计价、真实库存、交付说明、退款政策。积分／代币保留原来的站内购买流程。新结算一次最多 20 行、100 单位；数字权限与会员不作为重复批量商品。交易拆成逐单位订单，共享一次外部付款，便于单位级售后。

先使用站内钱包或免费商品验收；再开一个直连测试渠道；验证付款、重复通知、超时查询、交付、退款和对账后才启用生产凭证。外部服务操作文档见 PAYMENTS.md。

二、访客下单与找单

访客填写联系邮箱、选择商品并复核总额。确认后系统生成随机 64 位十六进制私密通行证，保存在该浏览会话，并可从“访客订单”展开查看／复制。任何持有者都能访问这组购买记录，因此应像密码一样保存。

通行证不是登录账号，不赋予资料、管理、会员或社区登录权限。邮箱只用于联系方式，不允许只凭邮箱枚举订单，也不会自动发送通行证邮件。丢失后由商家核对真实付款证据人工处理，不提供知道邮箱即可重置的捷径。

访客付款可用已配置的官方渠道；非零金额不能借用不存在的站内余额。会员购买要求正式账号。已有账号可登录后显式“认领访客购买”；必须确认，且存在未解决的待支付单时不可认领。认领成功后旧通行证失效。

三、运费模板

后台“运费与促销”维护模板，并把模板绑定到实物商品。重量单位为克；金额单位为站点最小货币单位，例如 CNY 的分。示例可直接用于模板的 JSON 输入：

{"mode":"weight","default":{"first":1000,"first_fee":800,"step":500,"step_fee":300,"free_above":19900},"zones":{"CN-XZ":{"first":1000,"first_fee":2000,"step":500,"step_fee":800,"free_above":0}}}

含义：普通地区首 1000 克 8 元，每增加 500 克加 3 元，达到模板内商品应付 199 元免邮；CN-XZ 使用独立费率。free_above:0 表示不启用满额免邮，不是无条件免费。

按件设置 mode:"piece"，首件、续件分别用 first、step 表示。固定运费设置 mode:"fixed"。default:null 配合限定 zones 可以拒绝未列地区；没有默认也没有地区是无效模板。地区代码由你定义并告知买家，例如 CN-GD；地址中的自由文字不会自动地理编码。

相同模板的实物商品合并计费，再按订单单位分摊；退款按照当时快照的金额处理，不按今天的新运费规则重算。若关闭运费模块或商品未绑定模板，应在运营前确认是否符合你的包邮规则，不要误开零运费。

四、组合优惠

规则带 group。同组只采用对买家更有利的一条，不同组按确定次序在剩余金额上叠加。所有折扣使用整数，分摊后的单位金额之和等于订单金额。

{"type":"threshold_fixed","group":"order","min_amount":10000,"discount":1000,"item_ids":[]}

满 100 元减 10 元。以下是第二件半价：

{"type":"nth","group":"quantity","min_amount":0,"nth":2,"discount_bps":5000,"item_ids":[12]}

discount_bps 是减免的万分比，5000 为减半；item_ids 为空表示不按商品 ID 限定，非空只匹配所列商品。其他类型的完整字段模板可在后台“运费与促销”选择示例并编辑，服务端会再次验证类型、数值、作用范围和修订号。

“买 X 送 Y”是现有购物篮的价格优惠，不会凭空给订单添加赠品，不是拼团。优惠券只允许单单位、已登录用户使用，并遵守原有叠加限制。发布促销前应测试同组、跨组、会员价、券、运费和库存同时存在的组合。

五、售后与原路退款

买家在收据页发起退款、退货退款或换货，并填写原因；可以关联属于自己的媒体作为证据。默认申请窗口为 30 天，可后台调整。实物已发货的退货应选择寄回流程，不把“已发货”直接当作未履约取消。

后台“售后与退款”要求管理员密码，启用双重验证的账户还需验证码。审核通过：仅退款进入退款队列；退货退款／换货进入等待寄回。买家填写运单，商家检查收货并选择是否可再次销售。换货仅支持同商品同 SKU；检查库存后再录入补发运单，买家确认收货后完成。状态和修订号防止旧页面重复审核。

退款以一个单位订单的全部成交额为准，包含它分摊的运费。本版不提供任意金额部分退款或按政策自动扣除退货邮费。站内钱包支付退回原站内资产；直连支付进入原网关退款，不同时给站内余额入账。确认外部成功后才撤销交付权益、处理库存／邀请码、冲回收益和佣金。已发卡密不会自动重新出售；已使用邀请码阻止自动退款。

网络超时是“不确定”，不是失败或成功。退款会保留固定退款号，后续先查询；不能手动把未知退款改成已完成以消除红色状态。确认为失败的单保留商家处理记录；在商户后台查清资金后由受控人工流程解决，勿直接修改金额或订单状态。

旧版“订单 → 退款”仍用于原来的站内订单；新统一结算单导向新售后入口。外部充值退款和普通会员整单撤销不在这套商品自动售后范围。

六、永久会员与补差

套餐天数为 0 表示永久，VIP 1–3 仍各自记录期限。本版新购会员会记录付款权益批次，补差依赖该批次而不是猜测用户当前等级。有限期批次的可抵扣价值按剩余时间比例向下取整；永久批次按后台保留价值万分比折算。

两个模式：“新周期”购买目标套餐的新完整期限；“保留到期日”在当前有效期限内升级。最终抵扣不超过目标应付价值，超出的残值不退现金、不另存余额。只能向更高级升级；永久批次不会被错误降成有限期，永久升级要求适当的永久目标套餐。报价带签名与 5 分钟时效，付款时再次验证会员、套餐和来源批次，旧标签页不能沿用已变化权益的报价。

例如源年卡 100 元、剩余约 180／365 天，可抵扣约 49.31 元；目标新年卡 200 元，新周期应付约 150.69 元。实际代码按秒、最小货币单位计算，以页面最终报价为准。保留到期日模式还会按同一剩余期限折算目标价格，不能套用新周期示例。

本版补差结算走站内资产；普通新会员套餐可用统一外部支付。历史订单需后台核验其实际付款、开始时间与截止时间后导入可追溯批次；导入不是人工制造新权益。补差退款仅退本次补付款，并核对权益是否仍属于该次升级；之后人工授予或再购买的权益不会被覆盖。复杂混合券包、组合服务权益与所有历史规则不属于本版支持范围。

七、主动查单、自动任务与代付

后台“交易控制台”可查单；“售后与退款”可处理退款和提现任务。普通页面浏览不悄悄批量调用外部付款 API。任务执行器一次处理 1–10 项，支付、退款、代付按最久未处理项推进；没有强制常驻队列。

VPS 可使用完整包里的 tools/run_jobs.php，调用方法见脚本自身提示。共享主机可由你控制的调度器向 jobs.php 发送签名 POST：JSON 正文如 {"limit":1}，请求头 X-CY-Time 为 Unix 秒、X-CY-Nonce 为随机 32 位十六进制、X-CY-Signature 为下列字符串的 HMAC-SHA256 十六进制摘要：

时间戳 + "\n" + nonce + "\n" + SHA256(原始请求正文)

密钥来自后台“自动任务”的 jobs_secret，至少 32 字符；时间差不超过 300 秒，同一时间戳与 nonce 不能重放。不要把密钥放进 URL，也不要把它交给不可信免费定时平台。本包附 tools/trigger_jobs.php，在可运行 PHP 的可信机器上生成签名请求，不要求站点本身有 SSH。

示例仅为形态，不是可用凭证：

R2:  https://your-account.r2.cloudflarestorage.com/your-bucket

标准化账单格式与差异处理

本模块用于人工准备数据后的只读核对，不是会计软件，不会改变资产。禁止把不明来源的文件当作支付成功依据。

CSV 必须是 UTF-8（可带 UTF-8 BOM），英文逗号分隔，表头严格如下：

event_type,reference,trade_id,currency,amount_minor,state,event_at
payment,LOCAL_SALE_NO,PROVIDER_TRADE_ID,CNY,100,succeeded,2026-09-07T10:00:00+08:00
refund,LOCAL_REFUND_NO,PROVIDER_REFUND_ID,CNY,100,succeeded,2026-09-07T11:00:00+08:00

这里的号码是格式示例，不是真实交易。不要直接用示例“核对”生产账单。

字段 规则
event_type payment 或 refund
reference payment 对应 cy_sales.sale_no；refund 对应 cy_refunds.refund_no，不是网站单位子订单 order_no
trade_id 渠道交易号或退款号。成功行必须非空；允许字母数字和 . _ : -，最长 191
currency CNY、USD、EUR、GBP、HKD、SGD、CAD、AUD；本模块只处理这些两位小数币种
amount_minor 非负整数，不含千分位、货币符号或小数点。100 表示该币种 1.00；最大 12 位
state succeeded、pending 或 failed
event_at ISO 8601，必须有秒和时区，如 Z 或 +08:00；不能使用含糊的本地时间

reference 最长 80 位，只接受字母数字开头及 . _ : -。拒绝公式前缀和不合法引用。每个导入文件，同一 event_type+reference 只接受一行；先选定同一事件的最终状态，再导入。文件最多 2 MiB、2000 条，跨度不超过 31 天。包含窗口起点，不包含窗口终点。

必须先把服务商导出列转换成上面的名称与含义。绝不能把“到账净额”当作订单毛额、把人民币转换后金额贴上美元币种、把支付交易号当作退款号。时区要与导出账期一致。渠道会在支付后产生退款记录；二者分别对应 payment/refund。

核对优先级：不存在 → 币种 → 金额 → 交易号 → 状态 → 入账/退款凭证 → 完成时间。一个行显示当前首先遇到的差异，修正原因后可重新核对。仅本地存在可能是导出范围、时间边界或平台延迟，也可能是真正缺失；先核实，不能直接判定资金丢失。

本地反向扫描超过 2000 条缺失记录时会拒绝这个范围，缩小账期后再导入。比较使用站点支付成功和退款更新时间，不保证与渠道清算日一致。“匹配”只表示这些字段一致，不代表银行清算、平台争议或退款终局已核验。

数据库只保存规范化行、文件摘要和核对结果，不保存原始 CSV 文件。审核账号仍可读取交易引用，应最小化后台权限。若需要原始账单留档，请保存在 Web 根目录之外的受控存储。

操作复核：先做一个正确样本，再分别修改一项金额/币种/交易号/状态/时间，确认报告识别；重复导入应回到同一批次；所有这些操作后余额和订单不应发生变化。

外置 Meilisearch

后台“设置 / 发现”选择 meilisearch，填写公开可达的HTTPS接口、专用 cy_ 前缀索引和服务端API密钥，确认同意发送公开元数据和用户搜索词。服务必须在另一个可运行搜索进程的服务器或托管服务上；免费共享主机只运行PHP连接器，不需要在主机安装Docker。服务成本、数据处理与访问配额由你与提供商决定。

接口只接受HTTPS、443端口和公共IP解析，不能填localhost、私网、带用户名密码或查询参数的地址。VPS上的同机服务也需经受保护的HTTPS入口接入；不能关闭校验去访问内网。API密钥只留在服务端，给该专用索引配置搜索、文档写入/删除和任务读取所需的最小权限，不使用公开主密钥。

在“搜索工作台”先点击“加入下一批25篇”，逐批建立同步队列。然后“处理一个到期任务”，或启动一次最多12次请求的短同步会话。关闭或隐藏页面会停止继续发请求；队列在数据库保留。请求受理后不标记完成，之后必须取得远端任务成功状态；失败保留并退避重试。长时间无人管理需配置真实调度，并开启 meili_jobs；没有调度就不能保证及时同步。

同一文档变化会合并到同一队列项，并记录版本。只同步可匿名列出的已发布内容：标题、摘要、标签、当前有效中英译文标题与摘要。正文、付费正文、私信、账户、订单、笔记和工单不发送。归档、下架或权限变化会排队删除。

一个订单多个包裹

切换顶部包裹卡可查看或修改指定包裹。变更运单只清除该包裹旧轨迹，不影响其他包裹。人工更新需含时区的时间、文字说明；远端快递100查询保留原签约、显式同意、间隔和单号匹配检查。

这是多运单与轨迹管理，不包含每箱商品数量分配、跨SKU换货、多仓库存、电子面单、退件独立轨迹或承运商自动订阅。

后台创建与下载

进入后台“恢复副本”，输入单独的16–256字节备份密码、再次输入确认，选择是否含本地媒体，再提供当前管理员密码与已启用的TOTP/恢复码。确认归档包含敏感数据后创建。下载和删除也要求当前凭据复验，不能仅凭登录Cookie执行。

归档使用PBKDF2-SHA256派生独立密钥和逐记录AES-256-GCM认证加密；每条记录绑定序号、前一记录认证标记与头部，末尾清单用于检测截断、乱序或追加。解析只接受已知表名和严格的本地文件键，不执行归档里的SQL、PHP或序列化对象。

服务器文件使用随机名称、PHP停止执行封装与私有目录权限；下载移除封装，扩展名为 .cybackup。下载前检查目录记录的SHA-256。将归档移出服务器，密码放在另一安全位置。文件和密码同时丢失无法恢复；不得放进源码仓库或普通邮件。

默认归档上限64MiB、保留最近3份成功副本；可在安全设置调到8–512MiB、1–10份。创建请求有最多约20秒的安全预算，并提前考虑主机执行时间；大站、慢主机或大媒体请用主机/数据库备份工具，不反复提高超时硬撑。只读一致性事务会持有快照，操作时尽量停写。

离线检查

将完整包解压到本地可信环境或隔离VPS。工具只接受CLI，不能通过浏览器运行，tools/ 不放到网站公开目录。下例应用目录为 /srv/chengyu/site，没有连接生产站点：

php /srv/chengyu/tools/recover-backup.php inspect /srv/chengyu/site /private/copy.cybackup

工具从标准输入读取备份密码，不把密码写进命令参数或历史记录。普通终端可能回显输入；类Unix终端可使用关闭回显的方法：

old=$(stty -g) || exit 1
trap 'stty "$old"' EXIT HUP INT TERM
stty -echo
php /srv/chengyu/tools/recover-backup.php inspect /srv/chengyu/site /private/copy.cybackup
stty "$old"
trap - EXIT HUP INT TERM

随后输入备份密码并回车。不要把密码作为工具第三/第四参数。自动化输入只能来自权限严格的私有文件或秘密管理器，完成后按你的密钥制度销毁。Windows终端可使用私有标准输入文件；不要套用 stty。

检查输出只包含版本、数据库类型、记录/文件数等摘要，不输出原密钥和私密记录。错误密码、认证标签变化、路径穿越或不完整末尾会直接拒绝。

恢复到空目标

准备同类型空数据库，创建一个仅在本地可信目录的PHP连接文件，例如 /private/target-database.php：

<?php
return [
    'driver' => 'mysql',
    'host' => '127.0.0.1',
    'port' => 3306,
    'name' => 'chengyu_rehearsal',
    'user' => 'rehearsal_user',
    'password' => 'REPLACE_WITH_TARGET_DATABASE_PASSWORD',
];

使用上节相同的标准输入方式输入密码。工具先完整验证归档，再检测空库，从当前可信代码建立结构、事务写入数据、逐片恢复并核对媒体，最后生成新的私有配置。已有任何数据表会拒绝。MySQL DDL不能全部回滚；失败可能留下空表或未发布目标数据，重新演练应换一个干净目标，不能把半恢复站点直接上线。

安装页展开“当前主机的 PHP 运行限制”，已安装站点到后台系统页运行能力检测或下载 JSON。会读取内存、上传、POST、输入及执行时间、文件上传开关和输入字段数量。max_input_time=-1 按继承执行时间处理；数值解析兼容所有目标 PHP 版本，避免整数溢出。

这些数据来自 PHP，本程序不能据此推断主机账号的实际空间、数据库配额、流量、Web 服务器请求大小或代理超时。检测不会更改主机配置，也不会自动隐藏业务模块。
