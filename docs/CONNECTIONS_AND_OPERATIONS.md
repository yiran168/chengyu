# 0.15.0 账号连接、主动查单与配置快照

这是真实业务代码的使用说明，不是外部平台已完成联调的证明。新功能不按 PHP 小版本关闭，但网络、密钥、证书和平台审核条件必须真实满足。

## 1. 统一入口

| 位置 | 地址 |
| --- | --- |
| 后台连接中心 | `/admin/index.php?tab=integrations` |
| 社交登录配置 | `/admin/index.php?tab=settings&group=connections` |
| 配置快照 | `/admin/index.php?tab=configuration` |
| 徽章管理 | `/admin/index.php?tab=badges` |
| 用户安全中心 | `/index.php?r=security` |
| 公开徽章展馆 | `/index.php?r=badges` |

子目录部署需在路径前加子目录。后台已按工作台、创作、社区、交易、体验分组，搜索框支持 Alt+/ 定位，清空搜索后恢复原分组状态。无 JavaScript 时仍可用原生折叠与链接。

## 2. Google / GitHub / Microsoft 登录

在对应平台创建 Web 应用，使用自己的 client ID 和 client secret。后台连接中心会显示按实际站点网址生成的回调地址，必须原样登记，例如：

```text
https://your-domain.example/oauth.php?provider=google
https://your-domain.example/oauth.php?provider=github
https://your-domain.example/oauth.php?provider=microsoft
```

先确认安装配置中的站点 URL 是真实 HTTPS，再保存密钥并开启总开关和单个平台开关。测试应用请按平台规则添加测试账号；外部应用未发布时不等于所有访客都能授权。

Google 请求 `openid profile`，GitHub 请求 `read:user`，Microsoft 使用 `common` 端点和 Graph `User.Read`。Microsoft 应用的账户类型需允许实际登录的个人或组织账户；组织策略可能要求管理员同意。这三个驱动不是任意 OIDC、GitHub Enterprise、QQ、微信或抖音登录适配器。

**已有用户：**先用本地密码登录，到安全中心绑定；需验证当前密码，已开启双重验证时还需验证器或恢复码。**新用户：**授权后仍需完成本地用户名、邮箱、密码和条款；站点的邀请码、邮箱验证与注册限额仍然生效。

不会仅因外部账号和本地账号邮箱相同就合并。已绑定身份的登录也不会跳过本地双重验证。不持久保存访问令牌或刷新令牌；身份以平台、应用和稳定标识的摘要关联，不用显示名判断身份。授权 state 和完成凭据 10 分钟后失效，共用 PKCE S256。

解绑需当前密码与已启用的第二因素，并撤销其他旧会话。这仅删除本站关联，不代替用户在平台安全页撤销应用授权。关闭新登录开关不会删除原关联；用户仍可用本地密码登录后解绑。

主机需允许出站 TLS socket、DNS 和公网 443，配置正确 CA 信任。程序不需 cURL、Composer 或 `allow_url_fopen`，也不会在连接失败时关闭证书校验。不跟随跨域重定向，拒绝内网端点和非 443 端口，限制响应大小与超时。域名 DNS 当前通过 IPv4 解析；纯 IPv6 DNS 主机需另行适配与验收。

## 3. 易支付主动查单

适用于经典易支付余额充值订单，不是所有同名支付网关通用接口。在易支付设置中开启主动查询，填入商户提供的 API 地址，通常是 `https://gateway.example/api.php`。它必须与订单原收银台同 HTTPS 域名，不含查询参数。程序发送 `act=order`、`pid`、`key`、`out_trade_no`。

用户在本人订单页点击查单，管理员也可在连接中心输入订单编号检查。服务端校验商户、订单、支付通道、精确金额和已支付状态后，调用与异步通知相同的入账服务。回调与查单竞争、重复查单不重复加钱。未支付、超时和信息不匹配都不会假装成功。

使用原订单的商户与密钥快照；查询地址也随新订单保存。旧订单未保存地址时可使用当前地址，仍必须满足原网关同域约束。已过期充值单如有真实付款证据可恢复入账，不用于有稀缺库存的商品预留。

每单每分钟最多 6 次，每操作账户每小时 30 次，已入账订单直接返回当前状态。查询结果和审计不记录密钥。这是按需查单，不是定时全量对账、自动退款、代付或 CodePay 主动查询。请先用自己的商户完成真实小额与重复通知验收。

## 4. 加密配置快照

快照只包含集中设置，不包含用户、商品、订单、资产、布局数据、附件或 `app/config.php`。**它不是整站备份。**数据库只保留最近 30 份，重要版本请及时导出并离线保存。

先保存基线快照，再修改设置。恢复前预览差异，密钥只显示已隐藏标记，不输出原文。输入当前密码及已开启的第二因素后恢复，系统会先自动保存当前配置。如预览后有人修改设置，恢复将拒绝，需重新核对。

导入和导出同样需身份二次确认。`.cysettings` 档案使用原站 `secret` 加密，只能由保留原密钥的站点打开；不是新建其他站点的可移植主题包。损坏、伪造、非本站密钥、超过 400KB 或含未知版本设置的档案会被拒绝。恢复使用与平时保存相同的校验和事务，不直接执行任意 SQL。

## 5. 永久会员与价格确认

后台会员套餐的天数填 0 表示永久，1–3650 表示指定天数。系统使用明确的永久标记时间 `253402214400`，不是简单给十年。前台显示永久，三个等级仍保持各自期限。永久高级会员不能重复付款买同级或更低级的重复权益；同级临时授予不会缩短永久权益。永久会员不自动获得所有付费内容，仍尊重内容自己的权限规则。

本版不按剩余天数自动补差升级，不自动原路退回会员订单。价格确认现在同时带上币种与金额；整车为余额、积分、代币分别提交最高确认额，服务端重算后超额会回滚整单。这不是锁价或预留库存；价格上涨时刷新核对后重新提交。旧的自定义表单如不提交上限字段，不自动获得该确认保护。

## 6. 社区徽章

管理员创建徽章，选择固定安全图标、配色、排序和启用状态，再按用户 ID 授予。到期时间留空表示不自动到期。同人同徽章仅一条，更新期限不重复新建。可撤销指定用户的徽章，或停用整个徽章。徽章最多 200 种，后台近期授予列表显示 30 条，其余记录可按用户与徽章 ID 撤销。

公开展馆与个人页排除过期授予、停用徽章和停用账户。徽章只是社区荣誉，不改变角色、会员、资产、下载或管理权限。暂无按任务自动发放规则，不把手工荣誉等同法定身份认证。

徽章与连接图标使用有限次动效，不连续空转；尊重共用曲线、时长、扫光开关、减少动态效果和低资源模式。不强制用户等动画播完才进行交易。

## 7. 故障排查与验收

回调不匹配：核对站点 URL、子目录、HTTPS、端口和应用登记的完整地址。不要在一次授权中修改应用密钥，配置变化会使该次授权失效。会话丢失：确认同一浏览器、Cookie、同一域名及反向代理策略；不以关闭 state 检查修复。

TLS 失败：核对主机出站权限、时间、DNS、OpenSSL 和 CA；不禁用证书校验。主动查单被拒绝：先确认是经典协议、充值订单、原商户密钥仍有效，以及网关是否启用查询接口。不要根据付款截图或返回 URL 手动伪造入账通知。

本地协议夹具已检查这些分支，但不是真实平台授权。上线前应实测三家平台的注册、绑定、登录、双重验证与解绑，主动查单与通知重复到达，以及配置快照和整站备份的各自恢复。

## 原生表单与外部跳转

本站继续保持 `form-action 'self'`，不会为社交登录或支付放开任意域名提交。异步表单收到经过服务生成的外部地址后由浏览器导航；无 JavaScript 的原生表单则结束为一个同源 200 继续页面，而不是直接返回外部 303。继续页在脚本可用时立即导航，没有人为倒计时；脚本不可用时保留真正的 HTTPS 链接，显示目标域名，并设置 no-store、no-referrer 和 noindex。订单继续支付入口也复用此页面。

继续页不是支付成功页，不会触发入账；只有已校验的回调或主动查单能确认支付。它不是接受任意 `target` 参数的公开转发接口。原生 POST 刷新仍由原订单幂等键防止重复建单。此行为已经通过本地 HTTP 检查；当前环境不能完成真实浏览器跨站导航，仍需要在实际域名验收。

设计依据：MDN 对 form-action 后续重定向的浏览器差异说明：https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/form-action 。
