# 0.10.0 新模块使用说明

路径中的“后台”均指根目录部署后的 `/admin`。管理员或相应管理角色才能修改配置，普通用户看见按钮不等于拥有服务端权限。初装示例只是可编辑样本，不是经营成品或真实交易。

## 一、布局工作台

后台进入「布局工作台」，选择首页、文章、社区或商城。布局放在该页面的标准列表区域之前，不替换登录、支付、用户中心等系统页面。

支持 8 类组件：标题、文本、内容卡片、专题卡片、行动按钮、站点统计、友情链接、间距。可设置标题/安全 Markdown、内容或专题 ID、内部跳转、对齐、普通/玻璃/强调表面、显示设备和入场效果。组件可新增、复制、删除、箭头调序或拖动调序；修改后点击发布保存。内置三套起始组合，可进一步修改。

每个位置最多 24 个组件。导出文件是 `chengyu-layout` v1 JSON，服务端限制为 100,000 字节并重新验证所有字段。导入会替换编辑器当前未保存布局，导入前先导出备份。跨站导入必须重新核对内容/专题 ID。布局 JSON 不带支付密钥、数据库密码、HTML 脚本或可执行 PHP；这不是安全运行任意模板代码的沙盒。

两位管理员同时编辑同一位置时，旧版本保存会收到冲突，不会静默覆盖新修改。无 JavaScript 时仍提供受校验的 JSON 编辑入口。此模块是**结构化组件编排器，不是古腾堡、任意拖拽整站或完整所见即所得设计器**。

## 二、多规格商品与卡密库存

在后台创建商品后进入对应「规格」管理。实物和卡密商品可建立最多 100 个 SKU，设置唯一编码、名称、价格、库存、启用与排序；每个规格有自己的库存。页面和购物车会携带明确的规格 ID，不能只传一个随意价格。

卡密商品从库存页选择对应规格，再按行导入，每批最多 500 行。代码加密保存，重复码全局检查，字面字符串 `0` 也是有效卡密。卡密库存从未售代码记录同步计算，不把人工库存数字当作可发放卡密。已有未分配规格的未售码时，先处理原库存再切换规格结构，不能让两类库存并行失真。

前台同一商品的不同规格作为不同购物车条目。购物车最多 20 个条目、总计 100 件；单条卡密/实物数量 1–10，数字授权通常为 1。整车结算使用一个事务，任何商品无权限、售罄或余额不足都会整体回滚，不会只扣钱而留下半张购物车。请求标识与内容指纹用于重复提交保护。

未发货实物退款回到原规格库存。已发出的卡密即使退款也不重新出售。已有有效数字权益不会重复购买；过期的限时权益可以重新购买。更改商品类型可能破坏历史订单，所以存在销量、库存或规格后受限制。

## 三、VIP 1–3 与有效期

后台会员套餐增加等级字段：VIP 1、VIP 2、VIP 3。高等级可访问要求较低等级的会员内容。每个等级独立累计期限，同等级续期从现有到期时间与当前时间的较晚者开始；低等级续费不会顺便延长高级会员。

内容可配置最低 VIP 等级。后台编辑普通资料不会重置或延长会员；需要管理员明确勾选替换期限才进行对应变更。会员未到期并不自动表示可看一切付费资源，仍按内容自身的访问级别和 VIP 免费规则判定。

0.9.0 的单层会员升级时保留为 VIP 1。兑换码赠送的原基础 VIP 仍按其既有语义处理，不是任意指定高级套餐的销售系统。

## 四、付费时限、密码、修订与下载

内容可设置购买权益天数，0 为永久，非零范围为 1–3650 天。订单保存购买当时的到期时间，后续商品改价/改时长不重写旧订单。到期后的正文与私有附件同样重新检查权限。只有真正付费的内容可通过购买解锁，不能对 VIP、回复或密码内容构造零元订单绕过限制。

密码内容使用哈希保存密码，错误输入有限流。授权保存在会话，修改密码会让旧授权失效；此功能不是对共享密码防转发的数字版权保护。

内容编辑使用版本号避免覆盖另一位编辑的更新，并保留最近 20 个文本修订。还原以文本内容为范围，不回退价格、已付款订单、库存或资产账本，不能用于撤销交易。

私有文件经 `media.php` 检查权限再输出，支持单段 HTTP Range：固定段、末尾段、开放尾段，合法返回 206，非法或多段返回 416；HEAD 不发送文件正文。私有存储保护前缀不包含在下载内容与长度中。

后台可以配置每日下载额度及查看下载记录。配额按**已登录用户、当天、不同私有文件**计数；同一天重复获取同一文件及其分段不会重复占用次数，HEAD 不扣次数，管理人员豁免。通过密码获得访问的匿名访客没有稳定用户身份，不能把此额度宣传为对匿名人的可靠日限制。需要身份级配额时使用登录/VIP/购买权限。

## 五、任务中心

后台可建立一次性或每日任务，目标来自实际数据：当天签到、通过审核的评论、已发布且到展示时间的文章/帖子、完善个人简介与显示名。积分与经验奖励独立配置。资料完善仅允许一次性任务，避免同一份资料每天无限领奖。

用户在前台「任务」查看进度并领取，进度未达标不会发放。领取记录、积分账本和经验写入在同一事务内，重复提交不重复发奖。领取过的任务不允许改变目标/周期/奖励规则；停止旧任务后新建规则，防止已发奖励语义变化。此系统没有人工审查任务、外部平台打卡或定时后台自动领奖。

## 六、邀请制注册

后台用户设置可启用注册邀请码要求；邀请码在专门管理页生成，单批 1–100 个，每码最多使用 1–1000 次，并配置到期时间。原始邀请码只在生成后的页面展示一次，应立即保存到安全位置。数据库保存带站点密钥的摘要，不能在后台反查明文。

注册成功和消费邀请码次数处于同一事务，注册失败不会浪费次数；并发使用遵守次数上限。管理员可以停用代码。此模块是**邀请注册**，不是商城购买后自动生成邀请码的商品类型；后者仍未实现。

## 七、专题、友情链接和公告

后台通过专属管理页建立专题，关联最多 200 条内容 ID；前台输出前重新检查内容状态和权限，不把未发布正文拼进专题。不同文章、帖子或商品可根据可见性组合。

友情链接支持名称、描述、分组、顺序和启用，链接只接受安全 HTTP/HTTPS 协议。它不是自动审核站点或检测死链的工具。

公告支持开始/结束时间、展示人群与内部跳转，按请求时刻判断展示，无需定时任务。到期消失不是服务器已经执行过一个后台定时作业。任务、专题、友情链接等有模块开关；其他运营参数由各管理表单配置。

## 八、发货、确认收货与退款逆向

实物订单由后台人工发货，可更正运输信息；所属用户确认收货，重复确认不会重复处理。这里只保存人工填写的数据，不调用物流轨迹 API。

退款仍是本项目支持的站内购买退款，退回原站内资产，撤销该笔订单权益并保留其他有效订单权益。不是支付宝、微信或银行卡原路退款。

推荐佣金的退款冲销允许形成内部负债记录，以免推荐人已提现导致买家永远不能退款；负数佣金不等于普通余额可以透支，也不是自动向推荐人的银行卡追回。运营者应审核此情况并人工对账。提现仍为人工审核/人工打款后确认，不是自动代付。
