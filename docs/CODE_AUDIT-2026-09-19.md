# 代码检查与修复 · 2026-09-19

检查对象是 `chengyu-0.18.0-complete/chengyu` 中的 0.23.0 代码。本轮修复纳入 0.23.1；0.23.0 压缩包不包含这些修改。

## 发现并修复

### P2：合法凭据的首尾空白被删除

后台密钥保存和安装器数据库密码都调用了默认执行 `trim()` 的文本校验。比如 `  password123  ` 会被保存成 `password123`，导致 SMTP 认证或数据库连接失败。已有账号登录密码走专用校验，本次没有发现同一问题。

- `site/app/Core/Support.php`：在共享文本校验中增加可选的不裁剪模式，保留原有长度、UTF-8 和非法控制字符限制。
- `site/app/Core/Settings.php`：密钥按原值加密入库；空字符串继续表示保留旧值，明确勾选清除才删除。
- `site/install/index.php`：MySQL 密码使用同一不裁剪模式。

通过隔离数据库重载和真实本地 TLS SMTP 的 AUTH LOGIN 流程复现并验证。曾被旧版本裁剪的凭据无法自动还原，需要重新输入原始值。MySQL 安装器使用的共享校验已覆盖，但本轮没有另启 MySQL 实例做完整安装认证。

### P2：不存在的文章编辑链接打开了新建页面

登录后访问 `index.php?r=write&id=不存在的编号`，原逻辑将查询不到的文章当作“新建”，返回含新建表单的 HTTP 200 页面，可能导致误建文章。

`site/app/Http/SiteController.php` 现在在指定目标不存在时返回 404。真实 HTTP 测试验证普通会员和管理员均得到 404 且没有新建表单；无编号或 `id=0` 仍可新建，作者和管理员仍可编辑已有文章，其他会员仍被拒绝。
