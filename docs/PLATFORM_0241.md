# 0.24.1 使用与修复范围

本版处理 2026-09-28 独立复核中确认的缺口。没有把原问题清单的所有描述都视为已经证实，也没有修改生产网站、原报告的用户或订单。

## 操作变化

- 流水：后台“流水”按账户编号筛选，记录、总数与分页使用同一条件；用户编辑页提供该用户的流水入口。
- 邀请码：停用后可重新启用，已使用次数保持不变；到期或额度用完的码不能恢复。重复提交同一状态不会新增重复审计。
- 售后：售后申请和退款队列页都可查看待审核的普通钱包订单，展开即可批准或拒绝；与订单详情共用处理表单。输入当前管理员密码，已经启用双重验证时还需验证码或恢复码。
- 双重验证：用户编辑页新增“恢复”入口，要求再次验证管理员并明确目标身份，吊销目标旧会话、旧验证器、恢复码和未使用找回链接。所有管理员均无法登录的虚拟主机场景见 [账户恢复](ACCOUNT_RECOVERY.md)。改密码仍不会自动移除双重验证。
- 表单：异步保存跳转后的成功信息在目标页显示一次；刷新不会重复弹出。上传头像后立即预览，明确提示仍需保存资料；保存后显示已保存状态。
- 游客访问会员升级页会引导登录。售后四个队列标签及待审投稿提示补齐中文。规格管理无可选商品时直接说明需先创建实物或发卡商品。
- 修正已退款普通内容订单被传入“会员升级退款”时误报成功的边界；保留真正会员升级退款的幂等保护。

## 清单中未复现的故障

当前源码下，经过审核发布的付费文章可发现并购买；待审文章仍不向公众展示。备份创建、下载与解密、公告按请求时间显示、实物规格与收货、评论审核展示、两条退款流程、账单导入和登录限流均在隔离样本中完成。修改密码实际生效，确认的缺陷是跳转后提示丢失。

页面构建器的 24 组件上限保持明确限制；数字商品不支持填写物流；搜索不索引受保护正文。普通钱包订单“待退审”与批准后生成的结算退款执行任务是不同状态，本版将入口和说明放在一起，未把两类记录混写。

原始线上样本的确切部署、数据状态与错误日志尚未取得；本地未复现不等于断言原站没有问题。本轮没有新增实际商户支付、生产退款或服务商实例验证。[本版测试](TEST_REPORT.md) / [保留数据升级](UPGRADE.md)。
