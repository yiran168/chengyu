# 作者收益、阅读历史与关注发现

适用 0.13.0–0.14.0。新模块无 WordPress、队列、cron 或额外生产依赖；与旧模块共用数据库、权限、钱包和前后台模板。下面的默认值只适用于未被管理员修改的站点。

## 一、开启作者经营

先到 `/admin` → 系统设置 → 交易与资产分组，开启「作者收益分成」；配置默认分成比例和等待天数。对应设置键为 `creator_income_enabled`、`creator_share_bps`、`creator_hold_days`。比例以基点保存：8000 = 80%，不是 8000%。

在用户管理中编辑指定作者，打开作者资格。`creator_bps=-1` 使用站点默认；0 表示该作者不产生新分成；0–10000 是其独立比例。关闭资格阻止新分成和新的作者自定价，已有收益和历史条款不会被删除。

作者打开个人中心的「创作中心」：
`/index.php?r=creator`。
创作中心提供真实收益摘要、订单收益明细、合资格结算、可选余额转换及提现入口，不是演示金额。后台 `/admin/index.php?tab=creators` 查看所有作者收益，可按作者 ID 筛选；作者资格在用户管理维护，提现在提现审核管理。

付费投稿使用 `/index.php?r=write`。获准作者可对自己的文章或帖子设置余额价格、选择付费保护，将收费内容放入「受保护正文」，提交后仍需管理员审核。公开正文和摘要始终公开，不应放入秘密内容。旧文章只有管理员勾选「允许获准作者管理此价格」后才允许作者修改原定价，避免重置管理员已有规则。

这不是多商家商城入驻。普通作者原有上传权限没有扩大为任意私有文件/视频；普通作者上传图片，受限资源文件继续由有权限的管理员管理。作者不能自行设置所有 SKU、库存、会员特价或支付资产。

## 二、收益如何计算

仅针对实际已支付、余额计价、金额大于零、作者当时具有资格且买家不是作者自己的内容订单。积分/代币购买、免费订单、购买会员和加入圈子，不产生本模块的内容作者收益。

公式（内部单位为分，最终向下取整）：

```text
可分成基数 = 实付金额 - 本单实际推荐佣金
作者收益 = floor(可分成基数 × 作者比例 / 10000)
```

例如实付 100 元、推荐佣金 10 元、作者比例 80%，作者收益是 72 元，剩余 18 元是这两项扣除后的站内差额；这不代表扣除了网关手续费、税费、运营成本或退款损失。

订单创建时保存作者、实际基数、比例、收益、可结算时间快照。以后调整站点比例/等待期、作者资格、文章作者或价格，不追溯改写旧单。升级前订单不批量追补作者分成，也不把原推荐佣金转换成作者收入。

推荐佣金 `commission` 与作者收益 `earnings` 是两种独立账本资产；订单后分成与退款都在现有交易事务内执行，不靠仅显示前台数字完成。

## 三、结算与提现

付费后先显示「待结算」。到达等待期、订单仍已付且没有正在处理的退款，才可结算。实物订单还必须确认收货。作者点击「结算符合条件的收益」，每次最多 50 条，逐订单核验并记入收益资产；超过 50 条可以继续点击，不需要后台常驻队列。

重复点击、重复请求和并发结算不会重复入账。已结算收入统计是历史累计，不等于当前可用收益：提现、转换和退款会改变可用资产。

可选「收益转余额」默认关闭。开启后作者须验证当前密码，按 1:1 将可用收益转入余额，形成对应转出/转入流水；同一请求不重复处理。转换是单向的，余额不是可提现资产，不提供余额反向换收益。

提现需另外启用钱包和提现功能。申请时选择推荐佣金或作者收益作为来源，填写真实收款说明并验证密码；申请冻结所选资产，驳回退回同一种资产，不能混入其他资产。外部转账由管理员人工完成后确认，程序不会自动调用支付宝/微信代付。手续费、经营合规、实名和税务需要运营方自行处理。

## 四、退款和负收益

待结算订单退款，收益变为已冲回，不向作者发钱。已结算后退款，会冲回该订单的作者收益；原订单退款与冲回在同一事务中，重试不重复扣回。关闭分成功能也不能阻止历史订单退款冲回。

如果作者已转换或提现，冲回可能使 `earnings` 为负。程序保留这笔负债，不为了让数字好看而偷偷挪用买家退款、删除流水或回写旧订单。后续收益先弥补负债；负收益不能继续转出或申请该资产提现。

提现审核确认前会再次检查所选收益资产，若退款造成该来源余额为负，会阻止标记打款完成。管理员应先处理冻结申请、退款争议和真实转账状态。已经在外部打出的款项无法由本程序自动追回，不能把恢复数据库当成撤回真实支付。

建议在业务规则中设置合理的等待期、退款窗口、作者协议和风控核验。本模块是记账/结算实现，不是持牌支付托管服务。

## 五、阅读记录与隐私

站点模块开关 `reading_history_enabled` 默认开启；容量 `reading_history_limit` 默认每人 200 条，范围 20–500。记录仅在登录且页面正文已授权输出后写入，不靠访问未解锁标题创建“已读”。

前台 `/index.php?r=history` 只查询本人数据，提供卡片、进度、删除单条、清空和个人关闭。个人关闭同时清空历史，不影响收藏；后台没有查看任意用户阅读历史的页面。管理员/数据库运维人员仍可能从其权限读取数据库，不能把“本人页面隔离”宣传为对站点运营者端到端加密。

浏览器按阅读高度估算 0–100% 进度，首次与节流滚动时提交，最多约 45 秒一次，页面隐藏时尽力补交。进度只增不减；它不是阅读证明、任务领奖证据、课程考试记录，也不自动把滚动条恢复到精确段落。关闭页面瞬间的网络可能未送达，因此进度是尽力记录，不承诺每个像素都保存。

记录容量在后续记录时裁剪，不需要 cron。无 JavaScript 时可以查看和管理历史，但不会自动采集滚动进度。

## 六、关注动态与搜索

关注动态 `/index.php?r=following` 依照当前用户已关注作者的内容生成，继续执行原有发布、分类和权限过滤；取消关注后下一次读取即变更。它是按作者聚合的时间列表，不是 WebSocket 消息流或社交推荐算法，也不会在列表里泄露收费正文。

搜索联想默认随搜索模块开启。`search_suggestions_enabled` 独立控制弹框增强；至少输入 2 个字符，延迟 200ms 合并输入，最多展示 6 条。中文输入法在组词阶段不发请求；迟到的旧响应不能覆盖新结果，关闭弹框会使未完成查询失效。

联想使用原有内容检索，只取标题、公开摘要和标签等当前可展示元数据；不检索受保护正文。部分内容公开标题可以作为购买入口展示，这不代表已解锁正文。没有外部搜索服务依赖，不等于 Meilisearch 的分词、纠错、权重和大规模索引能力。

上下键选择，Enter 打开选中结果，Escape 先清空结果再关闭搜索；没有 JavaScript 仍可使用原来的页面搜索表单。请求失败不伪造结果。浏览器组件测试包含模拟乱序响应，而真实 HTTP 套件单独测试了服务端搜索权限、开关和结果字段。

## 七、设置与验收

新导航目标「创作中心、阅读历史、关注动态」可在后台菜单管理选择；模块关闭时入口随导航权限隐藏，直接访问仍执行服务端开关校验。

先用隔离账号验收「批准作者 → 付费投稿 → 审核 → 买家购买 → 等待/结算 → 提现驳回 → 退款冲回」，核对所有资产流水和订单状态。再测试其他作者无法结算别人的收益、其他账号看不到阅读历史、关闭记录后无新增、关闭模块后接口拒绝。真实商户付款与人工打款必须另外小额验证。
