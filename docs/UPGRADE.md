# 升级到 0.22.0

从 0.21.0 升级：结构 v13 → v14，给导航增加父级、说明、图片、分栏、修订号和请求键，给文章增加列表排版和公开图片索引。保留原导航为一级、旧图片绑定和正文；不自动造新栏目，不批量扫描旧文章。旧文章编辑保存后才提取正文公开图片。先备份，再覆盖代码和 assets，保留 config.php、原 secret、数据库和 storage；不要重新安装。升级后检查后台导航、正文插图和多图列表。

从 0.20.0 升级：结构 v12 → v13，新增 cy_bulletins 快讯表，以及文章来源名称、来源链接、版权类型字段。覆盖代码和 assets，保留原配置、secret、数据库和 storage；不要重新安装。清理 OPcache/CDN 后检查后台“快讯”和“文章与版权”。原内容的出处保持空白、版权沿用站点默认，不插入演示快讯，不改旧订单或上传封面。

从 0.19.0 升级：结构从 v11 升级至 v12：新增视觉素材绑定表、内容内置封面字段和导航图标字段；覆盖应用代码和 assets，保留 config.php、原 secret 与 storage。清理 OPcache/CDN，检查评论翻页、归档路由与后台运行限制报告。新模块默认开启，可在后台“模块”关闭归档。

备份恢复工具仍要求使用创建该备份时匹配的应用版本。不要跨版本直接恢复旧备份。

以下 0.18 → 0.19 数据迁移步骤也适用于直接升级至本版：

## 从 0.18.0 升级

本轮基线是用户提供的 0.18.0 完整代码，数据库结构从 v10 依次升级到 v14。config.php 中的 schema_version: 1 是配置格式，保留为 1。此程序不导入 WordPress 数据。

1. 暂停写入、收款和任务调度，备份同一时点的数据库、旧代码、app/config.php、原 secret、全部 storage 与服务器规则。先在隔离环境验证备份可恢复。
2. 覆盖上传包中的应用文件与 assets，保留原 config.php 和 storage。旧站不上传 install，不使用新站口令生成器重新安装。
3. 清理 OPcache、CDN 和浏览器缓存。首次请求按顺序迁移至 v14，需要数据库建表、加字段和索引权限；不要手动修改版本号跳过失败。
4. 检查文章、登录、订单、媒体与后台。按 PLATFORM_019.md 设置外观和资源版本，再恢复写入和受认证的调度。

新增 cy_resource_files、cy_resource_reports、cy_resource_downloads 三张表。资源版本保存来源、加密镜像/提取码与修订号，反馈与下载记录分别保存；原内容 resource_id、订单和媒体数据不搬迁、不重算余额。三张新表纳入加密快照。

布局文档仍使用 version:1；旧文档缺少的新字段会在验证时填入兼容默认值。旧发布历史保留。外观默认采用新排版与二次元站标，可在外观设置切换经典排版、抽象封面和文字站标；已有自定义内容与封面保留。

0.18 的加密备份先使用匹配的 0.18 工具恢复，再升级；0.19 备份使用匹配的 0.19 代码与相同数据库引擎恢复。不要把新版恢复工具当作任意版本转换器。

回滚需要停写并恢复同一时点的旧代码、配置、数据库与存储，不能仅覆盖旧 PHP 文件。回滚数据库不会撤销真实商户付款、退款、邮件或已发包裹。更早版本有顺序迁移代码，但不代表所有历史生产库都已演练。

0.20 → 0.21 已在原生 PHP 7.4 与 8.5 / SQLite 上演练，保留订单、余额、付费权限和加密资源；证据见 evidence/021/upgrade-from-020.json。0.18/0.19 迁移链在上版已有演练，本版没有冒充重新实测全部历史生产库。0.20 备份也应先用匹配版本恢复再升级。

0.21 → 0.22 在PHP7.4和8.5的原生SQLite上分别通过13项数据保留检查，证据见 [本版升级记录](evidence/022/upgrade-from-021.json)。已有导航保留为一级，旧文章没有凭空添加图片。
