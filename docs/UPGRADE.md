# 从 0.18.0 升级到 0.19.0

本轮基线是用户提供的 0.18.0 完整代码，数据库结构从 v10 到 v11。config.php 中的 schema_version: 1 是配置格式，保留为 1。此程序不导入 WordPress 数据。

1. 暂停写入、收款和任务调度，备份同一时点的数据库、旧代码、app/config.php、原 secret、全部 storage 与服务器规则。先在隔离环境验证备份可恢复。
2. 覆盖上传包中的应用文件与 assets，保留原 config.php 和 storage。旧站不上传 install，不使用新站口令生成器重新安装。
3. 清理 OPcache、CDN 和浏览器缓存。首次请求按顺序迁移至 v11，需要数据库建表和索引权限；不要手动修改版本号跳过失败。
4. 检查文章、登录、订单、媒体与后台。按 PLATFORM_019.md 设置外观和资源版本，再恢复写入和受认证的调度。

新增 cy_resource_files、cy_resource_reports、cy_resource_downloads 三张表。资源版本保存来源、加密镜像/提取码与修订号，反馈与下载记录分别保存；原内容 resource_id、订单和媒体数据不搬迁、不重算余额。三张新表纳入加密快照。

布局文档仍使用 version:1；旧文档缺少的新字段会在验证时填入兼容默认值。旧发布历史保留。外观默认采用新排版与二次元站标，可在外观设置切换经典排版、抽象封面和文字站标；已有自定义内容与封面保留。

0.18 的加密备份先使用匹配的 0.18 工具恢复，再升级；0.19 备份使用匹配的 0.19 代码与相同数据库引擎恢复。不要把新版恢复工具当作任意版本转换器。

回滚需要停写并恢复同一时点的旧代码、配置、数据库与存储，不能仅覆盖旧 PHP 文件。回滚数据库不会撤销真实商户付款、退款、邮件或已发包裹。更早版本有顺序迁移代码，但不代表所有历史生产库都已演练。
