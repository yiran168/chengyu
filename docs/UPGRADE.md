# 升级到 0.24.0

从 0.23.1 / 0.23.2 / 0.23.3 / 0.23.4 升级：备份数据库、原配置、secret 和 storage，然后将 `chengyu-0.24.0-patch-from-0.23.1.zip` 合并覆盖到网站根目录，不先删除原目录。本版同时修改 **app 和 assets**，两个目录都要上传；尚未安装的站点再覆盖补丁内的 install/index.php。已安装并删除 install 的站点不要重新上传 install。

补丁不含 app/config.php、install/key.php、INSTALL_KEY.txt、storage 或数据库，原安装口令继续使用。不要用完整新站包替换原有私密配置或验证文件，不重新安装。

首次请求自动将数据库 v15 升级至 v16，仅给 cy_navigation 增加 category_id、preview_count、preview_sort 三列，需要数据库加列权限。原菜单默认关闭内容预览；不创建假文章，不改订单或余额。升级支持重试，不要手改版本号跳过失败。回滚需要恢复升级前同一时点的代码、数据库、配置与存储。

覆盖后清理 OPcache、CDN 和浏览器缓存，检查后台版本 0.24.0、导航保存、布局添加/草稿/发布和上传。新功能操作见 [0.24说明](PLATFORM_024.md)。PHP7.4和8.5分别用0.23.4完整包程序生成隔离旧库，升级各通过16项检查，见 [升级证据](evidence/024/upgrade-from-0234.json)。旧包内部 App::VERSION 曾误写成0.23.3，所以证据基线返回0.23.3、结构15；这也是本次已修复的问题。

以下是历史升级记录，旧版“只上传 app”和“结构仍为 v15”仅适用于对应旧版本；升级至0.24必须同时覆盖 assets 并迁移至v16。

本版强化 MP4/PNG 内容检查、修复损坏分片补传和写入失败清理。若提示分片损坏，再次点击上传即可补传损坏片，已经通过校验的片会保留。建议更新后检查图片、私有附件和大文件上传。格式范围、读取上限与各入口检查见 [文件识别说明](FILE_TYPES.md)。

## 从 0.18.0 升级

本轮基线是用户提供的 0.18.0 完整代码，数据库结构从 v10 依次升级到 v15。config.php 中的 schema_version: 1 是配置格式，保留为 1。此程序不导入 WordPress 数据。

1. 暂停写入、收款和任务调度，备份同一时点的数据库、旧代码、app/config.php、原 secret、全部 storage 与服务器规则。先在隔离环境验证备份可恢复。
2. 覆盖上传包中的应用文件与 assets，保留原 config.php 和 storage。旧站不上传 install，不使用新站口令生成器重新安装。
3. 清理 OPcache、CDN 和浏览器缓存。首次请求按顺序迁移至 v15，需要数据库建表、加字段和索引权限；不要手动修改版本号跳过失败。
4. 检查文章、登录、订单、媒体与后台。按 PLATFORM_019.md 设置外观和资源版本，再恢复写入和受认证的调度。

新增 cy_resource_files、cy_resource_reports、cy_resource_downloads 三张表。资源版本保存来源、加密镜像/提取码与修订号，反馈与下载记录分别保存；原内容 resource_id、订单和媒体数据不搬迁、不重算余额。三张新表纳入加密快照。

布局文档仍使用 version:1；旧文档缺少的新字段会在验证时填入兼容默认值。旧发布历史保留。外观默认采用新排版与二次元站标，可在外观设置切换经典排版、抽象封面和文字站标；已有自定义内容与封面保留。

0.18 的加密备份先使用匹配的 0.18 工具恢复，再升级；0.19 备份使用匹配的 0.19 代码与相同数据库引擎恢复。不要把新版恢复工具当作任意版本转换器。

回滚需要停写并恢复同一时点的旧代码、配置、数据库与存储，不能仅覆盖旧 PHP 文件。回滚数据库不会撤销真实商户付款、退款、邮件或已发包裹。更早版本有顺序迁移代码，但不代表所有历史生产库都已演练。
