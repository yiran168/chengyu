# 0.12 社区与交易模块使用说明

本章只描述源码已经实现的范围。后台管理路径均以根目录部署为例；部分危险或需要运营规则的功能默认关闭，启用前先设置价格、说明与审核。

## 一、分类层级与圈子

后台「分类/版块」设置父级。层级最多 8 级，不允许循环、跨内容类型父子关系；已有内容或子节点的分类不能直接改成另一类型。上级与本级阅读条件同时生效，不是“子级开放就绕过父级”。

阅读条件：公开、登录、指定最低 VIP、圈子成员；发布条件：登录、指定最低 VIP、成员、编辑/管理员。发布限制和阅读限制是独立设置。分类继承由共用 `Categories` 服务执行，文章详情、列表筛选、购买、评论、正文访问和私有下载均通过服务端判断；编辑/管理员有管理访问权。

把社区版块设为圈子，配置是否开放加入、站内资产、价格与天数。0 金额为免费加入；余额是整数分，积分/代币为整数。前台有圈子发现页、圈子详情、加入表单及成员到期提示。`/admin/index.php?tab=circles` 管理圈子成员，可人工给予期限或暂停成员资格，修改写审计日志。

**不是定期订阅扣款**：有效成员不可提前购买续期；到期后可再次加入。每笔成功订单有独立期限，退款只撤销对应订单授予的有效权益，人工期限/其他有效订单不被误删。成员暂停不自动退款，管理员要单独处理争议。不得把本圈子付款视为绕过父级权限；父级要求仍需满足。

关闭新加入不会删除历史权益；单独关闭整个圈子模块将阻止新的加入行为。取消/退款仍走订单处理，不能靠删除分类清除交易历史。

## 二、积分悬赏问答

后台「模块」启用积分、问答及悬赏，设置最高悬赏积分。悬赏默认关闭；本版仅站内积分，没有现金悬赏/代付/多人分配。

问题作者可为自己已发布、未采纳的问题托管 1–30 天积分。托管时即扣除可用积分并生成唯一记录；余额不足整体回滚。一个问题只保留一段悬赏历史，本版不支持追加或退款后重新悬赏。

作者/编辑采纳同帖已审核顶级回答时，同一事务把积分发给回答作者、更新采纳状态并写日志；不能奖励自己、已停用账号或过期悬赏。重复请求不会再次发奖；已发奖不能改奖另一个回答。

过期未发奖由作者在问题页点击退回；管理员可在 `/admin/index.php?tab=bounties` 提前人工退回并留痕。关闭新悬赏后，历史未结清积分仍可退回。**不需要计划任务，也不是自动到期退款服务**；运营者须处理待结清记录。

回答后来被驳回时，采纳展示撤销，但历史积分奖励不自动扣回；重新审核/再次采纳也不重复付款。争议由管理员结合日志人工处理。

## 三、单选与多选投票

发布帖子选择投票，填 2–10 个不同选项，设置最多可选数量 1–选项数。1 是单选，大于 1 是多选。结果可以始终可见、投票后可见、截止后可见；截止后可见必须有有效截止时间。

每账号一张不可修改的票；选项顺序不同但集合相同的重试返回原结果，不产生新票。提交重复选项、越限或别的投票的选项都会被拒绝。第一票之后锁定选项、题目、隐私规则、最大选择数与截止时间，避免投票后改规则。

分母是投票人数，不是选择总数，因此多选百分比之和可能大于 100%。未达到结果显示条件时服务端不返回票数，不是仅靠 CSS 隐藏。旧单选数据迁移后继续使用，不丢票。

## 四、购买后自动生成邀请码

后台「模块」启用自动邀请码商品（默认关闭）；编辑商品，将交付类型设为邀请码，配置每个码允许使用次数、购买后有效天数、价格、库存和交付说明。适用于单规格商品，本版不提供邀请码 SKU 组合。

结算在同一事务中扣款/扣库存、生成随机邀请码、保存验证摘要并加密保存交付内容。用户在自己的订单里查看，管理员按订单权限处理；每次支付通知或幂等重试不会生成第二份码。

要强制邀请码注册，必须把后台注册方式切为「仅邀请码注册」；开放注册不会要求或消耗该码。邀请码原文只在交付记录受控展示，注册验证依摘要和次数进行，多个注册竞争次数不会超用。

未使用的码支持站内退款并同步停用；已经消耗次数的码拒绝自动退款，转人工争议处理。已经生成交付的码不会回到可售库存，也不会把同一个码卖给另一位买家。退款去向仍是原站内资产，不会自动调用支付宝/微信原路退款。

## 五、经购买验证的商品评价

后台启用商品评价，默认需要审核。实际购买成功的用户可对该商品提交 1–5 星、最多 2000 字的文字评价；每个用户/商品最多一条，再次提交为修改。修改后按当前审核设置重新进入待审，不绕过审核。

`/admin/index.php?tab=reviews` 审核。公开列表只统计已批准评价、仍有效的对应购买订单和正常账号；订单退款后该评价不再进入公开评分/列表，历史记录保留供审计。不能向没有购买的用户开放“已购评价”标记。

本版没有图片追评、商家回复、评价积分奖励、虚构评价导入或虚假销量；展示的数量与平均分从数据库实时查询，不可在后台填一个假的数字。

## 六、页面与配置

圈子入口：`/index.php?r=circles`，详情 `/index.php?r=circle&id=分类ID`。积分悬赏与评价在对应文章/商品页面显示，不能单独绕开内容权限访问内部资料。

前台表单全部使用现有登录、CSRF、参数验证与事务；普通用户不能调用后台成员/退款/审核接口。管理员、编辑权限依接口区分，不能只根据按钮是否可见判断授权。后台集中设置与具体业务对象分开维护，不把每个圈子的价格硬编码成全局设置。
