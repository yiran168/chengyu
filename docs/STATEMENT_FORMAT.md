# 标准化账单格式与差异处理

本模块用于人工准备数据后的只读核对，不是会计软件，不会改变资产。禁止把不明来源的文件当作支付成功依据。

CSV 必须是 UTF-8（可带 UTF-8 BOM），英文逗号分隔，表头严格如下：

```csv
event_type,reference,trade_id,currency,amount_minor,state,event_at
payment,LOCAL_SALE_NO,PROVIDER_TRADE_ID,CNY,100,succeeded,2026-09-07T10:00:00+08:00
refund,LOCAL_REFUND_NO,PROVIDER_REFUND_ID,CNY,100,succeeded,2026-09-07T11:00:00+08:00
```

这里的号码是格式示例，不是真实交易。不要直接用示例“核对”生产账单。

| 字段 | 规则 |
|---|---|
| event_type | payment 或 refund |
| reference | payment 对应 cy_sales.sale_no；refund 对应 cy_refunds.refund_no，不是网站单位子订单 order_no |
| trade_id | 渠道交易号或退款号。成功行必须非空；允许字母数字和 . _ : -，最长 191 |
| currency | CNY、USD、EUR、GBP、HKD、SGD、CAD、AUD；本模块只处理这些两位小数币种 |
| amount_minor | 非负整数，不含千分位、货币符号或小数点。100 表示该币种 1.00；最大 12 位 |
| state | succeeded、pending 或 failed |
| event_at | ISO 8601，必须有秒和时区，如 Z 或 +08:00；不能使用含糊的本地时间 |

reference 最长 80 位，只接受字母数字开头及 . _ : -。拒绝公式前缀和不合法引用。每个导入文件，同一 event_type+reference 只接受一行；先选定同一事件的最终状态，再导入。文件最多 2 MiB、2000 条，跨度不超过 31 天。包含窗口起点，不包含窗口终点。

必须先把服务商导出列转换成上面的名称与含义。绝不能把“到账净额”当作订单毛额、把人民币转换后金额贴上美元币种、把支付交易号当作退款号。时区要与导出账期一致。渠道会在支付后产生退款记录；二者分别对应 payment/refund。

核对优先级：不存在 → 币种 → 金额 → 交易号 → 状态 → 入账/退款凭证 → 完成时间。一个行显示当前首先遇到的差异，修正原因后可重新核对。仅本地存在可能是导出范围、时间边界或平台延迟，也可能是真正缺失；先核实，不能直接判定资金丢失。

本地反向扫描超过 2000 条缺失记录时会拒绝这个范围，缩小账期后再导入。比较使用站点支付成功和退款更新时间，不保证与渠道清算日一致。“匹配”只表示这些字段一致，不代表银行清算、平台争议或退款终局已核验。

数据库只保存规范化行、文件摘要和核对结果，不保存原始 CSV 文件。审核账号仍可读取交易引用，应最小化后台权限。若需要原始账单留档，请保存在 Web 根目录之外的受控存储。

操作复核：先做一个正确样本，再分别修改一项金额/币种/交易号/状态/时间，确认报告识别；重复导入应回到同一批次；所有这些操作后余额和订单不应发生变化。
