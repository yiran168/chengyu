## 先发现问题，再修改和回归

统一 HTTP 客户端复现并修正三个问题：大小写不同的同名请求头、urlencoded 请求缺少统一 1 MiB 体积限制、HEAD 响应绕开冲突传输长度检查。修复前后三项记录分别为 `transport-before.json` 与 `transport-after.json`。同时修正搜索词字符串 `0` 被空值判断忽略的问题。

新增回归覆盖七组验证码配额原子扣减与冷却；外置搜索公开元数据/有效译文、删除、异步任务验真、修订竞争、退避、权限与本地回退；多包裹归属、版本冲突、重复提交、独立轨迹及迁移保留旧数据；加密归档错误密码、篡改、截断、路径穿越、空目标保护、真实账户/余额/本地媒体恢复和恢复后的暂停开关。

备份专项 19 项在 `backup-working.json` 中通过，已被纳入最终 558 项，不能再额外计数。恢复服务实际使用测试适配器建立独立目标、写入数据和媒体；这不是 MySQL、原生 PDO 或服务商环境中的恢复证明。

测试开发过程保留了失败证据：早期测试仍把结构版本写死为 9；备份表目录遗漏两个既有业务表，已修正目录；HTTP 测试的错误状态预期与现有 403 约定不符，以及不同测试组复用管理员触发原有敏感操作配额。后者只在测试夹具中清空配额状态隔离测试组，没有放松生产限流。最终失败数为零，不隐去早期失败过程。

视觉检查发现新备份页 `.recovery-grid` 与旧双因素恢复码布局重名，已改用 `.recovery-vault-grid`，保留旧样式，并增加两项隔离断言。之后重新运行全部离线浏览器检查，生成最终新页面截图。

## 运行时、数据库和浏览器边界

实际执行 PHP **8.4.23**。环境没有原生 pdo_mysql/pdo_sqlite 验收条件，数据库通过测试专用 FFI 适配调用真实 libsqlite3，能执行 SQL、事务及隔离恢复，但不能证明原生 PDO 行为或 MySQL/InnoDB 分支正确。

生产仍使用原生 PDO，不引入 FFI 替代驱动，不要求用户主机启用 FFI；测试目录不在上传包。七 PHP 版本 × 两种原生数据库的 14 组 CI 配置已保留，本轮没有执行。安装/运行不按 PHP 小版本裁剪业务模块。

浏览器实际 URL 导航受到环境策略阻止；set_content 不验证公网 Cookie/CSP/TLS、浏览器跳转、真实跨文档动画、支付跳回或服务器目录访问规则。HTTP 请求套件确实经过本地 PHP 服务，但其中目录保护由测试路由实现，不是 IIS/Apache/Nginx/Caddy 实机规则验收。
