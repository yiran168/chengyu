# 0.16 交易、物流、会员与任务操作手册

先在隔离测试站操作。真实支付、代付、翻译和对象存储默认关闭。开关开启并不代表外部服务已开通；不能用伪造成功回调验收收款。

## 一、首次启用的顺序

先在“设置 → 统一结算”确认站点结算币种。默认 CNY；订单或资金活动出现后禁止随意更换，避免把人民币余额改成美元余额。没有自动换汇。旧 CNY 站点不应为开 PayPal 直接篡改数据库币种。

确认商品使用余额计价、真实库存、交付说明、退款政策。积分／代币保留原来的站内购买流程。新结算一次最多 20 行、100 单位；数字权限与会员不作为重复批量商品。交易拆成逐单位订单，共享一次外部付款，便于单位级售后。

先使用站内钱包或免费商品验收；再开一个直连测试渠道；验证付款、重复通知、超时查询、交付、退款和对账后才启用生产凭证。外部服务操作文档见 PAYMENTS.md。

## 二、访客下单与找单

访客填写联系邮箱、选择商品并复核总额。确认后系统生成随机 64 位十六进制私密通行证，保存在该浏览会话，并可从“访客订单”展开查看／复制。任何持有者都能访问这组购买记录，因此应像密码一样保存。

通行证不是登录账号，不赋予资料、管理、会员或社区登录权限。邮箱只用于联系方式，不允许只凭邮箱枚举订单，也不会自动发送通行证邮件。丢失后由商家核对真实付款证据人工处理，不提供知道邮箱即可重置的捷径。

访客付款可用已配置的官方渠道；非零金额不能借用不存在的站内余额。会员购买要求正式账号。已有账号可登录后显式“认领访客购买”；必须确认，且存在未解决的待支付单时不可认领。认领成功后旧通行证失效。

## 三、运费模板

后台“运费与促销”维护模板，并把模板绑定到实物商品。重量单位为克；金额单位为站点最小货币单位，例如 CNY 的分。示例可直接用于模板的 JSON 输入：

```json
{"mode":"weight","default":{"first":1000,"first_fee":800,"step":500,"step_fee":300,"free_above":19900},"zones":{"CN-XZ":{"first":1000,"first_fee":2000,"step":500,"step_fee":800,"free_above":0}}}
```

含义：普通地区首 1000 克 8 元，每增加 500 克加 3 元，达到模板内商品应付 199 元免邮；CN-XZ 使用独立费率。`free_above:0` 表示不启用满额免邮，不是无条件免费。

按件设置 `mode:"piece"`，首件、续件分别用 `first`、`step` 表示。固定运费设置 `mode:"fixed"`。`default:null` 配合限定 `zones` 可以拒绝未列地区；没有默认也没有地区是无效模板。地区代码由你定义并告知买家，例如 CN-GD；地址中的自由文字不会自动地理编码。

相同模板的实物商品合并计费，再按订单单位分摊；退款按照当时快照的金额处理，不按今天的新运费规则重算。若关闭运费模块或商品未绑定模板，应在运营前确认是否符合你的包邮规则，不要误开零运费。

## 四、组合优惠

规则带 `group`。同组只采用对买家更有利的一条，不同组按确定次序在剩余金额上叠加。所有折扣使用整数，分摊后的单位金额之和等于订单金额。

```json
{"type":"threshold_fixed","group":"order","min_amount":10000,"discount":1000,"item_ids":[]}
```

满 100 元减 10 元。以下是第二件半价：

```json
{"type":"nth","group":"quantity","min_amount":0,"nth":2,"discount_bps":5000,"item_ids":[12]}
```

`discount_bps` 是减免的万分比，5000 为减半；`item_ids` 为空表示不按商品 ID 限定，非空只匹配所列商品。其他类型的完整字段模板可在后台“运费与促销”选择示例并编辑，服务端会再次验证类型、数值、作用范围和修订号。

“买 X 送 Y”是现有购物篮的价格优惠，不会凭空给订单添加赠品，不是拼团。优惠券只允许单单位、已登录用户使用，并遵守原有叠加限制。发布促销前应测试同组、跨组、会员价、券、运费和库存同时存在的组合。

## 五、售后与原路退款

买家在收据页发起退款、退货退款或换货，并填写原因；可以关联属于自己的媒体作为证据。默认申请窗口为 30 天，可后台调整。实物已发货的退货应选择寄回流程，不把“已发货”直接当作未履约取消。

后台“售后与退款”要求管理员密码，启用双重验证的账户还需验证码。审核通过：仅退款进入退款队列；退货退款／换货进入等待寄回。买家填写运单，商家检查收货并选择是否可再次销售。换货仅支持同商品同 SKU；检查库存后再录入补发运单，买家确认收货后完成。状态和修订号防止旧页面重复审核。

退款以一个单位订单的全部成交额为准，包含它分摊的运费。本版不提供任意金额部分退款或按政策自动扣除退货邮费。站内钱包支付退回原站内资产；直连支付进入原网关退款，**不同时给站内余额入账**。确认外部成功后才撤销交付权益、处理库存／邀请码、冲回收益和佣金。已发卡密不会自动重新出售；已使用邀请码阻止自动退款。

网络超时是“不确定”，不是失败或成功。退款会保留固定退款号，后续先查询；不能手动把未知退款改成已完成以消除红色状态。确认为失败的单保留商家处理记录；在商户后台查清资金后由受控人工流程解决，勿直接修改金额或订单状态。

旧版“订单 → 退款”仍用于原来的站内订单；新统一结算单导向新售后入口。外部充值退款和普通会员整单撤销不在这套商品自动售后范围。

## 六、永久会员与补差

套餐天数为 0 表示永久，VIP 1–3 仍各自记录期限。本版新购会员会记录付款权益批次，补差依赖该批次而不是猜测用户当前等级。有限期批次的可抵扣价值按剩余时间比例向下取整；永久批次按后台保留价值万分比折算。

两个模式：“新周期”购买目标套餐的新完整期限；“保留到期日”在当前有效期限内升级。最终抵扣不超过目标应付价值，超出的残值不退现金、不另存余额。只能向更高级升级；永久批次不会被错误降成有限期，永久升级要求适当的永久目标套餐。报价带签名与 5 分钟时效，付款时再次验证会员、套餐和来源批次，旧标签页不能沿用已变化权益的报价。

例如源年卡 100 元、剩余约 180／365 天，可抵扣约 49.31 元；目标新年卡 200 元，新周期应付约 150.69 元。实际代码按秒、最小货币单位计算，以页面最终报价为准。保留到期日模式还会按同一剩余期限折算目标价格，不能套用新周期示例。

本版补差结算走站内资产；普通新会员套餐可用统一外部支付。历史订单需后台核验其实际付款、开始时间与截止时间后导入可追溯批次；导入不是人工制造新权益。补差退款仅退本次补付款，并核对权益是否仍属于该次升级；之后人工授予或再购买的权益不会被覆盖。复杂混合券包、组合服务权益与所有历史规则不属于本版支持范围。

## 七、主动查单、自动任务与代付

后台“交易控制台”可查单；“售后与退款”可处理退款和提现任务。普通页面浏览不悄悄批量调用外部付款 API。任务执行器一次处理 1–10 项，支付、退款、代付按最久未处理项推进；没有强制常驻队列。

VPS 可使用完整包里的 `tools/run_jobs.php`，调用方法见脚本自身提示。共享主机可由你控制的调度器向 `jobs.php` 发送签名 POST：JSON 正文如 `{"limit":1}`，请求头 `X-CY-Time` 为 Unix 秒、`X-CY-Nonce` 为随机 32 位十六进制、`X-CY-Signature` 为下列字符串的 HMAC-SHA256 十六进制摘要：

```text
时间戳 + "\n" + nonce + "\n" + SHA256(原始请求正文)
```

密钥来自后台“自动任务”的 jobs_secret，至少 32 字符；时间差不超过 300 秒，同一时间戳与 nonce 不能重放。不要把密钥放进 URL，也不要把它交给不可信免费定时平台。本包附 `tools/trigger_jobs.php`，在可运行 PHP 的可信机器上生成签名请求，不要求站点本身有 SSH。

自动代付仅实现 PayPal Payouts。需要商户申请相应权限、站点使用其支持币种、收款邮箱准确。管理员审核提现并再次证明身份后才排队；查询不明时保留冻结，既不重复发起新批次，也不释放资金。作者收益与推荐佣金的来源继续隔离。并未提供支付宝企业付款、微信商家转账、银行卡代付或替用户代付购物订单。

## 八、上线验收清单

用独立测试账户完成：库存不足、价格变化、重复点击、重复通知、访客换浏览器、通行证失效、优惠叠加、禁止地区、部分单位售后、寄回和换货、退款查询超时、代付超时、不同会员期限、永久升级以及退款后权限。用真实商户允许的小额测试核对支付平台与站内账目；不得仅看本站显示“成功”。
