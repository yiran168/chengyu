# 安全、数据与运维说明

没有“无漏洞”或通过独立渗透审计的承诺。自动化测试不能代替真实环境配置、安全复核与持续维护。当前版本适合先做隔离验收，再决定开放哪些模块。

## 已实现的主要边界

密码使用 PHP password_hash / password_verify。会话开启严格模式，Cookie 使用 HttpOnly、SameSite；规范网址为 HTTPS 时使用 Secure。登录、退出或凭据更改涉及会话防护；服务端用户 session_version 支持使既有会话失效。
写入请求要求 CSRF，只有支付通知走独立的签名验证流程。业务权限在服务端判断，不能靠隐藏菜单防护。普通用户不能访问管理员页面、读其他用户的订单或私信、拿到未购买的私有附件。
所有动态数据库参数绑定；表 / 字段标识来自程序控制并验证。输入使用类型 / 长度约束。Markdown 不执行用户 HTML，输出进行转义，外链限制协议。不能据此宣称覆盖全部 XSS 场景或浏览器兼容情况。
敏感操作包括管理员财务操作及用户转账的相应身份 / 密码校验，日志记录操作而不是把所有密码与完整密钥写入日志。
登录、注册、发帖、私信、找回邮件等使用频率限制。共享代理、NAT 用户和反向代理部署仍需要人工调整，避免误伤。

## 资产一致性

站内资产用整数，不用浮点数表示货币。钱包调整、账本、订单状态、库存与权益在数据库事务中更新；账本唯一幂等键与平台交易号唯一约束防重复结算。
SQLite 用 BEGIN IMMEDIATE，MySQL 用事务与需要的行锁；MySQL 死锁重试有次数上限。嵌套操作共享外层事务，没有实现嵌套保存点。
schema 使用索引与唯一约束，但没有声明完整数据库外键；关联一致性由服务层维护。不要直接手工删金融记录或绕过服务层写表。
8 进程 SQLite 竞争扣款验证过余额不会扣成负数；这不是 MySQL 并发压测、财务审计、分布式部署保证或资金保险。

## 文件与秘密

商户密钥、SMTP 密码、订单支付配置快照、卡密及部分支付信息使用应用 secret 加密；secret 位于 `app/config.php`，丢失后无法恢复原密文内容。管理员账号被控制后仍可能修改配置与执行管理员功能，加密不等于免于账号失陷。
用户地址簿、正文、普通资料和媒体文件并非全部加密存储。订单地址快照有加密，但不能把整个数据库称作“全量加密”。备份必须按敏感数据保护。

上传限制 MIME 和大小；普通成员只允许合规图片，不允许 SVG / PHP 等可执行文件。管理员可上传规定的资源类型，应用通过受控下载端点输出。
实际文件写成随机命名并带 PHP 阻断前缀的存储封套，直连执行会先退出；合法下载由应用去掉封套后输出原始字节。该机制不等于文件内容加密，不替代 Web 服务器拒绝访问 storage。PHP 解析失效时必须立即处理服务器配置。
Apache `.htaccess`、Nginx 私有目录规则、Caddy handle 与 IIS web.config 的实际生效情况必须在部署主机检查。本次 HTTP 测试中的私有目录拒绝由测试路由器提供，不能作为这些生产服务器配置已经验证的证据。
不要把完整交付目录、备份、SQL、INSTALL_KEY、测试适配器或 debug 页面上传到 Web 根目录。

## 安全上线顺序

先完成 HTTPS、规范网址、目录访问阻断、文件权限和主机账户安全；删除 install；测试普通用户权限隔离；恢复备份；再测试商户支付，最后开放用户注册与交易。
现有Google/GitHub/Microsoft OAuth适配、TOTP/恢复码和邮件验证注册；仍没有短信验证或真正实名核验。本版的人工认证标记不是第三方身份认证服务。后台管理员应使用唯一强密码并优先配合主机侧访问控制。
前端出现余额或价格不能作为授权事实；管理员收款、提现人工流程也必须留外部凭据。金融模块默认关闭的部分不应仅为“功能多”而全部打开。
不要在支付回调路径加人机验证页面，也不要为了回调方便全局关闭 CSRF、金额校验或 HTTPS。

## 可恢复的备份

必须把数据库、app/config.php 的原 secret、整个 storage 作为同一备份集。CSV 导出不是完整备份，没有密码哈希、加密配置和媒体等完整恢复要素。
MySQL 使用面板的一致性导出，或专业备份工具的事务一致性模式；同时避免备份过程中新增上传造成数据库与媒体不一致。
SQLite 使用 SQLite 在线备份 API / sqlite3 `.backup` 或停止写入后正确处理 WAL。不能在活跃写入期间只复制主 `.sqlite` 文件并忽略 WAL。

恢复演练：在非公开的新目录 / 数据库准备备份 → 保留相同 secret → 修正绝对路径与规范网址 → 恢复 storage → 验证密码登录、会员权限、购买权益、卡密解密、订单与账本合计、文件下载 → 关闭测试站的真实支付或使用单独测试商户。
演练成功才可认定备份“可恢复”。演练未在本次真实主机执行。
不要直接用安装向导重新生成密钥覆盖已有数据库。安装器看到已有用户会拒绝新装；应恢复原 config，而不是删除用户数据绕过它。

## 日志、清理与事件处置

异常日志受保护且有大小限制。管理员系统清理处理过期令牌、过期限流项、超时待支付单和按留存期轮转审计；不会清空金融流水。
收到泄露或异常付款报告：暂停对应入口，保留订单 / 账本 / 主机与网关日志，核对真实商户账单，撤销泄露凭据、使会话失效，复核受影响账户与金额。不要直接删除证据。
对应用 secret 的更换需要重新加密方案，不可只换一串随机值；商户密钥修改也需要考虑旧订单快照。恢复与升级前都应备份。

## 0.10.0 新模块安全边界

布局导入只接受白名单数据，不接收模板脚本，不导出支付或数据库秘密。注册码保存摘要，原始代码显示一次；每次注册与扣次数处于同一事务。密码内容不是身份认证或防传播 DRM。

私有下载额度按已登录用户的不同文件计算，匿名密码访客不具备同等日配额保证。文本修订还原不改变金融数据。商品或任务存在历史成交/领取后，部分规则不能原地修改，应停用再新建。

推荐佣金退款冲销可以产生内部负债待人工处理；普通余额、积分、代币仍禁止透支。不得把负佣金当作已经追回到银行卡的事实。升级前读 UPGRADE.md，迁移失败不要手动伪造数据库版本标记。

## 0.11 新安全约束

退出登录清空临时会话证明与展示状态，轮换会话 ID 与 CSRF；用户或管理员改变凭据时吊销旧找回令牌。嵌套事务任何异常都会使整笔事务不可提交，不能用外层 catch 偷留下半个财务操作。

邮箱码 6 位、10 分钟、5 次错误上限，绑定收件人/用途/会话/用户；共用收件人和 IP 发送配额。错误次数先提交，正确消费与业务变更一起提交。数据库不存明文码，但账户邮箱、SMTP 服务商日志仍是个人数据；不把验证邮件作为营销轰炸接口。源码和完整包中不得放生产 SMTP 凭据。

投票结果在服务端按可见策略裁减，不能只靠前端隐藏；单账号唯一约束不是防止自然人多账号的实名方案。受限内容评论不向无权限者输出；回复后可见规则保留其必须的回复入口。采纳只能指向已审核本帖顶级回答，审核拒绝自动撤销。

动效输入是受限数值/枚举，不接受任意 JavaScript 或 CSS 字符串，工作台不能编辑付款代码。动画和管理员预览不参与权限判断。截图/静态渲染并未验证生产 CSP、主机访问规则或所有客户端版本。

本轮没有外部安全机构渗透测试；仍需隔离验收、依赖维护、主机目录保护与完整备份恢复。查看 TEST_REPORT.md 的真实环境边界，不以测试数量代替商业运行安全证明。


## 0.13 补充

涉及当前密码确认的敏感动作会重新读取有效用户状态和会话版本，拒绝已经改密/停用的旧会话。用户转账服务对发送方和接收方锁定并重新确认有效状态，不只依赖前台按钮隐藏。

作者应计收益不是立即可提现的钱：等待期、退款争议、实物收货、重复结算、来源资产负债必须通过服务端校验。不要绕开人工审核直接在数据库标记“已打款”。负收益应按真实账本处理，不删除原记录消除负债。

阅读历史包含行为数据。应在隐私说明告知用途、容量和退出方式；关闭个人历史会清空记录，但站点原有安全/访问日志并不因此自动删除。后台页面不提供任意用户历史查询，不代表拥有数据库的运营者无法接触数据。

搜索只输出当前可展示的元数据，浏览器按纯文本生成结果；不在缓存或搜索索引暴露受保护正文。真实浏览器的 CSP/代理缓存和已登录页面隔离需要在部署主机另验。

## 0.14：第二因素、恢复与金额确认

密码登录的服务入口也拒绝超过 72 字节的密码，避免 bcrypt 静默截断。停用账户在兑换前由资产服务重新锁定并检查，不能只依赖路由或隐藏按钮。

第二因素密钥加密保存，恢复码存带站点密钥的摘要；登录时与账户行锁/会话版本共同验证。重复时间步或恢复码拒绝，事务回滚恢复消费。管理操作要求当前密码和相应第二因素；暂停新绑定/重置密码不会移除已启用保护。

备份必须包含原加密密钥，并妥善保护备份和用户恢复码。恢复旧数据库可能重放旧状态，需要撤销旧会话并重新核对安全与资金。本地恢复脚本只有站点所有者在 Web 根目录外执行，不是 HTTP 后门；脚本完整生产命令路径没有原生 PDO 实机验收，本地服务方法和语法已测。

报价返回纯文本和整数，前端不插入返回 HTML。结算复算并核验单件最高金额，拒绝时回滚券额度/扣款。预览不保证永久价格或库存，不能把显示“已核对”当“已支付”。

部署自检需管理员与 CSRF，输出不含商户/数据库密钥或服务器绝对路径。版本信息仍只给可信维护人员；自检通过不替代外部安全审计、真实目录保护和支付验收。

## 0.17 新数据边界

学习笔记、工单与回复按账户权限隔离，但并非数据库全量加密；持有数据库备份的管理员仍能访问，必须保护备份。运单号和轨迹使用站点secret加密。快递100查询需明确同意发送单号和必要手机号，返回结果核对原运单，且不驱动收货/资金状态。

搜索只索引公开标题、摘要、标签与有效发布译文；源内容修改/下架后实时条件仍需通过。账单CSV属于不可信输入，严格限定格式、金额、时间与规模，仅生成报告。课程预览会开放对应资源，因此同一资源复用时必须明确授权含义。布局草稿不改线上，恢复仍须最新修订号。

安全验收新增账户间课程笔记/工单/物流隔离、退款后课程撤权、账单导入不改变资产及轨迹串单拒绝；自动测试不等同独立渗透测试。


## 0.18.0 搜索与加密副本

外置搜索只同步公开元数据，不发送付费正文或私人内容。索引是独立公开数据处理边界；配置前确认是否适合向外部服务公开标题/摘要/标签。密钥服务端加密保存，出站复用 HTTPS/地址验证，返回排名不能绕过本站访问权限。停用服务或更换地址不会替你清除旧服务商上的数据。

恢复副本采用 PBKDF2-SHA256（600000 次）与分块 AES-256-GCM，含顺序/前块标签关联和终止记录，拒绝截断或篡改。密码 16–256 字节；应用不保存备份密码。格式是本项目有限记录协议，不接受 PHP 序列化对象、SQL 语句或任意路径。密码和归档需要分开保存；归档中包含原站 secret、用户哈希、订单、余额等敏感信息，不能公开分享。

加密不等于可恢复保证，须另存并定期演练。当前只支持同版本、同结构、同数据库类型的独立空目标。MySQL DDL 无法完全事务回滚；失败后丢弃隔离目标再排错，不在运行中的生产数据库重试。恢复后维护模式与 recovery_hold 阻止任务继续，原会话失效；外部资金与旧数据库之间的差异需人工核对。具体命令及限制见 `BACKUP_RECOVERY.md`。
