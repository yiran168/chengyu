# 从 0.16.0 升级到 0.17.0

本版以实际上传的 **0.16.0 完整包**为基线，数据库目标 **v9**。不是再次基于 0.15.0 交付同名 0.16.0。安装配置 `app/config.php` 中的 `schema_version: 1` 是配置格式，保持不变，不是数据库版本。本程序不是 WordPress 或子比数据导入器。

## 安全升级流程

1. 暂停交易、收款和外部任务调度。备份同一时点的数据库、代码、原 `app/config.php`、其中的 `secret`、完整 `storage/` 和 Web 服务规则。SQLite 活跃写入时不要只复制主文件而漏掉 WAL；先停写或使用一致性备份。
2. 在隔离副本中验证备份可恢复，禁用副本的真实支付、邮件、物流和翻译服务。更新程序入口、`app/` 和静态资源，但**保留原配置文件、密钥、数据库及全部存储**。不要重新安装。旧站已删除 `install/` 的，不必再次上传安装器。
3. 首次请求会依次执行迁移至 v9。私有存储必须可写以取得迁移锁；MySQL 的 DDL 不能假定整段都能事务回滚。失败时停写并查看私有日志，不要手动提高版本号掩盖失败。
4. 清理 OPcache、CDN 与浏览器静态资源缓存。进入后台系统自检，按 `ACCEPTANCE_017.md` 验证后恢复交易及调度。升级未自动开启任何外部付费接口。

0.15.0 及更早受支持结构可通过现有顺序迁移路径升级，但本轮直接比对的发布基线是 0.16.0，不能将其说成每个历史版本实库都测试过。

## v9 数据变化

新增倒排索引及构建游标、布局草稿/发布历史、课程/章节/私人进度、运单/人工轨迹、账单核对批次/明细、客服工单/回复/模板表。现有已发布布局作为首个历史快照保留；没有把现有文章自动转成课程，也不导入 ICU 数据库。

旧订单、会员权益、卡密和作者收益继续使用原表。新账单核对仅生成差异，不更改余额或补做入账。新物流轨迹仅展示，不自动确认收货或退款。查单、退款和代付任务仍沿用原审核与状态机。

## 默认行为和运营变化

搜索引擎默认为 portable；首次升级后先在后台构建索引。未完成构建时自动回退原有检索；需要时可显式切回 legacy。更新内容与发布译文时会同步相应索引。课程与客服功能可在设置中开关；没有内容时显示空状态，不注入演示商品。

前后台语言偏好现在分开保存，旧版统一偏好作为兼容回退。未设置独立偏好的用户仍使用默认规则。支付宝新增 `page` 选项但默认保持 `wap`，不会把旧商户强行切换到电脑网站支付。

物流查询默认 manual，快递100参数需自行配置；账单需自行从商户后台取得并转换标准格式。原官方支付、PayPal 代付、对象存储、自动翻译仍需有效凭据与实际验收。

## 最小升级验收

验证旧账户、TOTP、余额流水、旧卡密解密、付费资源、SKU库存、退款及收益。再验证索引重建/隐私排除、课程预览/购买/退款撤权、学习笔记的账户隔离、布局草稿不影响线上和历史恢复、工单越权拒绝、运单所有者隔离及账单导入不改资产。

CLI 任务仍为 `php tools/run_jobs.php /absolute/site/root 1`；免费主机可使用后台按钮或受签名保护的外部调度。没有真正定时触发，就不能保证无人值守及时推进支付、退款或代付。

## 回滚

高于程序支持版本的数据库会被拒绝启动。**不要只换回 0.16.0 PHP 文件。** 停写后同步恢复升级前数据库、代码、配置、密钥与文件，再核对升级期间实际发生的外部付款、退款、代付和发货。

数据库回滚不能撤销真实资金、邮件或已下载副本。索引可重建，但私人笔记和工单必须靠备份恢复。旧 v8 模块说明见 `COMMERCE_016.md`；升级步骤以本页为准。
