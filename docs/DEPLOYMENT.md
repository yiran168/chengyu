# 安装与部署

项目版本：0.23.2。主机资料的来源及核查日期见 HOSTS_AND_SOURCES.md。本文描述部署步骤，不代表已登录蓝队云、萌哒云或在真实 VPS 执行过部署。

## 一、免费虚拟主机：推荐 MySQL 安装

### 1. 在面板准备

绑定自己的域名，选 PHP 而不是 ASP。建立一个空数据库并记录数据库主机地址、端口、名称、用户名、密码。数据库名称前缀以主机面板实际值为准，不是自行填写一个不存在的名称。
启用 HTTPS，并确认浏览器能正常访问，不出现证书警告。本站的支付网关回调必须能从公网访问。

程序面向 64 位 PHP 7.4–8.5，所有版本使用相同功能；检查 `pdo_mysql`、OpenSSL；文件内容识别使用内置程序，无需 Fileinfo。上线仍建议使用获得安全维护的运行时，而不是把兼容旧语法等同于旧运行时安全。安装器会检测运行时、PDO 驱动和基本写权限，但不等于完整安全审计，也不能提前验证真实支付回调。
蓝队云官方免费主机说明为 Windows 环境、FTP 上传 wwwroot、无 SSH 和单独环境更换；未明确本套餐 PHP 小版本和 PDO 扩展。萌哒云按用户提供的面板截图可选 PHP 7.4、8.0、8.1、8.2，另有旧版本；本程序应选择至少 7.4。截图显示的“萌速”配额为 SSD 2GB、MySQL 1GB、月流量 780GB，尚未独立核实该实例的扩展、权限和请求限制。两者均须以实际面板、安装检测和工单为准；代码不能替主机安装扩展或解除磁盘/网络限额。见 HOSTS_AND_SOURCES.md。

### 2. 上传

推荐使用单独的上传 ZIP，在网站根目录解压。或者在本地解压完整包，仅上传 `site/` 内全部内容，含隐藏文件。根目录应当直接看到：

```
index.php
action.php
notify.php
notify-direct.php
jobs.php
oauth.php
media.php
admin/index.php
install/index.php
app/
assets/
storage/
.htaccess
web.config
```

**不能公开**完整交付 ZIP、INSTALL_KEY.txt、数据库导出、备份、tests、docs、deploy。
不要覆盖原网站；先备份旧站，使用空站点目录和空数据库。此安装器不会迁移 WordPress 数据，也不提供一键导入旧主题。

Apache / LiteSpeed 需要正确处理随包 `.htaccess`。Nginx 不读取 `.htaccess`，须在面板添加 `deploy/nginx.conf.example` 中的目录保护规则。IIS 附带 `web.config`，但未实测；由主机确认配置功能允许、目录浏览关闭且敏感目录不可访问。不要删除防护文件来绕过错误。

### 3. 运行向导

打开 `/install/`，例如：

```
https://example.com/install/
```

填写站点名称、规范网址、安装口令、MySQL 信息和管理员账号。先在电脑打开包内 `DEPLOY_PREPARE.html`，生成本站独立口令；上传生成的 `key.php` 覆盖服务器 `install/key.php`。口令保存在刚生成的私密 `INSTALL_KEY.txt` 中，公开包本身不含通用口令。它用于避免未安装站点被抢先初始化，不是管理员密码。
管理员用户名为 3–32 位小写英文字母、数字、下划线，字母开头。密码为 12–72 字节、必须含字母和数字。
可选择安装原创示例内容和套餐；公开运营前必须检查价格和内容。

安装器创建数据表和配置文件，但不创建 MySQL 数据库或数据库用户。站点网址必须与当前安装目录一致，不能填带查询参数、片段或其他路径的网址。
向导成功后登录 `/admin`。实体目录入口不依赖 WordPress 伪静态。

### 4. 权限与收尾

`app/` 安装期间要能由 PHP 写入，以创建 `app/config.php`；安装后除配置变更或升级外不应继续允许 PHP 修改应用代码。
`storage/` 要允许 PHP 创建媒体文件和日志。不要用全站 777 解决权限问题。共享主机文件所有者模型不同，使用主机提供的权限管理。
`app/config.php` 自动设置为仅所属用户可读写；不要改为可公开下载的扩展名。
安装完成且确认能登录后，删除 `install/`。

用未登录浏览器实际请求下面的路径，必须被拒绝或返回无敏感内容的 404，不能显示目录、源码或 JSON 种子数据：

```
/app/seed.json
/app/config.php
/storage/
/uploads/
/.htaccess
```

测试安装器的 PDO 检测与这些 HTTP 路径保护是两个不同的事项，都需要验证。

### 5. 首次后台设置

站点身份与联系方式、服务条款、隐私与退款说明 → 外观与布局 → 用户与评论审核 → 内容 / 会员套餐 → 交易与支付 → SMTP。
蓝队云用户在「站点设置」中设置「主机鸣谢文字」和「主机鸣谢链接」，遵守该套餐页面的页脚链接规则。不要自行删掉主机要求的标识。
后台系统页能查看 PHP、数据库类型、上传限制、存储写入状态和 HTTPS 网址配置；不能控制主机面板或安装证书。

## 二、已有面板的 VPS

用现有面板创建 PHP 站点、绑定域名和证书、建立数据库，再按上述安装。不要运行新 VPS 脚本覆盖面板服务。
Nginx 的私有路径拒绝规则优先于 PHP 匹配，参见模板；PHP-FPM socket 按面板实际值修改。本站无需通用 `try_files ... /index.php` 前端控制器重写。
面板开启强制 HTTPS 后再把安装网址设为 HTTPS。已经安装的站点换域名或 HTTP 切 HTTPS，备份后修改 `app/config.php` 的 `url`，保留 `secret` 与数据库信息，不要重新安装。
反向代理必须只信任自己控制的代理，并正确传递 HTTPS 状态。不要为了消除登录问题全局信任任意客户端伪造的代理头。

## 三、全新、无面板 VPS

`deploy/install-vps.sh` 面向全新 Debian 12+ / Ubuntu 24.04+、root 权限和 systemd 主机。**本次只检查了 Bash 语法，没有实际安装系统包或取得证书。**
先阅读脚本。它会安装发行版 Caddy、PHP-FPM、PDO 驱动，创建 `/var/www/chengyu`，写入 Caddy 配置；会拒绝目标目录已存在、常见面板或已运行 Web 服务的环境。它不修改云防火墙、不为你设置 DNS、不卸载现有服务。

把完整包上传到非 Web 公开目录解压后：

```bash
cd chengyu
sudo bash deploy/install-vps.sh example.com
```

将 `example.com` 换成自己的域名；按提示输入 `INSTALL`。先使域名 A/AAAA 指向该 VPS，允许公网 TCP 80/443，保证 Caddy 能绑定端口并持续保存证书数据。删除指向错误服务器的 AAAA 记录，而不是反复申请证书。
完成后浏览器进入 `/install/`，选 SQLite，填 `/var/www/chengyu/private/chengyu.sqlite`。私有口令保留在 `/var/www/chengyu/INSTALL_KEY.txt`，可用 root 读取。也可自行配置 MySQL，脚本没有安装 MySQL 服务器。
Caddy 的公开域名 HTTPS 申请和续期由 Caddy 管理；不是 PHP 后台调用 ACME。网关服务、DNS 和防火墙必须正常，否则不会凭空获得可用证书。

验证后，在该脚本部署的特定路径下执行：

```bash
sudo rm -r /var/www/chengyu/site/install
sudo chown root:www-data /var/www/chengyu/site/app
sudo chmod 0750 /var/www/chengyu/site/app
```

这些命令只适用于本脚本创建的路径。不要照搬到不确定的生产路径，不要删除私有数据库或存储。`config.php` 仍需 PHP 用户能读，媒体存储仍需可写。
运行日志使用 `journalctl -u caddy`、`journalctl -u php8.3-fpm` 等，PHP 服务名按实际安装版本替换。

## 四、IP、端口、子目录

根目录部署时 `/admin` 和 `/admin/` 都由 Web 服务器的实体目录入口处理；带端口可以使用 `http://IP:端口/admin/` 进行隔离环境初测。正式登录与充值应使用有效 HTTPS，HTTP 模式无法创建本站在线充值单。
不能保证主机共享 IP 能直接访问你的虚拟站点，这由面板的站点绑定决定。

子目录部署时后台是 `/子目录/admin/`，而不是域名根目录 `/admin`。要严格满足根目录加 `/admin`，就把网站放在该域名的文档根目录。Nginx 私有目录规则也要加子目录前缀。本次自动化测试以根目录部署为主，没有完整覆盖所有子目录 / 代理组合。

## 五、常见问题

| 现象 | 排查方向 |
| --- | --- |
| 显示 PHP 源码或下载 PHP | 立即停止访问并移除公开文件，修复服务器 PHP 解析，检查密钥是否已泄露 |
| 404 /admin | 检查是否多套了一层 site 目录、默认文档是否为 index.php |
| PDO 无驱动 | 面板启用 pdo_mysql 或 pdo_sqlite，不能通过上传 PHP 包补出原生扩展 |
| 安装写入失败 | 配置目录所有者、主机配额、open_basedir、storage 权限 |
| MySQL 连接失败 | 面板给出的真实地址 / 端口 / 账号 / 名称、空库权限、InnoDB 与 utf8mb4 |
| HTTPS 后登录循环 | 规范网址、浏览器 Cookie、代理 HTTPS 状态与实际访问域名是否一致 |
| 上传大小失败 | PHP upload_max_filesize、post_max_size、Web 服务器 body 上限和后台限制需同时允许 |
| 支付返回后没到账 | 返回页不发钱；检查服务端异步通知和真实商户账单，见 PAYMENTS.md |
| SMTP 找回失败 | 主机出站端口、邮件服务授权码、TLS CA 与发信地址授权；从未保证免费主机允许出站 SMTP |
| 页面空白 / 500 | 查看受保护的 storage/errors.php 与服务器日志，保留错误编号，不公开日志 |
| 缺少 SSL 控制权限 | 用主机面板或联系主机商；PHP 代码不能替代该权限 |

## 六、升级与迁移

0.14.0 按序提供从 0.9.0–0.13.0 到结构 v6 的增量、可重试迁移，详见 UPGRADE.md。没有在线热更新或自动降级回滚，不支持 WordPress 数据库直接导入。
迁移需要数据库、`app/config.php`（尤其 secret）、整个 storage 一致备份。域名或绝对存储路径变化后修改配置对应项，检查回调地址和邮件链接，并再次做验收。完整备份不能用用户 / 订单 CSV 导出来代替。

## 七、新增模块上线顺序

升级或安装后先检查「模块」中的问答/投票开关，在测试版块发布试帖并用两个普通账号验证权限与结果隐私。后台「动效工作台」可先在本地预览，保存后用另一个浏览器检查默认效果；页面不会因关闭动画而失去付款或下载功能。

SMTP 先配置、实际收发成功，再开启必填邮箱验证，避免把真实访客挡在注册入口。详见 EMAIL_COMMUNITY.md。需要普通不验证注册时保持该可选开关关闭，所有 PHP 版本遵循同一设置，不是低版本精简模块。

部署完成不要求开放 SSH、FFI、Python、Node 或测试端口。测试目录仅留本地。安装器只检查基础运行环境，不表示服务器的网络、数据库性能与所有业务已验收。

## 八、安全、定价与主机自检

首次上线先到“系统”运行部署自检，确认真实环境的原生 PDO、回滚、加密与写权限。下载报告便于维护，但报告不含公网敏感路径访问检查，不得跳过真实 URL 验收。

准备好离线恢复码再给管理员启用身份验证器，确认服务器时钟正确。SMTP 密码找回不会移除身份验证器；没有命令权限的免费主机尤其需要事前保管恢复码。完整包的本地恢复脚本不得公开上传。

先用测试账户/测试商品设置会员价和活动，核对 0/8000/10000 比例含义、单件最高确认额和按成交价退款，再开放促销。详情见 SECURITY_PRICING.md。旧站没有价格规则时不会因升级自动出现优惠。
