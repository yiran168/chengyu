# 结构、DRY 与扩展

## 入口与服务

`index.php` / `admin/index.php` 分别处理前后台读取，`action.php` 处理带权限与 CSRF 的写入，`notify.php` 验证外部支付通知，`media.php` 输出授权媒体；`feed.php` 和 `sitemap.php` 提供公开 XML。`app/bootstrap.php` 统一配置、错误处理和会话；`App.php` 组装业务服务。

```
app/
  Core/       PDO 数据库、增量迁移、设置、输入、加密、Markdown
  Services/   Auth / Wallet / Commerce / Payment / Content / Media
              Membership / Inventory / Cart / Tasks / Invitations
              Catalog / Layout / Mailer / Activity / Admin
              Categories / Bounties / Reviews / Threads / Verification
              Creator / Discovery / Pricing / SecondFactor
  Http/       Actions / SiteController / AdminController
  Views/      前后台模板与共享组件
  settings.php
  schema.php
  lang/zh-CN.json
```

全局设置统一由 `settings.php` 和版本增量定义组成，默认值与字段数记录在RELEASE.json；本轮另加 `settings018.php`，保留 `settings017.php`。默认值、类型范围、后台表单、保存验证与前台读取复用同一键。任务、专题、SKU、套餐、布局等是业务对象，不硬塞成数百个彼此关联的全局配置项。

5 种主题共用业务服务和组件，只改变变量与小范围排版。支付验证、库存扣减、账本写入、内容授权不复制到每个主题。SVG 几何封面与图标属于本项目原创代码素材，不依赖 CDN、在线字体或图片服务。

## 新版 DRY 边界

`Inventory` 是规格选择、库存消费/恢复、卡密同步和导入的共用入口；`Cart` 复用 `Commerce` 的购买规则，不再维护另一套可分叉的扣款代码。`Membership` 管理独立等级期限，内容与媒体复用同一访问判定。

`Catalog` 对专题、链接、公告使用受限实体定义和共用管理路径，不开放客户端传入任意 SQL 表名。`Layout` 只接受固定 JSON 格式和字段白名单。`Tasks` 从实际数据取得完成证明，领取和资产调整共用事务。`Invitations` 只保存摘要，次数消耗在注册事务中。

控制器做输入解析、权限和路由，服务层维护业务不变量，视图输出已授权数据；不能在模板中直接修改账本。基础数据库和活动日志统一复用，但不把语义不同的余额、邀请码和库存强行做成同一个抽象。

## 金融与并发

余额、推荐佣金与作者收益以整数分保存，积分/站内代币为整数。所有资产通过 `Wallet::adjust` 和业务事务，带与业务记录绑定的幂等键。请求指纹阻止将同一个结算标识复用于不同购物车。付款、库存、卡密、权益与退款一起设计。

MySQL 用 InnoDB 行锁，SQLite 用事务和忙等；嵌套调用共享外层事务，任一嵌套调用抛错都会标记 rollback-only，外层捕获异常也不能提交部分变更。金额和数量验证在写入前完成，事务内避免不可回滚的网络发信。唯一约束不是错误处理的替代品：正常重试返回已有结果，冲突数据应报错。

推荐佣金逆向可能形成内部欠账，以保证已经提现的推荐收益不阻塞买家退款；普通用户资产仍不能超支。免费主机上没有分布式事务或多节点锁的保证。

## 数据库结构升级

`schema.php` 创建基础表，`Core/Migrations.php` 增量升级到结构v9（v8交易表、v9运营表另见本篇补充）；v2 新增 13 张表，v3 新增 4 张表；v4 新增 4 张表及分类/投票/邀请码字段；v5 新增收益与历史两张表、作者/隐私/提现来源字段及媒体关联索引；v6 新增身份验证器与价格规则表、券范围字段；v7 新增身份连接、查询记录、配置快照、徽章与授予五张表。新装和升级共用迁移，不把升级逻辑仅写进安装器。数据库 `cy_settings._schema_version` 在全部迁移完成后才更新。

用私有文件锁串行化单站迁移；新增表/列先判定存在，可重试。MySQL DDL 不能被应用事务整体回滚，因此失败恢复需要备份和重试设计。配置文件的 `schema_version` 是安装格式标记，不是当前数据库迁移版本。

生产使用 PDO；本环境的 FFI SQLite 是测试工具，不能替代原生 PDO/MySQL 验收。开发者应运行随包 CI 矩阵并保留原生数据库测试结果，再扩展 SQL 或调整锁顺序。

## 扩展方法

新增设置：字段定义、中文标签、读取点和非法值测试一起提交。新增主题：扩展允许值与样式变量，验证移动端、深色、减少动态效果和文字对比度。新增业务：先定义权限/事务/逆向流程，再接前后台。

新增支付网关需核对其真实官方协议、签名、金额单位、交易状态和重试语义，再加入固定样例和真实商户联调。不能因名称中有“易支付”或“码支付”就复用另一个平台的参数。

新增订单类型必须同时处理履约、下载、库存、取消、退款和推荐佣金逆向。新增数据库版本先有一致性备份与迁移测试。修改公共组件应同时跑旧测试与新增边界用例，而不是删除不通过的旧测试。

## 运行边界

定时发布和公告通过读取时判断时间，不是可靠后台调度平台。没有自动主动支付对账、消息队列、全文检索集群或多节点共享会话实现。需要高并发或大型媒体时应独立设计基础设施，不能从源码体积推断免费主机容量。

浏览器动效遵循减少动态效果；低资源模式只收敛视觉负载，不限制购买或后台业务。客户端偏好存在 localStorage，管理员默认存在数据库，互不冒充。示例内容可编辑，不代表真实访客数据。

## 0.11 服务与浏览器边界

`Verification` 统一验证码哈希、发送限额、用途/会话绑定、失败次数与证明消费；注册、改绑和找回密码共用发送配额。失败尝试在独立验证事务提交之后才抛错；成功证明在账户业务事务消费，避免失败注册把证明永久扣掉。SMTP 网络发送在数据库事务之外，发送失败不留下可消费证明。密码修改和管理员凭据变更同步吊销旧找回链接。

`Threads` 管理讨论类型、投票选项、结果隐私与采纳，保存复用 Content 的版本/事务；读写复用 Content 的访问检查。投票同时依赖账户/内容锁与唯一约束，重复提交不产生多票。采纳和审核均先锁同一内容再锁评论，减少相反锁序；审核否决同步清理采纳标志。

`Core/Motion.php` 是预置曲线与预设的单一来源，`settings.php` 管理字段范围，视图将允许的公开数值输出为转义 JSON；前端不再维护第二张曲线表。`Settings::savePartial` 复用整组验证并保留未修改字段，不由动效页重置其他外观。

`motion.js` 管理显现、指针反馈、原生弹层与主题转场；`motion-studio.js` 只负责编辑器参数、曲线显示和重播，调用同一引擎。`features.js` 邮箱请求复用 `app.js` 的 CYUI 请求和反馈层，不复制 CSRF/错误转换流程。样式变量共用，主题不复制业务模板。

浏览器的增强是渐进式：内容本来可见，JS 成功初始化后才加入等待显现状态；动画开关从不决定业务授权。减少动态效果优先，指针仅在事件后调度帧，无全局常驻指针渲染循环。后台保存始终经过服务端输入校验、CSRF、权限和审计。

## 0.12 的新增边界

`Categories` 负责树结构校验、继承阅读/发布条件与成员有效期；`Content::access` 再检查分类，避免调用方只传入原始内容行时漏掉父级门禁。前台是否显示按钮不是授权来源。

圈子加入和自动邀请码是 `Commerce` 的订单分支，不各自建立第二份扣款系统；`Invitations` 继续以摘要验证，交付码通过既有加密服务保存。`Reviews` 锁定购买订单并通过关联有效订单计算公开评分；`Bounties` 使用已有 Wallet 幂等键托管/发奖/退回，采纳与发奖同事务。

旧单选的 `cy_poll_votes` 表保留一账号一票约束，选择集合位于 `cy_poll_choices`；迁移回填可重试。结果查询按投票人数统计而非选择行数。数据库死锁/锁等待超时在最外层事务有限重试，业务副作用不得移到事务回调内的外部网络。

动效的曲线与字段属于 `Core/Motion.php`，解析弹簧属于 `assets/spring.js`，前台与实验室共用。`interactions.js` 管理具体控件与焦点，不另复制后台/前台弹簧算法。CSS 按主题变量工作，避免主题各自维护 JS。


## 0.13 维护边界

`Creator` 集中管理作者收益的应计、结算、退款逆向与转换；`Commerce` 在订单事务内调用，`Wallet` 是唯一资产账本边界。前后台收益列表共用 `income_rows`，避免显示与统计规则分叉。锁顺序以订单 → 收益 → 作者为主，提现使用原来源资产；原生 MySQL 的并发和死锁重试仍需专门运行矩阵。

`Discovery` 管理本人阅读状态与检索建议，关注/历史列表重用 `Content::feed` 的中央可见性过滤，不复制另一套忽略分类权限的 SQL。阅读容量有明确上限，搜索建议只暴露公开字段。

新 JS 拆成 `discovery.js` 与 `feedback.js`，UI 网络状态与业务权限分离；运动仍交给 `motion.js` / `spring.js`。无构建依赖、无外部 CDN 脚本、无前端保存的支付密钥。服务器输出遵循统一转义，搜索 DOM 使用 textContent，不执行响应里的标记。

## 0.14 的复用边界

`Pricing` 只做受限整数计价/优惠券验证和规则保存，会员资格继续调用 `Membership`，不另造会员缓存或资产账本。预览不预留券；真正核销必须在 `Commerce` 交易里调用 reserve 路径。SKU、卡片、购物车和订单保存共用同一计算入口；最高确认金额不是客户端指定成交价。

`SecondFactor` 按账户→认证记录的锁顺序复用 Wallet 的有效账户锁、Crypto、Activity 和会话版本。TOTP 数学放在独立 `Core/Totp`，HTTP 入口只处理输入/证明传递；现有 Auth 登录在账户事务中调用验证，避免两个入口实现不同验证规则。恢复码只保存摘要，明文短暂放在当前用户会话且消费后清除。

`Diagnostics` 以管理员按需执行的检查集合输出，不借运行检查执行任意 SQL 或外部命令；回滚探针写入随机短期键并验证不存在。只报告当前被检查的基础能力，不将测试适配器冒充生产驱动。

`refinement.js` 复用 `CYMotion` 的时长、曲线、减少动态效果与清理语义。布局编号是稳定键，内容仍由原 Layout 校验；报价不创建客户端私有计价公式，服务端返回整数和安全展示文字。CSS 使用现有颜色/表面变量，新页面不复制业务代码。

这些边界便于扩展，但不构成任意插件加载平台；新增财务模块仍需事务、幂等、权限、退款和并发回归，不能只增加按钮。


## 0.15.0 补充

账号连接、主动查单、永久会员、整车上限、配置快照、徽章和后台分组交互的当前行为、限制与操作请以 [连接与运营说明](CONNECTIONS_AND_OPERATIONS.md) 为准。新功能复用现有事务、账户和动效服务，不复制多套入账或身份校验。

## 0.16 新服务边界

Checkout 复用 Commerce 的单位订单、账本、库存和履约；GuestOrders 是令牌限定的购买身份，不是常规登录。Shipping/Promotions 通过 Rulebooks 验证修订号；Membership 用实际付款权益批次和签名短时报价。

DirectPayments 调度同一 Gateway 接口；Refunds/Payouts 使用固定请求号、租约、未知结果核实，外部 HTTP 位于数据库事务之外，确认事实才进入本地原子回滚。Jobs 只做有界调度，不隐藏常驻服务。

Uploads 复用 Media 的类型与落盘校验；ObjectStorage 复用 S3 签名和 HttpClient，暂存验证后条件复制为正式 key。Translations 绑定源版本及自身 revision，受保护正文不外传；Locale 是统一界面翻译入口，搜索复用公开访问条件。

## 0.17 可维护性边界

`Navigation` 集中前后台路由/模块白名单，`PlatformActions` 在动作分发前统一权限和限流，`PlatformPages` 负责新增读取入口。`SearchIndex`只处理公开元数据索引，不另造内容权限；`Learning`继承Content访问与Media交付；`Tracking`关联Commerce订单，不另建收货状态机；`Reconciliation`只读交易凭证、写差异报告；`SupportDesk`管理工单自身的版本与幂等键。

`Migration017`为v9新增表/索引，重复执行有防护，保留发布布局快照。运行数据与测试专用FFI隔离。视图共享 `platform_header`、`tracking_timeline`、`support_thread` 等模板；2524键语言包通过Locale统一读取，前后台作用域独立。外部物流HTTP请求不长时间持有数据库锁，回写前重新校验修订号。

课程/工单操作、索引重建与布局编辑使用普通HTTP请求；服务器没有隐式后台守护程序。功能边界不是靠PHP小版本分支裁剪，而是由权限、业务设置和主机能力决定。


## 0.18.0 复用与边界

`HttpClient::request` 统一传输校验，JSON、form、HEAD 共用重复头、请求体和响应分帧约束。`Activity::rateMany` 一次事务预留验证码全部配额，不在每种收件场景复制限流逻辑。

`RemoteSearch` 使用合并 outbox、租约及修订号处理远程异步任务，所有网络调用在数据库短事务之外；`Content` 复用既有列表权限与本地回退，不信任远程结果直接展示内容。`Tracking` 的包裹与旧订单/售后分离，轨迹不能直接操作钱包。

`SnapshotSchema` 保存源代码控制的表目录；`Database::snapshot` 提供一致性读取；`EncryptedArchive` 管理加密记录；`SnapshotReader` 统一校验、inspect 与恢复读取；`Backups` 只负责管理员创建/目录/下载，`Recovery` 负责 CLI 空目标恢复。浏览器页面不具备执行任意 SQL、任意路径提取或覆盖生产库的能力。

`Migration018` 由既有迁移入口调用，v10 保留 v9 运单并添加包裹键；目标数据库比当前代码新时仍拒绝启动。MySQL/SQLite 共用服务，不按 PHP 7.4–8.5 分叉业务。
